<objective>
Add a standalone "Invite collaborator" path to /collaborators so an artist can invite a person
with **first name + email only**, with no split sheet and no full royalty form in the way.

Purpose: today the only way to reach the (already-working) invite endpoint is to first create a
collaborator through CollaboratorForm, whose client-side `required` attributes demand first name,
last name, email AND phone, followed by a rights-registry block. That reads as a royalty form, so
the invite feels split-sheet-bound. The server never required any of it — POST /api/collaborators
only requires `name`.

Output: a shared invite helper, a new zod-strict quick-invite endpoint, and a 2-field modal whose
result panel always exposes a **Copy invite link** control — because Resend is currently down in
prod (invalid API key + unverified sender), so an email-only invite button would ship dead.
</objective>

Confirmed by reading the files during planning — build on these, do not re-litigate them:

1. `app/api/collaborators/route.ts` POST requires only `update.name`; every other field flows
   through `sanitizeCollaborator`'s allowlist. No server relaxation is needed for a minimal row.
2. `assembleDisplayName` in `lib/collaborators/index.ts` returns `first_name` alone when
   middle/last are absent, and falls back to `c.name` when no parts exist. A `{ name, first_name,
   email }` row renders correctly.
3. `CollaboratorCard` (line ~66) and `CollaboratorPicker` (line ~228) both null-guard `pro`/`ipi`
   and both use `assembleDisplayName`. `CollaboratorRoster` sorts on `a.name.localeCompare(b.name)`,
   so `name` must be non-empty on the new row.
4. The cooldown in `app/api/collaborators/[id]/invite/route.ts` is **60 seconds**, not 24 hours
   (relaxed for resend UX), and currently returns `{ ok: true, skipped: true }` with no token.
5. `collaborator_invites` (migration 018) has `invite_token TEXT UNIQUE NOT NULL`,
   `token_expires_at` default now()+30d, `status` CHECK in (pending|accepted|expired), `sent_at`.
   RLS policy "Inviting user manages invites" is `auth.uid() = inviting_user_id`, so the inviting
   user may read back their own row's `invite_token`.
6. `collaborators` RLS is "Users manage own collaborators" — `auth.uid() = user_id`.
7. Migration 066's `collaborators_claimed_implies_confirmed` trigger only forces
   `status := 'confirmed'` when `claimed_by IS NOT NULL`. An unclaimed row may be inserted with
   `status: 'pending'` and it sticks.
8. The prior-art copy-link pattern is `app/api/admin/staff/[id]/resend/route.ts` (returns
   `{ data: { emailSent, inviteLink } }`) + `handleCopyLink` in `components/admin/StaffAdmin.tsx`
   (`navigator.clipboard.writeText`, toast on success/failure). Mirror it.
9. `sendEmail` in `lib/email/index.ts` returns `{ ok: false, error }` rather than throwing.
10. There is no @testing-library / jsdom in this repo — jest `testEnvironment` is `node`.
    Automated coverage for this change is route tests + pure-helper tests; the modal is covered by
    `tsc --noEmit`, `lint`, and `next build`.
11. Zod convention to mirror: `app/api/admin/pipeline-stages/route.ts` — module-level
    `z.object({...}).strict()`, `safeParse`, generic 400 message on failure.
12. URL-building convention to mirror: `approveUrl` in `lib/split-sheets/esign-invite.ts` —
    strip trailing slashes off `NEXT_PUBLIC_APP_URL`, emit a relative path when it is absent
    rather than a link that reads "undefined".

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> POST /api/collaborators/quick-invite | Untrusted JSON body crosses into a row insert on a user-owned table |
| server -> browser (response body) | A capability-bearing invite token crosses back out to the client |
| server -> Resend | Artist-entered `first_name` crosses into an HTML email body |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-i4i-01 | Information Disclosure | quick-invite + `[id]/invite` responses returning `inviteLink` | high | mitigate | The token is a signup capability. Both routes only emit it after proving the caller owns the row: `[id]/invite` filters `.eq('id', id).eq('user_id', user.id)` before delegating, and quick-invite creates or reuses a row it just scoped to `user.id`. RLS "Users manage own collaborators" (`auth.uid() = user_id`) backstops both. Scoped disclosure to the inviting owner only — the same posture as `app/api/admin/staff/[id]/resend/route.ts`, which returns a live magic link to a gated manager. |
| T-i4i-02 | Elevation of Privilege | quick-invite request body | high | mitigate | `z.object({first_name, email}).strict()` rejects any extra key outright, so `claimed_by`, `user_id`, `status`, and every registry field are unreachable via this route. `user_id` is set server-side from the session, never from the body. |
| T-i4i-03 | Spoofing | quick-invite creating a row for another user | high | mitigate | `user_id` comes from `auth.getUser()`; the reuse lookup is filtered on the same id; RLS WITH CHECK rejects a mismatched insert even if the code regressed. |
| T-i4i-04 | Tampering | `first_name` interpolated into the invite email HTML | medium | mitigate | `buildCollaboratorInviteEmail` retains every `esc()` call from the M6 fix (27-CODEX-REVIEW.md), and Task 1's helper test asserts markup in a name lands escaped. Moving the builder must not lose the escaping — that is an explicit test. |
| T-i4i-05 | Denial of Service | invite-email spam via repeated quick invites | medium | accept | The existing 60s cooldown per collaborator+inviter is preserved and now returns the prior link rather than erroring. Per-user global rate limiting is out of scope for this task and unchanged from today's posture. |
| T-i4i-06 | Repudiation | no audit trail on quick invites | low | accept | Each invite writes a `collaborator_invites` row with `inviting_user_id` and `sent_at`, which is the same trail the existing path leaves. No additional audit surface is warranted for an artist-scoped action. |
| T-i4i-SC | Tampering | dependency installs | low | accept | No new npm/pip/cargo packages are introduced by this task — zod, jest, and Supabase are already dependencies. No package legitimacy gate applies. |
