<objective>
Add a staff-only **Vendor Health** page to The Playbook's IT Team room that runs live, read-only credential probes against each external vendor and reports working / not working / not configured per vendor — without ever exposing a key value.

**Purpose:** On 2026-08-26 a production email outage was traced to `RESEND_FROM_EMAIL` in Vercel holding the Resend **API key value** instead of a sender address. Vercel secrets are write-only, so the settings screen looked perfectly healthy and the only way to find it was a throwaway diagnostic endpoint. This page turns that class of bug into a ten-second check and lets a non-owner (Thomas, running artist-side beta) verify for himself.

**Immediate motivating question:** is `DOCUSEAL_API_KEY` correct in Vercel production? `requireApiKey()` in `lib/esign/docuseal.ts` **throws** when unset — there is no graceful fallback — so a wrong key means an artist submits a song and hits a hard error.

**Output:** a `lib/observability/vendor-health.ts` probe core, an independently-gated `GET /api/admin/vendor-health` route, a sixth IT-room sub-page, and jest coverage for the pure verdict logic and the no-leak guarantee.
</objective>

<discovered_constraints>
Verified by reading the repo during planning. These are not assumptions.

1. **`DOC_PAGE_FILE` will break the build.** `lib/playbook/nav.ts` declares
   `DOC_PAGE_FILE: Record<Exclude<ItSubpageSlug, 'dashboard'>, string>`. Adding
   `vendor-health` to the `ItSubpageSlug` union makes that `Record` demand a
   `vendor-health` key, so `tsc --noEmit` fails until the `Exclude<>` is widened
   to also drop the new slug. The new page is bespoke React, not a markdown
   render, so it must NOT get a `DOC_PAGE_FILE` entry.

2. **`__tests__/playbook-nav.test.ts` will fail.** It asserts
   `IT_SUBPAGES` has length 5 and pins the exact slug array. Both assertions
   need updating to 6 entries. `__tests__/playbook-docs-render.test.ts` pins
   `DOC_PAGE_FILE` to exactly 4 keys and stays valid as long as constraint 1 is
   honoured the right way.

3. **`components/playbook/Rail2.tsx` maps over `IT_SUBPAGES`**, so the new page
   appears in the rail automatically — no Rail2 edit is needed.

4. **`getStaffRoles`/`requireStaff` default excludes the `it` role.**
   Do not hand-roll a gate. `requireRoomAccess`/`requireRoomAccessPage` in
   `lib/playbook/rooms.ts` already compose the base staff gate correctly and
   migration 130 seeds `it-team` grantable to `it`, with leadership passing
   structurally.

5. **`fetch` is patched inside Next route handlers and Server Components and
   caches by default.** Every probe must opt out of the data cache or the page
   will render a stale verdict, which on a health page is worse than no page.

6. **Jest runs `testEnvironment: 'node'` with no jsdom.** Cover pure functions
   and the probe runner with a mocked `fetch`. Do not attempt to render a
   component in a test.

7. **`npm run lint` runs with `--max-warnings=0`** — an unused import fails CI.

8. **No package installs.** Every probe is plain `fetch` plus one in-process
   import. The Package Legitimacy Gate does not apply to this work.
</discovered_constraints>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `/admin/playbook/it/vendor-health` | Any authenticated session can request the URL; only it-team-granted staff and leadership may render it |
| browser -> `GET /api/admin/vendor-health` | `middleware.ts` excludes `/api` from its matcher, so this route is its own complete security boundary |
| server -> vendor APIs | Credentials leave the server in request headers; vendor responses are untrusted input returning across the boundary |
| probe result -> rendered page / JSON body | The narrowest and most dangerous boundary — anything placed in a `VendorProbeResult` becomes visible output |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-2qm-01 | Information Disclosure | `VendorProbeResult.detail` | critical | mitigate | Detail strings are built only from status codes, fixed prose, and a named allowlist of non-secret vendor JSON fields (domain name, domain status, template count, model count, livemode). Task 2's sentinel test seeds every credential env var with a distinctive value and asserts none appears in the serialized result set. |
| T-2qm-02 | Information Disclosure | failure paths in `probeCredentialed` | high | mitigate | The vendor response body is never read on a non-2xx path. Several APIs echo the submitted credential in an error payload, so a failure detail is assembled from the numeric status plus fixed prose only. |
| T-2qm-03 | Information Disclosure | `safeSenderDisplay` | high | mitigate | The single audited function permitted to return an env value, and only after `isEmailShaped` passes and the Resend key prefix is excluded — which structurally prevents a key-shaped value from reaching a render. A sender address is already public in every outbound email header. Prohibition in `must_haves` forbids any second value-returning path. |
| T-2qm-04 | Elevation of Privilege | `GET /api/admin/vendor-health` | high | mitigate | `requireRoomAccess('it-team')` is the handler's first statement and returns the gate's own status before `process.env` is read or any probe runs. Task 3 asserts a refused request invokes zero probes. |

| T-2qm-06 | Denial of Service | probe fan-out | medium | mitigate | The staff gate is the primary control against amplification. | T-2qm-07 | Tampering | DocuSeal and Anthropic probes | medium | mitigate | A future edit that "optimizes" the DocuSeal templates listing into a submission call would bill $0.20 per completed document and could mint real signature invites to real collaborators; an Anthropic completion call would bill tokens on every page view.
