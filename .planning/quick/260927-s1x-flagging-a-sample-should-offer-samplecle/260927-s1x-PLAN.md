<objective>
Flipping *"This track contains a sample"* tells an artist they now have a required
clearance, a capped readiness score and a buyer routed to `contact`, and never mentions
the tool that exists to help. Close the loop: raising the flag puts SampleClear in front
of them.

Purpose: the moment the artist raises their hand is the moment the offer is worth
anything. `lib/tools/sampleclear.ts` identifies master vs publishing holders — usually
different parties, and the thing artists most often get wrong alone — and drafts a
request to each. Since #120 that output renders as a real result view, so the link now
hands over something worth reading.

Output: a toggle-ON that opens the real Stage 3 sample-clearance requirement for that
track, and a line in the toggle that names the tool. No generation, no new server code.
</objective>

<design_resolution>
## The core design question, answered

**Question.** When the flag goes on, the requirement the panel needs does not exist yet
on the client. It only appears after the server re-renders. How do we open the REAL
requirement without inventing one, and without hanging if it never arrives?

**Answer: a pending key with an absolute deadline, resolved against the refreshed props.**

1. `SampleFlagToggle` reports a bare `trackId` upward after its toggle-ON PATCH
   succeeds. It does not know what a requirement is and does not build one.
2. `DocumentStage` turns that into `{ key: sampleClearKey(trackId), expiresAt: Date.now()
   + PENDING_OPEN_WINDOW_MS }` and stores it in state.
3. The PATCH already called `router.refresh()` (`SampleFlagToggle.tsx:46`). That re-runs
   the server render of `documents/page.tsx`, which recomputes `computeStage3` and hands
   `DocumentStage` fresh props — while preserving its client state, which is why the
   pending key survives the round trip.
4. An effect keyed on `[pendingOpen, allRequirements]` looks the key up in the refreshed
   list. Found → `setActive(match)` with the server's own object, clear the key. Not
   found and past the deadline → clear the key, open nothing. Not found and within the
   window → arm a timer for exactly the remaining milliseconds.

**Why this is not synthesis.** `setActive` receives the identical object `computeStage3`
produced — same status, same `documentId`, same signers, same prefill. `findRequirementByKey`
returns the element by reference; the unit test asserts identity (`toBe`) precisely so a
future refactor cannot quietly start returning a copy.

**Why it cannot hang.** The deadline is fixed at toggle time, not extended by re-renders.
The timer is armed for the *remaining* window, so repeated server renders cannot stretch
it. On unmount the cleanup clears it. Worst case: the key expires and nothing opens —
the artist still sees the new "Sample clearance" card in the Required section, which
opens the same panel on click. Silent give-up is the correct failure: an offer that
arrives thirty seconds late is worse than no offer.

**Known bounded edge.** If the artist toggles ON and then OFF inside the window, and the
ON-refresh lands after the OFF-PATCH, the panel can still open once. The worst outcome is
a panel the artist closes. Not worth machinery.

**Synthesis was not required.** No part of this plan builds a requirement object in the
browser, so the "stop and report" clause in the brief does not trigger.
</design_resolution>
