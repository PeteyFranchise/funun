<owner_judgment>
**Rose error panels: agreed, keep the fill.** A submit failure is the only signal the person gets, so it stays alarming. Tuned only to the bench's radius and type scale (11px radius, 12.5px text); `border-rose-500/30 bg-rose-500/10 text-rose-200` is unchanged.

**No entrance animations.** The bench uses a card rise and a staggered body fade. They were not in the brief, and shipping motion on an auth screen needs a `prefers-reduced-motion` guard to be correct. Left out deliberately, not forgotten — say so if the owner wants them and they become their own small task with the media query.

**Waveform heights are precomputed literals, not a render-time `Math.sin` loop.** `Math.sin` is implementation-defined in ECMAScript to the last ULP, so a Node-rendered string and a Safari-rendered string can differ and React logs a hydration mismatch on the app's first screen. The 44 values are computed once from the brief's formula, rounded to 2dp, and frozen as a constant with the formula recorded in a comment. Same picture, zero hydration risk.
</owner_judgment>
