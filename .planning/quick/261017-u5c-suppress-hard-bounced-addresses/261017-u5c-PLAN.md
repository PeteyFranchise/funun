<objective>
Close GitHub issue #190. Today a Resend HardBounce only flips `curators.email_valid = false`, so collaborator, buyer, invite, staff, alert and notification addresses that hard-bounced keep getting mail (bad for sender reputation and Resend account standing).

Fix it at the two chokepoints: record every hard-bounced address in a new service-role-only `email_suppressions` table (webhook side), and make the single `sendEmail` wrapper in `lib/email/index.ts` skip suppressed recipients (send side). Every outbound email in the app goes through `sendEmail`, so this covers all callers without touching them.

Output: migration 246 (authored and committed, NOT applied), webhook change, sendEmail change, tests for all three.
</objective>
