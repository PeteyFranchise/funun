<objective>
Build the backend for R4 flag-for-fix: a claimed user who appears on a FROZEN split sheet (esign_pending/executed) can submit a structured "this is wrong" correction (field + suggested value) that persists to a dedicated flags table and notifies the sheet owner via bell + email. This is the one genuinely net-new mechanism in the phase — no analog route exists — but every sub-part (structured-actions doctrine, service-role scoped write, dual-channel notification) has a live sibling to imitate.

Purpose: Give a claimed user a safe, non-destructive path to request an identity correction on a frozen sheet WITHOUT any ability to write another party's row or alter deal terms. Applying the fix stays the owner's action (19-06).
Output: A new flags table + RLS, a scoped POST route, a notification builder/type, and an authorization-negative test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (claimed user) -> correction-flag route | Untrusted body (partyId, field, suggestedValue). The route must derive flagged_by server-side and validate field/target before any write. |
| flag row -> owner (cross-user notification) | The suggested value crosses to another user; must be structured (no free text) and escaped by createNotification. |
| authenticated user -> split_sheet_parties / terms | Must be impossible to write another user's party row or any split_percentage/role from this surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-10 | Tampering / Elevation of Privilege | correction-flag route writing another user's data | high | mitigate | Write targets only split_sheet_identity_flags scoped by server-derived flagged_by=auth.uid(); route never UPDATEs split_sheet_parties or terms; RLS INSERT policy also enforces flagged_by=auth.uid() (negative test + migration 074). |
| T-19-11 | Information Disclosure | reading others' flags / rights beyond intended | high | mitigate | RLS SELECT policy limited to flagger + sheet initiator; suggested_value scoped to identity fields only; no broad grant. |
| T-19-12 | Tampering (forged provenance/payload) | free-text or arbitrary field injection | medium | mitigate | field validated against FLAGGABLE_FIELDS + DB CHECK; suggested_value length-capped and String-coerced; createNotification escapes user content (P18-13 structured-actions). |
| T-19-13 | Denial of Service | notification failure blocks the flag | low | mitigate | Notification call is try/catch best-effort; the flag write commits regardless. |
