<objective>
Stand up the shareable half of the feature: one GET that authorises like the comments read already
does, fetches exactly one take's root comments, hands them to the pure classifier, and returns
either a marker file or the sentence explaining why there isn't one.

Purpose: this is the route a writer's browser hits when they click Export comments. Everything it
does that isn't fetching rows or setting headers is a decision that already has a home in
`lib/catalogue/take-export.ts`, and keeping it that way is what stops the three formats and the
four refusal cases from being re-litigated at the edge.

Output: a thin route file and a source-assertion test in the established style for this subsystem.
</objective>

Create `app/api/works/[workId]/versions/[versionId]/comments/export/route.ts` exporting a single
`GET` handler. Nothing else is exported from this file. A route module that exports only a read
verb is the cheapest possible proof of E-10.

Open with a section-header comment recording the two constraints that are not visible from the
code: export is a pure READ that records nothing anywhere, and this file is the SHAREABLE half of
a deliberately split pair — the private pin export lives in its own route file with its own query,
and the two never share a data path.

Sequence the handler in this order, and do not reorder it:

1. Await the route params for the work id and the version id.
2. Read `format` from the URL search params, defaulting to `csv`. Validate it against a literal
   allowlist of the three format ids using a Zod enum, matching how the sibling comments route
   validates its body. An unrecognised value is a 400 with a plain message. Per E-13 the three ids
   are the three named options a user picks, and they stay distinct even though two of them share
   an extension.
3. Create the API client and get the user. No user is a 401.
4. Rate-limit on a per-user key namespaced to this route, with a generous allowance — this is a
   low-cost read, not a fan-out write. Use a key prefixed `work-version-comments-export:` followed
   by the user id, an allowance in the low hundreds and the existing fifteen-minute window, and
   leave the limiter fail-open like the other read paths. Over the limit is a 429 with the same
   copy shape the sibling routes use. CONTEXT leaves the exact numbers to discretion; record the
   chosen numbers and the reasoning in a comment so a later reader does not have to guess.
5. Call `resolveWorkAccess` with the deps factory, the work id, the user id and the `'contribute'`
   tier — the identical call the comments GET route makes, which is the phase's own operating
   boundary (b): the same gate that governs reading the comments. Return the refusal's status and
   reason verbatim.
6. Load the work's versions and confirm the requested version belongs to this work, returning 404
   if not. This is not redundant with the access check: without it, a version id from a different
   work could be paired with a work id the caller CAN reach. Build the version display map from
   the same rows so the filename's version segment is the same `vN` the room shows.
7. Load the work's title with the caller's own client. If the row is missing, 404.
8. Query the comments with BOTH `work_id` and `version_id` equality filters, an explicit
   `parent_comment_id` null filter, and a bounded limit. E-05 is why only one version id is ever
   read: a DAW marker file is imported against one audio file, so markers from another take would
   land on music they were never written about. The root filter is explicit on purpose — migration
   225 guarantees a reply cannot carry a span, but this export must not lean on that guarantee
   implicitly, and the pure classifier filters roots again as a second gate.
9. Present the rows through `presentVersionComments` with the loaded profiles and the version
   display map, so carried-from provenance and display names are resolved. Reaction groups are not
   needed and must not be fetched — a marker carries no reactions.
10. Call `classifyCommentExport` on the presented views.
11. If the refusal reason is anything other than `none`, return a JSON body carrying the reason and
    the message — and use status 409, not 200. A 200 with a JSON body is indistinguishable from a
    successful download to anything that is not carefully checking, and would save a `.csv` full of
    JSON onto someone's desktop. CONTEXT leaves the route shape to discretion; record in a comment
    that 409 was chosen so the refusal is impossible to mistake for a file.
12. Otherwise dispatch on the validated format to the matching renderer, pick the extension and
    content type for that format, build the filename with `exportFilename` passing the `comments`
    kind, and return the body through `new NextResponse(...)` with a charset-qualified
    `Content-Type`, a `Content-Disposition` attachment header, and a header carrying the
    repositioning-skipped count as a bare number. Name that header `X-Funun-Skipped-Reposition`.
    E-09 requires the count on the success path too, and a header is the only place it fits
    alongside a file body. Also set `Cache-Control` to no-store: this is per-user content and
    nothing about it should sit in an intermediary.

Extensions and content types: the Audacity label track is `.txt` with a plain-text content type;
the CSV and the Audition marker file are both `.csv` with a CSV content type. All three are
charset-qualified UTF-8, because Audacity's manual warns that a non-UTF-8 file with accented
characters may fail to import outright and display names are free text.

Accept all three format ids here even though plan 40-07 will expose only two in the interface. The
Audition serializer is written and pinned byte for byte; what plan 40-08 gates is putting the option
in front of a user, not the code's existence. Record that in a comment so the asymmetry reads as
intentional.

Wrap the data access in a try/catch returning a generic 500 with no raw database text, matching the
sibling route. Do not log the caught error object.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → export route | An untrusted work id, version id and format value arrive together |
| route → database | Two path params must both constrain every query, not just the version |
| route → downloaded file | Content leaves Funūn's access control permanently and is forwardable |
| song title → HTTP response header | User-controlled text is interpolated into `Content-Disposition` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-40-15 | Elevation of Privilege | exporting a work the caller is not a member of | critical | mitigate | `resolveWorkAccess` at the `'contribute'` tier before any read, identical to the comments GET route; a non-member receives 404 rather than 403 so the route cannot become an existence oracle |
| T-40-16 | Information Disclosure | pairing a foreign version id with a reachable work id | high | mitigate | Version membership is checked against the work's own version list, and every query filters on both the work id and the version id — not the version alone |
| T-40-17 | Information Disclosure | a private pin reaching the shareable file | critical | mitigate | Structural, not conditional: this route has no pin query, no pin import, and no parameter that could select one. Asserted here at file scope and again in plan 40-06 across both routes |
| T-40-18 | Information Disclosure | a reply's text appearing as a marker | medium | mitigate | An explicit root filter in the query AND a second root filter inside `classifyCommentExport`; neither is permitted to be the only one |
| T-40-19 | Tampering | header injection or a path-shaped filename via a song title | high | mitigate | The title only reaches the header through `exportFilename`, which strips quotes, path separators and every control character (plan 40-01, T-40-03) |
| T-40-20 | Repudiation | a write creeping onto the read path and telling the room something | medium | mitigate | E-10 makes export record nothing. The route exports only GET, and the test forbids every write-shaped and notify-shaped token by name |
| T-40-21 | Denial of Service | unbounded repeated export of a large take | low | mitigate | Per-user rate limit with a generous allowance and the existing shared limiter; the query carries a row limit; no file is persisted anywhere |
| T-40-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is added by this plan |
</threat_model>
