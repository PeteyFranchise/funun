<objective>
Write the Adobe Audition marker serializer against the shape research corroborated from three
independent sources, isolate it so it can be corrected or dropped without touching anything else,
and hand the human running plan 40-08's verification a one-command way to produce Funūn's exact
bytes.

Purpose: E-12 refuses to block the release on a vendor's undocumented format. The evidence is
strong enough to build against — a forum thread quoting a literal exported header and two
independently-written open-source parsers that agree byte for byte on delimiter, column count and
column order — but nobody in this phase has run Audition. So the code ships, gated, in its own
file, rather than being deferred wholesale.

Output: `lib/catalogue/take-export-audition.ts`, a test suite that treats the duration trap as a
first-class correctness concern, and `npm run export:audition-sample`.
</objective>

  <action>
Create `lib/catalogue/take-export-audition.ts` as its OWN module, importing only the marker type.
The isolation is the point: E-12 permits this phase to ship without Audition at all, so the
Audition support has to be removable by deleting one file and one dispatch branch. A shared renderer
module would make that a surgical edit instead.

Open the file with a section-header comment block recording, for a reader who will not have this
plan, everything that is inferred rather than observed:

- The extension is `.csv` but the delimiter is a TAB. This is confirmed three times over by
  independent sources and it is the single most surprising fact about the format.
- There are six columns with a header row, in the order Name, Start, Duration, Time Format, Type,
  Description.
- The Time Format column's value is the literal word `decimal`, and it is REQUIRED — a user report
  attributes import errors to omitting it. Despite that word, the Start and Duration values are
  NOT plain decimal seconds. Say this explicitly; it is Pitfall 1 and it is the mistake an hour of
  familiarity with the Audacity format sets a reader up to make.
- The third column is a LENGTH, not an end time. Say this in its own paragraph. Note that getting
  it wrong produces a file that imports successfully with every range marker at the wrong length,
  which is a silent, plausible-looking corruption with no error message anywhere.
- The `Type` value is `Cue` for every row. Point and range markers are not distinguished by this
  column; Adobe's own documentation says the only difference between the two is that range markers
  have a duration. Mark the range case as INFERRED — every corroborating example found was a point
  marker.
- Line endings are CRLF and the encoding is UTF-8. Mark both as INFERRED, and name plan 40-08 as
  where they get settled.
- The Description field is written as an empty sixth value, producing a trailing tab. Mark this as
  the safer of two unobserved options: both real-world parsers index fields positionally, so an
  extra empty field is far less likely to break parsing than a missing one.

Export `AUDITION_MARKER_HEADER` as a named constant holding the six tab-joined column names, so
the header string has one home and a test can assert it without re-typing it.

Export `auditionTime(ms: number): string` — clamp to zero, round to the nearest millisecond, then
format as whole minutes with no leading zero, a colon, seconds zero-padded to two digits, a dot,
and milliseconds zero-padded to three digits.

Export `auditionDuration(startMs: number, endMs: number | null): string` as a SEPARATE named
function rather than a call site that subtracts inline. A named function is a thing a test can aim
at directly and a thing a reviewer can see; an inline subtraction is a thing that gets "simplified"
into `auditionTime(endMs)` by someone being helpful. Return `auditionTime(0)` when `endMs` is null,
and `auditionTime(endMs - startMs)` otherwise.

Export `renderAuditionMarkers(markers: ExportMarker[]): string` — the header line followed by one
line per marker, each line six tab-joined fields in the documented order: the label, the start
time, the duration, the literal `decimal`, the literal `Cue`, and an empty string. Join every line
with a carriage return and a line feed, and end the file with the same pair. Return the header line
alone plus its terminator for an empty array.

Do not sanitise the label and do not filter or re-order the markers. Both happened in plan 40-01.

Add `lib/catalogue/take-export-audition.test.ts` covering every case in `<behavior>` with `toBe`
against exact literals. Give the duration-trap test a name that states the claim in words, so a
failure message reads as an explanation. For the cross-format divergence test, import both this
module and the Audacity renderer in the test file and assert both values from the same input array
— that import belongs in the test and nowhere else.
