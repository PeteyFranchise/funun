<objective>
Build the pure core of the DAW marker export: one internal marker shape that comments and pins both
reduce to, the sanitisation that makes a delimited file safe, the classification that decides
whether there is anything to export at all, and the filename that carries provenance.

Purpose: three unforgiving text formats are about to be written against this. Every decision about
what a marker SAYS — whose name, which version prefix, which comments are excluded and why —
belongs here, once, so the three renderers can stay dumb string templating and cannot drift from
each other.

Output: `lib/catalogue/take-export.ts`, a synchronous browser-safe module with no dependencies
beyond one timestamp formatter and the catalogue types, plus a test file that pins every string it
produces byte for byte.
</objective>

Export the shared shape:

`ExportMarker` — an object type with `label: string`, `startMs: number`, `endMs: number | null`.
`endMs` being `null` is the ONLY representation of a point marker in this phase. Each renderer
decides for itself how a point is written in its own format; that decision does not live here.

Export `sanitizeMarkerLabel(raw: string): string`, applying two independent protections in a fixed
order. First, whitespace normalisation: replace every C0 control character — which includes the
tab, the carriage return and the line feed — with a single space, then collapse runs of whitespace
to one space, then trim. Neither the Audacity label track nor the Audition marker file has any
escape mechanism for its delimiter, so a stray tab silently creates a phantom column and a stray
newline silently splits one marker into two; normalising here, upstream of all three renderers, is
the only place this can be fixed once. Second, the spreadsheet-formula guard: if the normalised
string's first character is an equals sign, a plus, a minus or an at-sign, prepend one apostrophe.
The order is load-bearing — normalising first is what stops a leading tab from hiding a formula
character from the guard. Record in a comment that this guard is OWASP's recommended mitigation and
is defence in depth rather than a guarantee, because no single prefix works identically across every
spreadsheet application.

Export `commentToMarker(comment: WorkVersionCommentView): ExportMarker`. Compose the label as an
optional carried-version segment, then the author's display name, then a colon and a space, then
the comment body — and pass the whole composed string through `sanitizeMarkerLabel`. The carried
segment is present only when `carriedFromVersionId` is non-null, and reads as the value of
`carriedFromVersionDisplay` wrapped in square brackets followed by a space; fall back to the literal
`an earlier version` when the display is null, matching what the presenter already does. Per E-07
and E-14 the author segment is the FULL display name from `comment.author.name` and never the
handle; when `comment.author` is null use `A former room member`, the same fallback the presenter

Export `pinToMarker(pin: WorkVersionPinView): ExportMarker`. Per E-04 the label is the word `Pin`,

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| comment body → delimited file | Free text authored by a room member crosses into a format with no escape mechanism |
| display name → delimited file | A profile field the account holder controls crosses the same boundary |
| song title → HTTP response header | User-controlled text is interpolated into `Content-Disposition` downstream |
| exported file → a spreadsheet application outside Funūn | Funūn has no control over the reader's software or its formula behaviour |
