  <action>
Create `lib/catalogue/take-export-formats.ts`. Open it with a section-header comment block that
records, for a future reader who will not have this plan: the file extension is `.txt` and not
`.csv`, the delimiter is a tab, there are exactly three columns in the order start, end, label,
there is no header row because the format is strictly line-based and a header line would import as
a garbage label at time zero, and the source is Audacity's own manual page on importing and
exporting labels. Record the encoding requirement too — UTF-8 with no byte-order mark, because the
manual warns that a non-UTF-8 file with accented or non-Latin characters may fail to import
entirely, and display names are free text.

Export `renderAudacityLabels(markers: ExportMarker[]): string`.

Each line is the start in seconds, a tab, the end in seconds, a tab, then the label. Convert
milliseconds to seconds by dividing by one thousand and formatting to exactly six decimal places —
six is what the manual shows and what keeps millisecond inputs lossless. A point marker, where
`endMs` is null, writes the START value again in the end column. Record in a comment that this
repetition is the format's own convention and not a workaround: the manual's example of a point
label at 3.4 seconds shows the same value in both columns.

Join the lines with a newline and end the file with one. Return the empty string for an empty
array — the routes never call a renderer with nothing, because classification refuses first, but a
renderer that returns a lone newline for an empty list is a renderer that writes an empty label at
time zero the day someone removes that guard.

Do not sanitise the label here. Plan 40-01 already collapsed every tab and newline in it, and doing
it twice invites the two implementations to disagree later. Do not filter, sort or re-order the
markers either; they arrive ordered from classification.

Add `lib/catalogue/take-export-formats.test.ts` asserting WHOLE FILES with `toBe` against a
literal, not fragments with `toContain`. A test that asserts the output "is tab delimited" is not
the same claim as a test that asserts the output is this exact byte sequence, and only the second
one catches a wrong decimal place. Write tab and newline characters as escapes in the expected
literals so the file stays readable in review.

Add to `lib/catalogue/take-export-formats.ts`:

A module-private `csvField(value: string): string` implementing RFC4180 quoting — wrap in double
quotes and double any embedded double quote when the value contains a comma, a double quote or a
newline; otherwise return it unchanged. Copy the rule from the metadata exporter's cell helper
rather than importing it, and say why in a comment directly above: the two exporters must be free
to diverge, because one writes creative notes for a human and the other writes distributor-bound
release metadata, and coupling them means a change made for one silently changes the bytes of the
other. The test below is what keeps the copy honest.

Export `renderMarkerCsv(markers: ExportMarker[]): string`.

Three columns: `Start`, `End`, `Marker`, with a column-name header row. Record in a comment that
this header is NOT the in-file header E-06 rules out: E-06 rejects a provenance line stating which
take and version the file belongs to, so that a rename cannot be papered over and a strict parser
cannot be broken. A column-name row carries no take-identifying information at all, and a
spreadsheet without one is unreadable.

Carry the same three facts as the other two formats and no more. The marker cell holds the whole
composed label including the author name and any carried-version prefix, rather than splitting
author and body into separate columns. E-13 makes the three options a choice of DAW, not a choice
of how much data you get; a CSV carrying more fields than the label formats would be a second
content contract to maintain and would re-open what a marker says, which E-07, E-08 and E-14
already closed.

Render times with `formatTrackTimestamp` — human-readable minutes and seconds, which is what a
person opening this in a spreadsheet can act on, and not raw milliseconds. The End cell is EMPTY
for a point marker. Audacity's strict format has a structural reason to repeat the start; a CSV
does not, and an empty cell reads more honestly as "this is not a range". Pass only the Marker cell
through `csvField`; the two time cells are generated and contain no delimiter.

Join rows with a newline and end the file with one, matching the existing `buildCsv` which also
joins on a bare newline rather than CRLF.

Then write `.planning/todos/pending/2026-09-15-csv-cell-injection-guard-metadata-export.md`
recording, for whoever picks it up, the decision this plan took and why:

- The finding: `csvCell` in `lib/metadata/export.ts` implements RFC4180 quoting with no
  spreadsheet-formula guard. That is a latent gap in SHIPPED code, not something Phase 40 created.
- The decision: Phase 40 did NOT fix it there. Three reasons, in order. First, `buildCsv`'s only
  consumer is the distributor metadata export, and silently adding an apostrophe to an ISRC, a
  UPC or a title changes bytes a third party parses — that is a delivery-affecting change and
  Phase 40's operating boundaries put delivery state explicitly out of scope. Second, Phase 40's
  guard has to protect all three of its formats, including a tab-delimited file with a `.csv`
  extension that spreadsheet software will happily open, so it belongs upstream in the shared
  label-sanitisation step and not inside either cell function. Third, closing a gap in a shipped
  exporter deserves its own change with its own verification against a real distributor import,
  rather than riding along inside a new feature.
- The residual risk: fields in the metadata export are structured — names, identifiers, titles —
  where a leading formula character is implausible but not impossible, since an artist name is
  user-controlled.
- The suggested fix when it is picked up: apply the same apostrophe prefix inside `csvCell`, then
  re-verify one real distributor import end to end before shipping.

Extend the test file with a second `describe`. Assert whole-file outputs with `toBe` for the cases
in `<behavior>`. Then add the equivalence table: import `csvCell` from the metadata exporter IN THE
TEST ONLY, and assert that for a table of RFC4180 inputs — plain text, a value with a comma, a
value with a quote, a value with both, a value with a newline, an empty string — `csvField` and
`csvCell` agree. Add a comment in the test recording that this equivalence is deliberately about
QUOTING only, and that the formula guard lives upstream in `sanitizeMarkerLabel` and is expected in
neither function.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| marker label → Audacity label track | A format with no quoting mechanism receives free text |
| marker label → CSV cell | A format with a quoting mechanism receives the same free text |
| this phase's CSV rule → the shipped distributor CSV rule | Two exporters that must agree on quoting and are allowed to disagree on everything else |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-40-06 | Tampering | `renderAudacityLabels` — a phantom column or a forged label row | high | mitigate | The label arrives already stripped of every C0 control character by `sanitizeMarkerLabel` in plan 40-01; this renderer adds no escaping of its own because the format offers none, and the acceptance criterion pins every line to exactly two tab characters |
| T-40-07 | Tampering | `csvField` drifting from `csvCell` and producing a subtly different quoting rule | medium | mitigate | A test-only import asserts the two agree across a table of RFC4180 cases, so a divergence fails the suite rather than surfacing as a broken cell in someone's spreadsheet |
| T-40-08 | Tampering | editing `csvCell` to close its injection gap and silently changing distributor-bound bytes | medium | accept | Deliberately NOT fixed in this phase. `lib/metadata/export.ts` is untouched, verified by a clean `git diff --stat`, and the gap plus its suggested fix is recorded as a pending todo so the acceptance is documented rather than forgotten |
| T-40-09 | Information Disclosure | a take-identifying provenance line appearing inside the file | low | mitigate | E-06 puts provenance in the filename only. The CSV's header row is column names with no take or version in it, and the Audacity renderer writes no header at all |
