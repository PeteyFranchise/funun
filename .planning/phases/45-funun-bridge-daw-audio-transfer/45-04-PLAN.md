# Plan 45-04: Writer's Room integration, provenance, cross-room send, and protected pull

## Objective

Make Bridge transfers understandable in Funūn and useful in both directions without granting new custody
or silently routing unreleased audio.

## Tasks

1. Present Bridge uploads as normal version/take records using existing playback/review controls plus
   narrow provenance: uploader, Bridge device display, source application if trustworthy, audio facts,
   checksum reference, and timestamp. Never expose local paths.
2. Add low-noise chat/Diary event only after server completion. Failed/retried/cancelled chunks do not
   create takes or noisy history.
3. Build explicit **Choose another room** over server-authorized targets, confirmation with title/member
   context, and a final revalidation at intent/completion. Provide wrong-room report/support path without
   destructive automatic moves.
4. Add **Send to Funūn Bridge** for an authorized selected asset. Mint a scoped expiring pull grant; Bridge
   downloads into `Funūn Imports/<work>` with checksum/progress and explicit conflict naming.
5. Ensure pull/download respects clean-master custody and protected derivative rules. Writer's Room access
   alone must not become a clean-master download grant.
6. Test blocked/removed, changed mapping, simultaneous sends, wrong-room prevention, existing filenames,
   expired pull, custody boundary, provenance/diary accuracy, and no rights mutations.

## Acceptance

- Every durable take has one verified object and one version row; no completion means no room artifact.
- A user cannot list/send/pull from a room they cannot currently access at the required capability.
- Cross-room routing is explicit and auditable.
- Pull cannot bypass existing custody/download restrictions.
