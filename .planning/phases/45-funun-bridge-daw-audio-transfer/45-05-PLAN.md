# Plan 45-05: Second-platform parity, producer beta, and launch gate

## Objective

Complete the approved OS rollout, verify production storage/cost behavior, and prove the Bridge workflow
with real DAW bounces before general availability.

## Verification and rollout

1. Port/harden the client for the second approved OS with native signing/notarization, keychain, watcher,
   sleep/restart, updater, accessibility, installer/uninstaller, and diagnostics parity. If owner approved
   only one-platform beta, record the second as a required later gate rather than pretending parity.
2. Test representative supported DAWs/formats on both platforms: normal/offline bounce, overwrite, long
   bounce, aborted bounce, file still growing, FLAC/WAV/approved formats, large file, unstable network,
   disk full, sleep, clock skew, duplicate, and malicious path/content.
3. Reconcile ledger/admission/storage objects/version rows/orphan cleanup and measure storage/egress for
   beta usage. Verify quotas and global kill switch under concurrent automated upload.
4. Conduct named producer beta: map project, bounce once, confirm/send, see room artifact, review/chat,
   pull an authorized take, revoke device/access, and recover from failure without manual web upload.
5. Exercise compromised-device revoke, updater rollback, provider/storage outage, support diagnostic,
   wrong-room response, local cache cleanup, and privacy deletion runbooks.

## Launch gate

Owner confirms OS scope, signed builds, remote migration/security verification, storage attribution,
quota/cost thresholds, producer UAT, support/incident ownership, and rollback. Otherwise keep cohort flag
limited and mark the phase incomplete.
