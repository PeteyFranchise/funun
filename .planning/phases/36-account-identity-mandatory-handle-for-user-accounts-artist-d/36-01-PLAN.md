  <files>lib/handles/validate.ts, lib/handles/validate.test.ts</files>
  <behavior>
    - `isValidHandle('maya-reyes')` is true (the one live production handle must survive)
    - `isValidHandle('MayaReyes')` is true; `isValidHandle('maya_reyes')` is true
    - `isValidHandle('ab')` is false (below minimum); a 31-character value is false; a 30-character value is true; a 3-character value is true
    - `isValidHandle('-maya')`, `isValidHandle('maya-')`, `isValidHandle('_maya')`, `isValidHandle('maya_')` are all false (no leading/trailing separator)
    - `isValidHandle('may--a')`, `isValidHandle('may__a')`, `isValidHandle('may-_a')` are all false (no consecutive separators)
    - `isValidHandle('may a')`, `isValidHandle('may.a')`, `isValidHandle('may%a')`, `isValidHandle('mayá')` are false
    - `isValidHandle('')` and `isValidHandle('   ')` are false, and neither throws
    - `isValidHandle('  maya-reyes  ')` is true (leading/trailing whitespace is trimmed before the check)
    - `normalizeHandleForCompare('MayaReyes')` is `'mayareyes'`; `normalizeHandleForCompare('  Maya-Reyes ')` is `'maya-reyes'`
    - `handleFormatError()` returns null for a valid value and a specific, actionable string for each rejection reason (too short, too long, bad characters, edge separator)
  </behavior>
  <action>
    Create `lib/handles/validate.ts` styled after `lib/metadata/identifiers.ts` — small pure
    named-export functions, no schema library, no semicolons, 2-space indent, `@/` imports only.

    Export `HANDLE_MIN_LENGTH = 3`, `HANDLE_MAX_LENGTH = 30`, and a module-private pattern
    `/^[A-Za-z0-9]+(?:[_-][A-Za-z0-9]+)*$/`. That pattern encodes the Claude's-discretion edge
    rules D-05 left open: letters and digits are the only atoms, hyphen and underscore are
    permitted only as INTERNAL single separators, so a leading separator, a trailing separator,
    and consecutive separators are all rejected. Add a section-header comment recording that
    this is a strict superset of every one of migration 037's 58 seeded reserved values (none
    contain a separator), so the format rule and the reserved list can never disagree.

    Export three functions:
    - `isValidHandle(raw: string): boolean` — trims, length-checks against the two constants,
      then tests the pattern. Never throws on empty or whitespace input.
    - `normalizeHandleForCompare(raw: string): string` — trims and lowercases. Add a comment
      stating in one line that this exists for comparison only and that per D-04 a handle is
      stored exactly as the person typed it; the case-insensitive unique index from migration
      010 (on the lowered column expression) is what enforces uniqueness.
    - `handleFormatError(raw: string): string | null` — null when valid, otherwise a specific
      user-facing message per this repo's error convention (state the problem and include the
      actionable limit, e.g. the character range for a length failure). This is the string the
      signup field, the settings form, and the API routes all surface, so it is written once here.

    Write `lib/handles/validate.test.ts` covering every case in the behavior block above.
  </action>
  <verify>

    <automated>npx tsc --noEmit</automated>
  </verify>
