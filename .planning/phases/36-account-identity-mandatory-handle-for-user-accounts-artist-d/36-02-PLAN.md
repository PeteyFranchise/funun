<objective>
Author migration 133 — the whole database layer of Phase 36 in one file, one push — then hand
it to the owner for the human-gated `supabase db push`.

The migration does four things: creates `handle_history` under the established zero-policy RLS
doctrine; rewrites `check_handle_not_reserved()` so it fires on INSERT and also blocks retired
handles; rewrites `handle_new_user()` so the default branch writes the signup-chosen handle
inside a narrowly-scoped catch; and adds a `resolve_profile_by_handle()` resolver so the public
profile route can look a handle up case-insensitively, and fall through to a retired handle,
without anyone needing read access to `handle_history`.

Purpose: two of the three most delicate pieces in this phase live in this file. D-06 is a live
exploitable hole — migration 040 already grants `authenticated` column-level UPDATE on `handle`,
and the guard only fires on UPDATE with a body that dereferences the OLD row unconditionally, so
today the database would not stop someone signing up as a reserved name. D-15 is the difference
between a lost race costing someone their signup and costing them nothing. Everything in waves 2
and 3 reads tables and functions that do not exist until this is pushed, so the push is a
blocking gate, not a formality.
Output: one migration file, one text-lock test file, applied to prod.
</objective>

    returns at most one row: first `RETURN QUERY` selecting `p.id, p.handle, FALSE` from
    `public.user_profiles p WHERE lower(p.handle) = lower(p_handle) LIMIT 1`; then `IF FOUND THEN
    RETURN; END IF;`; then `RETURN QUERY` selecting `p.id, p.handle, TRUE` from
    `public.handle_history h JOIN public.user_profiles p ON p.id = h.profile_id WHERE
    lower(h.old_handle) = lower(p_handle) LIMIT 1`.

    Finish with `REVOKE ALL ON FUNCTION public.resolve_profile_by_handle(TEXT) FROM PUBLIC;` and
    `GRANT EXECUTE ON FUNCTION public.resolve_profile_by_handle(TEXT) TO anon, authenticated,
    service_role;`.

    express a `lower(column) = lower($1)` filter, so the alternative is a pattern-match filter — and
