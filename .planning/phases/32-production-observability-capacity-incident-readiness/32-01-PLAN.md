<objective>
Build the D-10 central config layer — the single owner-editable surface that carries all tunable alert thresholds (Vercel 5xx, function throttles, dynamic-route p95, Supabase CPU, DB connections, disk, Auth/API 5xx, external-uptime consecutive failures, monthly spend), the SEV-1..4 enum, the growable alert-recipient list, and the incident owners. Hybrid shape per RESEARCH Open Question #3: a typed module for the mostly-static thresholds + SEV enum (benefits from type-checking, seeded from the SPEC's proposed values), and a small service-role-only Supabase table (`observability_recipients`) for the growable recipients/owners list (addable without a redeploy — the natural target for the deferred dashboard's CRUD UI).

Purpose: every downstream alerting surface (fan-out helper, daily cron, SEV routing, thresholds doc) reads from ONE place so "one place to adjust as we grow" (D-10) holds, and the deferred Observability Admin Dashboard becomes a thin UI over this layer rather than a rebuild.
Output: `lib/observability/config.ts` + tests; migration 110 (draft + text-tested) + its Jest content test; a HUMAN-GATED owner push step.
</objective>
