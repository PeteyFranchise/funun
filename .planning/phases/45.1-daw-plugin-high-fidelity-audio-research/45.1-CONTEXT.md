# Phase 45.1: DAW Plugin and High-Fidelity Live Audio — Research Context

**Captured:** 2026-09-23
**Status:** Research approved; implementation explicitly not approved
**Migration:** None

## Goal

Use real Bridge adoption and producer evidence to determine whether native AU/VST3/AAX integration and a
higher-fidelity live DAW-audio path are valuable, feasible, supportable, and safe.

## Locked boundaries

- **PLUG-01:** Do not implement a plugin before Phase 45 Bridge usage validates demand and workflows.
- **PLUG-02:** Evaluate AU and VST3 first; AAX requires separate Avid SDK/program/licensing/build review and
  Pro Tools demand evidence. No format is promised before verification in its actual hosts.
- **PLUG-03:** No network, encryption, allocation, disk blocking, or UI work may run on the realtime audio
  callback. Audio enters a bounded lock-free/buffered pipeline and failure never destabilizes the DAW.
- **PLUG-04:** Literal zero-disk upload is not a goal if it sacrifices crash recovery or audio correctness.
  Compare encrypted temporary spool, offline-bounce callbacks, and realtime capture honestly.
- **PLUG-05:** Live WebRTC DAW audio is reference monitoring, not a master. Evaluate stereo Opus/music mode,
  virtual audio device/native capture, latency, echo, and OS/browser limits without overstating quality.
- **PLUG-06:** Direct track insertion/pull must respect custody/download authority and host capabilities.
- **PLUG-07:** Public repository constraints, SDK license terms, code signing/notarization, binary release,
  crash telemetry, and update supply chain are load-bearing go/no-go items.
