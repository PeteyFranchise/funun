# Plan 45.1-01: Plugin feasibility, demand, SDK, and host matrix

## Objective

Return a go/no-go/sequence decision brief—not plugin production code—grounded in Bridge usage and verified
inside the DAWs Funūn's producers actually use.

## Research

1. Analyze Bridge beta by DAW/OS/workflow, upload/pull frequency, friction, requested direct insertion,
   failure/support load, audio classes, and willingness to install a plugin. Use aggregate/minimal telemetry
   plus interviews; do not collect local session paths/content.
2. Compare JUCE and credible alternatives for AU/VST3/AAX, commercial/open-source licenses, Avid access,
   Apple/Windows signing, notarization, installers, updater, CI/build farm, public-repo binary strategy,
   crash symbols, and ongoing host/OS compatibility burden.
3. Prototype offline/realtime host callbacks, bounded ring buffer/spool, background upload handoff, login/
   device delegation, room target, and pull/import in isolated experiments. Prove network never blocks the
   audio thread and failure is silent to audio output.
4. Build and manually verify a no-op/synthetic proof in the shortlisted real DAW/version matrix. Document
   host-specific constraints; do not infer Logic/Pro Tools behavior from another host.
5. Estimate build/support cost for AU-only, AU+VST3, and AU+VST3+AAX; define adoption/support thresholds
   that would justify each step.

## Human gate

Owner decides no-go, further spike, or a separately planned implementation phase and its format order.
Research completion grants no implementation permission.
