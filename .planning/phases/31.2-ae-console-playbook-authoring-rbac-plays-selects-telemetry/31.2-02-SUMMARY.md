## Accomplishments
- `accountForTick`/`foldAudibleSeconds` (`components/selects-player/audible-accumulator.ts`) — the pure genuine-accumulator delta math extracted per RESEARCH Pattern 4: a small forward contiguous tick (0<Δ≤2s) counts, seeking/backward/large-jump ticks yield 0, and the fold helper proves a pure scrub-through sequence totals ~0 while a contiguous full play totals ~its duration

## Decisions Made
- `clampDelta` returns 0 for `<=0`/non-finite input rather than throwing — keeps batch aggregation resilient to a single malformed row; the DB CHECK constraint (migration 132) is the defense-in-depth backstop if this pure contract is ever bypassed by a caller
- `aggregatePerTrack`'s `qualified` field is a single boolean, deliberately never multiplied by `replayCount` — matches R13's exact acceptance language ("past-threshold audible == exactly one qualified listen")
- `aggregateTrack` groups rows by `viewer_key` (a `null` key gets its own dedicated bucket) before delegating to `aggregatePerTrack` per group, so `qualifiedListens` at the track level counts distinct qualifying viewers, never deltas or replays
- `useAudibleTimeAccumulator.ts` ships with no unit test by design (jsdom cannot drive real `<audio>` `timeupdate`/`seeking` event timing) — its own correctness rests on Task 1's already-proven pure math; verified via `tsc --noEmit` only, exactly as the plan's task 3 verification specifies
