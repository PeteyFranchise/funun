## Decisions Made
- `requireRoomAccess`/`requireRoomAccessPage` check the caller's FULL role set via `getStaffRoles(auth.user)`, not just the single primary role `requireStaff`/`requireStaffPage` return — needed so a multi-role member passes when ANY held role (not just their highest-priority one) is granted, matching the plan's `<behavior>` spec for Task 1 exactly.
- The PATCH route double-guards against a leadership grant target: a fast 400 in the route handler before any service call, plus `isGrantableRole`'s own rejection inside `setRoomGrant`/`removeRoomGrant` — defense in depth rather than relying on a single check point.
- `setRoomGrant` uses `upsert(..., { onConflict: 'room_id,role' })` so re-granting an already-granted role is idempotent (no unique-constraint error), matching migration 130's `UNIQUE (room_id, role)`.
