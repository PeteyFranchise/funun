# Phase 31.2 Plan 08: Playbook Authoring UI + Dynamic Game-Plan Topic Sourcing Summary

**EntryEditor.tsx + a requireRoomAccessPage-gated room content page over plan 04's SOP/Topic routes, plus a read-time buildPickerTopics merge so authored Playbook Topics augment (never replace) the 31.1 seeded Game-Plan starters.**

## Performance

- **Duration:** 35 min
- **Started:** 2026-08-24T02:05:00Z
- **Completed:** 2026-08-24T02:40:00Z
- **Tasks:** 2
- **Files modified:** 5 (2 created, 3 modified)

## Accomplishments
- Room content page (`app/(admin)/admin/playbook/[room]/page.tsx`) self-guards via `requireRoomAccessPage(roomKey)`, resolves the room, computes approval authority the same way the plan-04 routes do, and lists published entries plus (for approvers) every pending draft in the room.
- `EntryEditor.tsx` gives members a full draft/edit/approve/reject authoring surface over the existing `/api/admin/playbook/entries` and `/api/admin/playbook/entries/[id]` routes — the server, not the client, decides publish vs. draft status.
- `buildPickerTopics` (TDD: RED test committed before implementation) concatenates `SEEDED_GAME_PLAN_TOPICS` with published `playbook_entries(entry_type='topic')`, never mutating or replacing the seeded constant.
- `loadAuthoredGamePlanTopics` reads the authored side of that merge, and the game-plan GET route now returns a separate `pickerTopics` field alongside the existing `topics`/`seeded` fields — the merge happens at the route (the picker's option-set call site), never inside `buildDefaultGamePlanTopics()`.
- All 3 of 31.1's pre-existing test groups (`coveredSummary`, `buildDefaultGamePlanTopics`, `buildGamePlanLogBody`, `normalizeGamePlanTopics`) pass unmodified — 15/15 tests green.

- `lib/client-partners/game-plan.ts` - Added `buildPickerTopics` (pure merge) and `loadAuthoredGamePlanTopics` (service-role loader); `SEEDED_GAME_PLAN_TOPICS`/`buildDefaultGamePlanTopics` untouched
- `lib/client-partners/game-plan.test.ts` - Extended (not rewritten) with 3 new `buildPickerTopics` tests; all 12 pre-existing tests still pass
- `app/api/admin/client-partners/[orgId]/game-plan/route.ts` - GET now also returns `pickerTopics` (seeded + authored, merged at read time)

## Decisions Made
- Topic entry content shape is `{ questions: string[] }`; SOP entry content shape is `{ items: string[] }` — chosen so `loadAuthoredGamePlanTopics` needs zero translation between what EntryEditor writes and what the picker merge reads.
- The room page's "all pending drafts for approvers" query is inline in the RSC page rather than added to `lib/playbook/entries.ts`, keeping that module's viewer-scoped `listEntries` contract (also used by the plan-04 GET route) unchanged.
- `components/admin/GamePlanPanel.tsx` (the actual picker UI) was intentionally left unmodified — out of this plan's `files_modified` scope; the route now exposes `pickerTopics` for a future plan to wire into the picker's rendered suggestions.
