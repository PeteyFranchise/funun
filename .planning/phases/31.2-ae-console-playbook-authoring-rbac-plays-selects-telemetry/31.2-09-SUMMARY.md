# Phase 31.2 Plan 09: Plays User Surfaces — PlayComposer, Today's Play Banner, Completion Rollup Summary

**Leadership composes and publishes a team-wide Play via PlayComposer (client-targeted health/stage segments + general directives), AEs see it as an always-visible "Today's Play" banner atop My Client Partners with own-book counts + deep-links + idempotent mark-done, and leadership sees a who's-acted rollup — closing the D-31.2-08..11 coaching loop.**

## Accomplishments

- `components/playbook/PlayComposer.tsx` — leadership builds a Play as a container of client_targeted (health-band or pipeline-stage segment) or general_task (title/note/link/attachment/content, no posting action) assignments, reorders them, and publishes via the plan-06 route; also shows the active play's who's-acted rollup inline
- `app/api/admin/plays/[id]/completions/route.ts` — leadership-only (verifyAdmin) rollup GET, reusing plan 06's `loadCompletions`
- `app/(admin)/admin/playbook/plays/page.tsx` — the leadership-only mounting page for PlayComposer (added beyond declared file scope — see Deviations)
- `components/admin/TodaysPlayBanner.tsx` mounted at the top of the My tab in `ClientPartnersRoom.tsx` — always visible while a play is active, own-book matching counts + deep-links for client-targeted assignments, directive content for general tasks, idempotent per-row mark-done, no snooze/dismiss
- `app/(admin)/admin/client-partners/page.tsx`'s `buildTodaysPlayData` — computes matchingCount/deepLink/done entirely server-side against the caller's own book (`myCompanyRows`, already `loadBook`-scoped), never a global list
- Closed plan 06's deferred `pipelineStageKey` wiring gap in `lib/client-partners/columns.ts` + `lib/client-partners/signals.ts` so stage-targeted assignments get correct own-book counts, not just health-band-targeted ones

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Added `app/(admin)/admin/playbook/plays/page.tsx`**
- **Found during:** Task 1
- **Issue:** PlayComposer.tsx had no RSC page to mount it, leaving it an unreachable, unusable component — the plan's own acceptance criteria ("Leadership composes/publishes...") require it to actually be reachable.
- **Fix:** Added a minimal leadership-gated (`requireStaffPage(['leadership'])`) page that loads the active play and renders `PlayComposer`.
- **Files modified:** `app/(admin)/admin/playbook/plays/page.tsx`
- **Verification:** `npx tsc --noEmit` clean.
- **Committed in:** `5cea842` (Task 1 commit)

**2. [Rule 1/2 - Bug/Missing Critical] Wired `pipelineStageKey` through `ClientPartnerRow`/`signals.ts`**
- **Found during:** Task 2
- **Issue:** Plan 06 explicitly deferred this wiring to plan 09 (per its SUMMARY's "Next Phase Readiness" and this plan's orchestrator notes). Without it, `matchingClientCount` would silently return 0 for every pipeline-stage-targeted `client_targeted` assignment on the banner, even though PlayComposer (this plan's own Task 1) lets leadership create exactly that kind of assignment.
- **Fix:** Added optional `pipelineStageKey?: string | null` to `ClientPartnerRow` and populated it from `resolveStage(...).key` in `signals.ts`'s `assembleRows()`.
- **Files modified:** `lib/client-partners/columns.ts`, `lib/client-partners/signals.ts`
- **Verification:** `npx tsc --noEmit` clean; `lib/client-partners/columns.test.ts` + `lib/client-partners/signals.test.ts` + `lib/client-partners/plays-eligibility.test.ts` all pass.
- **Committed in:** `c3f7b41` (Task 2 commit)

**3. [Rule 1 - Bug] Fixed a pre-existing test broken by the new `loadActivePlay` call path**
- **Found during:** Task 2 (full test suite run)
- **Issue:** `lib/admin/gate.test.ts`'s `loadClientPartnersRoomData` test suite uses a minimal chainable fake Supabase service that did not implement `.maybeSingle()`. `buildTodaysPlayData` (added by Task 2) calls `loadActivePlay`, which chains `.maybeSingle()` — the fake threw `TypeError: ...maybeSingle is not a function`.
- **Fix:** Added `maybeSingle: () => Promise.resolve({ data: null, error: null })` to the fake builder — correctly represents "no active play" for this suite, which never seeds a `plays` row.
- **Files modified:** `lib/admin/gate.test.ts`
- **Verification:** Full `npx jest` suite green (264 suites, 2834 tests) after the fix; was 3 failing before.
- **Committed in:** `d277c09` (separate fix commit, applied after discovering the break in Task 2's full-suite check)
