<objective>
Add the account-type access gate the Green Room has never had. Today every `/api/green-room/*` route checks
only `if (!user)` and the RLS insert policy is `author_id = auth.uid()` — any authenticated session (including
a buyer session that shares the same auth.users table) can post/read (RESEARCH Summary #2, Pitfall #3). This
plan adds the APP-LAYER half of the locked access matrix (Artist ✓ / Industry ✓ / else ✗) plus the inert,
forward-safe Team-Member "no posting under a Funūn email" block (INDUSTRY-07). The RLS backstop (defense-in-depth)
is the human-gated migration in Plan 28-05.

Source-of-truth decision (planner call, documented): the gate reads `user_profiles.member_type IN
('artist','industry')` — a single indexed lookup that matches the existing `lib/green-room/discover.ts`
convention and is kept in lockstep with `capability_grants` by Plans 28-01/28-05. A buyer/Team-Member/no-profile
principal has no `member_type` → excluded. Do NOT check `capability_grants` independently here (RESEARCH
Anti-Pattern: a fourth disagreeing gate).

Purpose: close the broken-access-control gap; buyers and staff-as-Funūn cannot participate.
Output: a testable, co-located Green Room access gate.
</objective>
