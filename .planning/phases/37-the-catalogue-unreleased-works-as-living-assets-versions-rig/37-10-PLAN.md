<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| collaborator-entered text (notes, titles, custom labels) → rendered diary | Free text from another account renders inside the owner's page |
| stored citation → what an artist and later a buyer read | The record's own words |
| signed playback URL → an audio element | A short-lived credential rendered into markup |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-37-60 | Tampering | XSS through a collaborator-entered note or title in the feed | medium | mitigate | React's default JSX escaping covers every rendered string, and no component in this plan uses raw-HTML injection. Stated as a plan-level prohibition so a later "rich notes" change must justify itself. |
| T-37-61 | Repudiation | Feed text drifting from the stored record | high | mitigate | Every entry's three parts come from `describeDiaryEvent()`, which reads the row and recomposes nothing; the AI consequence is asserted character-identical to the stored citation. |
| T-37-62 | Information Disclosure | A long-lived playback URL leaking a private take | medium | mitigate | URLs are minted server-side by the page with a short TTL (plan 06's batch signer) and are never constructed in the component; the component renders no player when none was supplied. |
| T-37-63 | Information Disclosure | Diary content reaching the public wall feed | high | mitigate | The component reads `work_diary_events` only, never imports the activity emitter, and the file's header records why the two must not be conflated. |
| T-37-64 | Tampering | Nudge creep turning the diary into a warning pile | low | mitigate | The single-value guiding-line prop and the plan-level prohibition on entry-attached nudges are both structural; the feed suite asserts no nudge affordance renders. |
| T-37-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install task exists in this plan — zero new packages in Phase 37.1. |
</threat_model>
