needs (artist, aggregate length, mood/energy/vocal, versions, instruments, and the tri-state
rights signal), move filtering/sorting/pagination server-side, and flip the catalogue page
from the representative fixture to live enriched rows.

Purpose: Make the catalogue pull real Sound Vault songs instead of the fixture. This is
DEFERRED and BLOCKED on the buyer-catalogue inclusion deliberation
(`.planning/deliberations/buyer-catalogue-inclusion-model.md`): which songs reach the
catalogue, by what workflow, and what the tri-state rights (Rights ready / Partial / Contact
required) actually mean are undecided, and the live model only computes binary rights-ready
today. This plan must NOT execute until that resolves — the first task is a blocking decision
gate.

Output (post-resolution): an enriched CatalogCard + loadCatalogPage + catalog route, live
rows on the page, and the fixture demoted to the empty-catalog case.

Prefer derive-over-migrate: mood/energy/vocal already live in tracks.metadata descriptors
(readDescriptors); artist is a public display name on user_profiles; length aggregates
existing per-track duration; versions = track count. Only a genuinely new column (instruments,
or a catalog_listing state if the resolution requires one) triggers a HUMAN-GATED migration
checkpoint — this plan authors SQL but never runs `supabase db push`.
</objective>
