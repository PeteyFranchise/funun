<objective>
Establish the light-theme buyer UI as a platform convention and resolve the double-nav:
make the light `.fnbl` system the buyer-portal shell, promote the catalogue's light top-nav
into a single shared BuyerTopNav mounted by the layout, retire the dark 16-03 sidebar, and
add a per-buyer dark-theme toggle (light default, dark opt-in, persisted by cookie).

Purpose: Two decisions converge on the same surfaces (layout + nav + catalogue header), so
they are one cohesive change. Buyer side = light (owner decision); logged-in buyers may
toggle to dark using Claude Design's dark buyer-portal tokens. The catalogue currently draws
its OWN top-nav while the layout draws a competing dark sidebar — this plan reconciles them
to one nav.

Output: A shared theme module (FNBL_CSS with a dark variant), a cookie theme util, a shared
BuyerTopNav + ThemeToggle, and a re-shelled light layout.

Nav-reconciliation decision (Claude's discretion, CONTEXT line 71): OPTION A — promote the
catalogue's light header to a shared BuyerTopNav mounted in the layout for all buyer-portal
pages, remap its Catalog/Shortlists/Requests links into it, add the dark-toggle control, and
retire BuyerPortalNav's dark sidebar. The catalogue receives an `embedded` prop so it no
longer draws its own header inside the shell. Rationale: the Claude Design mockup is a
full-width top-nav browse with no sidebar, and there is no unauthenticated public route in
this group today (CatalogBrowserLight's isPublic path is currently unused), so one shared
top-nav is the faithful, single-idiom result.
</objective>
