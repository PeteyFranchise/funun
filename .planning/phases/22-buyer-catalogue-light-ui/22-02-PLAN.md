<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| buyer client → POST /api/buyer/requests | Untrusted buyer form input crosses into the license_requests write path. license_requests writes are REVOKEd from `authenticated` (migration 081); this route is the only write path. |
| buyer client → catalogue rows | The rendered row carries a vault_project_id + track ids the buyer could tamper with before submit. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-22-02-01 | Elevation of Privilege / Spoofing | POST /api/buyer/requests (org scoping) | high | mitigate | The client never sends buyer_org_id/created_by — the route derives org from the authenticated session's buyer_members row (`member.org_id`) and gates on `canSubmitRequest(member)`. buildRequestBody emits ONLY D-07 dimensions; a Task 1 test asserts the body has no org/created_by/stage/owner_id/commission_pct keys, and the route's `.strict()` schema rejects any injected field. This plan does not modify the route. |
| T-22-02-02 | Tampering | request against private / non-rights-ready / blocked project | high | mitigate | `authorizeRequestTarget` re-runs the rights-ready + Phase 13 visibility + block gate server-side and returns 404; the wiring surfaces that 404 as an inline error and never pre-trusts the row. A tampered/synthetic vault_project_id (including every fixture row) is rejected server-side — correct-by-construction. |
| T-22-02-03 | Tampering | track_ids not belonging to the project | medium | mitigate | track_ids are sourced only from `modalRow.tracks` (the authorized project's tracks); the route independently verifies every track_id ∈ project and 400s otherwise. Surfaced inline. |
| T-22-02-04 | Tampering (input validation) | usage/territory/term/budget dimensions | medium | mitigate | Modal option lists are swapped to USAGE_TYPE_VALUES/TERRITORY_VALUES so the client can only emit valid enum values; offer→integer cents and term→integer months are parsed client-side and re-validated server-side by `z.enum(...)` / `z.number().int()`. Free-text vocabulary is eliminated. |
| T-22-02-05 | Information disclosure | artist commercial floor / match verdict | low | mitigate | The modal renders NO pre-cleared terms and NO match verdict (mirrors RequestComposer's deliberate omission); success shows only the generic toast. `matched_precleared` is computed server-side and never returned to browse. |
| T-22-02-SC | Tampering | npm/pip/cargo installs | low | accept | No packages installed — native fetch + existing zod/schema modules only. Nothing to audit. |

Block-on-high check: the two high-severity authorization threats (T-22-02-01, T-22-02-02) are fully mitigated by reusing the existing, unmodified route; no unmitigated high remains.
</threat_model>
