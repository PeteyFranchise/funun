<objective>
The take player has no keydown handler for playback at all today — every interaction is a mouse.
Add the transport vocabulary a web player is expected to have, and the playback speed a writer
needs to catch a mumbled lyric or judge intonation.

Purpose: this is the last of the five items, and it is the one with the sharpest failure mode. The
room mounts one player per take, so a naive per-component listener makes every mounted take answer
the same spacebar at once. And the room is full of typing surfaces — the lyrics pad, the comment
composer, the take-rename field — so an unsuppressed shortcut pauses a writer's audio mid-sentence.

Output: a keyboard that belongs to exactly one player, a speed control that resets per take, and a
quiet legend so the bindings are discoverable without a help panel.
</objective>

  <action>
Claiming. Give each player a stable instance identity — the version id is already unique per
mounted player on a page. Call `claimActivePlayer` from the `<audio>` element's `onPlay` handler
and from a `onPointerDownCapture` on the player's existing root div, so the player a writer just
touched or started is the one the keyboard belongs to. Call `releaseActivePlayer` on unmount.
Do not claim on hover, on focus-within, or on mount — a page with six takes would fight over it.

Listening. Register one document keydown listener per player, in an effect. As its first act the
handler calls `isActivePlayer` with this player's id and returns immediately when false. With N
players mounted, N listeners run and exactly one acts. This is simpler and more robust than a
shared singleton listener, because a player that unmounts takes its own listener with it.

Suppressing. Before dispatching anything, call `shouldSuppressShortcut(event,
document.activeElement)` and return when it is true. Passing the active element in at the call
site is what keeps the rule itself unit-tested. It covers four cases and all four are load-bearing
here: the comment composer is a textarea, the take-rename field is an input, the lyrics pad is
elsewhere on the same page, and an IME composition can fire an arrow keydown while focus is
technically inside a text field.

Dispatching. Call `resolveTransportAction(event)` and act on the result. `toggle-play` runs the
existing `togglePlayback`. `nudge` seeks by its `deltaMs` from the current position through the
existing `seek`, which already clamps. `step-comment` is wired in Task 2. Call `preventDefault`
only when an action was actually resolved — a null result must leave the key to the browser, which
is what keeps page scrolling and browser shortcuts intact. Space in particular must scroll the
page normally when no player holds the keyboard.

Do not add J, K or L bindings. The vocabulary is deliberately the web-player one, learnable without
being taught.

In the test file, add a static-markup assertion that the player renders no visible keyboard
affordance beyond the legend added in Task 2 — the bindings are behaviour, not chrome. The
dispatch logic itself is covered by `lib/catalogue/take-transport.test.ts`; do not restate any key
mapping in the component.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| document keydown → player action | A page-level listener observes every keypress in the room, including keys typed into the lyrics pad and the comment composer |
| module registry → which player acts | A single shared module value decides who owns the keyboard |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-39-29 | Tampering | a keypress meant for a text field reaching the transport | high | mitigate | `shouldSuppressShortcut` checks four conditions — INPUT/TEXTAREA/SELECT, contenteditable, IME composing, and keyCode 229 — and is unit-tested for each independently. | T-39-30 | Tampering | every mounted player answering one keypress | high | mitigate | The active-player registry gates each listener's first line; a player claims only on play or on a direct pointer-down, and releases on unmount. Plan 39-11 carries the two-players-mounted manual check |

| T-39-32 | Information Disclosure | a global shortcut hijacking a browser or OS binding | low | mitigate | `resolveTransportAction` returns null whenever meta, ctrl or alt is held, and `preventDefault` is called only when an action actually resolved, so an unclaimed Space still scrolls the page |
