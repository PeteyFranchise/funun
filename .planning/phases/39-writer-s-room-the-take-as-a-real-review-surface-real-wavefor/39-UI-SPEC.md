# Phase 39 — UI Design Contract

> Visual and interaction contract for the Writer's Room take-review surface. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker. This is a **refinement of two existing, densely
> styled components** (`TimedTrackPlayer.tsx`, `VersionComparisonPanel.tsx`), not a new screen —
> the contract below extends their established micro-scale rather than replacing it.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind, no Radix/base-ui |
| Icon library | none — plain unicode glyphs only (✕ ← → ✍ 🎤 ⟲), matching existing usage in both target files |
| Font | Inter via `--font-sans` (fixed project token, `tailwind.config.ts`) |

**Why "none," confirmed rather than re-asked:** `components.json` does not exist anywhere in the
repo across 39 phases of UI work. Both files this phase edits are hand-rolled Tailwind with a
mature, consistent micro-density scale of their own (9–13px type, 1–3px hairline gaps, pill
markers). Introducing shadcn for one phase now would fragment this specific surface rather than
unify it — the correct move is to extend the existing local convention, not import a new one.
If a project-wide shadcn adoption is ever decided, it should be its own phase, not a side effect
of Phase 39.

## Spacing Scale

The generic 8-point scale does not describe this component family — `TimedTrackPlayer.tsx` and
`VersionComparisonPanel.tsx` already run a denser, sanctioned micro-scale. This phase **must
reuse it exactly**, not introduce parallel values.

| Token | Value | Usage (existing, confirmed by direct code read) |
|-------|-------|--------------------------------------------------|
| hairline | 1px | `gap-px` between waveform bars — unchanged, only bar count grows 48→~200 |
| 2xs | 4px | icon/glyph gaps, avatar-to-name gaps (`gap-1`, `gap-1.5`) |
| xs | 8px | default inline control gaps (`gap-2`), vertical rhythm between stacked lines (`mt-2`) |
| sm | 10px | card/composer internal padding (`px-2.5 py-2`) |
| md | 12px | card padding (`p-3`), section top-gaps (`mt-3`), thread padding |
| lg | 16px | major block separation (`mt-4`) — used sparingly, e.g. VersionComparisonPanel's timeline block |
| xl | 20px | modal-level separation only (`mt-5`, VersionComparisonPanel's outer sections) |

Exceptions (all pre-existing, this phase must match them — not introduce new spacing values):
`h-9` (36px) waveform bar-row height in `TimedTrackPlayer`; `h-11` (44px) in
`VersionComparisonPanel`; `top-7` marker vertical offset. New elements this phase adds (Mark-span
pill, speed control, loop toggle, pin dots) must sit inside these existing container heights —
do not grow the waveform block's overall height (`h-[58px]` / `h-[76px]`) to make room; use
overlay layers instead (see Component Contract below).

**Mobile hit-target exception (hard constraint):** the "Mark span" toggle and its
"Confirm span" / "Cancel" pair are the one place in this component family that must render as
real ≥44×44px buttons rather than the row's usual dense text links — thumb-sized hit targets are
a hard constraint for this specific interaction because it is modal (accidental exit or a missed
tap has real cost: a lost drag). Every other new control (speed steps, loop toggle, pin button)
stays at the existing text-link density; only Mark-span's enter/confirm/cancel trio gets the
larger tap target.

## Typography

Reuse the existing scale exactly. Two weights only, matching current usage.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Micro-label (timestamps, mode state, chip captions) | 9px | 600 (semibold) | normal (auto) |
| Control / button label | 10px | 600 (semibold) | normal (auto) |
| Body (composer text, thread body, empty-state copy) | 11px | 400 (regular) | `leading-5` (20px) |
| Secondary/dim caption | 10px | 400 (regular) | `leading-4` (16px) |

No new sizes are introduced. Every new string this phase adds (Mark-span banner, speed labels,
loop toggle, pin popover, flagged-span caption, keyboard-legend line) must land in one of these
four rows — if an executor reaches for 12px+ or a third weight for a new element, that is a
deviation from this contract, not a discretionary call.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `ink` `#0a0a0f` | page background behind the player |
| Secondary (30%) | `card` `#0E0D1E` / `card2` `#1A1838` | player container, transport row, composer, popovers |
| Accent (10%) | `brandindigo` `#818CF8` | see reserved-for list below |
| Destructive/error | Tailwind `rose-300` / `red-300` (existing usage, not a custom token) | error text only — this phase adds no destructive *action* |

**Accent (`brandindigo`) reserved for, explicitly:**
- Seek progress fill on the real waveform (existing, unchanged)
- Point-comment marker pills, default state (existing, unchanged)
- **Committed range-comment shaded span** — `bg-brandindigo/15 border-x border-brandindigo/40` (new, D-04/D-07) — indigo signals "a saved comment," never "currently marking"
- Active speed step in the new 4-step control
- Active "Loop" toggle text
- Resolve/reopen thread action text (existing, unchanged)

**`brandfuchsia` (`#D946EF`) reserved for, explicitly:**
- "Mark span" toggle, both idle and active states (idle: text link matching "Record over"'s
  existing fuchsia treatment; active: filled pill) — fuchsia signals "an authoring mode is live,"
  matching the existing "Record over" action's color, not the passive comment-marker indigo
- **In-progress drag span** (uncommitted) — `bg-brandfuchsia/20 border-x border-brandfuchsia/60`
- The mode-active ring around the whole waveform block — `ring-2 ring-brandfuchsia/50`

**Indigo→fuchsia gradient (`bg-grad`), spent once per screen:** reserved for the **"Confirm
span"** button inside the Mark-span composer — the single highest-commitment new action this
phase introduces (it commits a shaded, publicly visible range comment). No other new element in
this phase may use the gradient. This does not compete with any other screen's gradient spend,
since the Mark-span composer is a transient overlay state, not a persistent screen element.

**Flagged carried span (D-07 — "needs a new position"):** amber, not red — this is a repositioning
prompt, not an error. Use Tailwind `amber-400` (`#FBBF24`), matching the "hygiene warmer than
legal" doctrine already ratified for this codebase (`sketch-findings-funun`'s `warn` token is the
same hex). Marker pill: `border-amber-400/70 text-amber-400` instead of the default indigo. Do
not reuse `rose-300`/`red-300` here — those stay reserved for genuine errors (failed requests,
decode failures).

**Private pins deliberately use neither accent color.** A pin dot is `bg-lav/60` — plain lavender
text-tier, no border, no pill. This is the point: a pin must never visually compete with a
comment marker (indigo pill) or a mode indicator (fuchsia). See Component Contract §4.

## Component & Interaction Contract

This is the operative section for `gsd-ui-checker`'s Visuals dimension — it specifies the
concrete states this phase adds, on top of the tokens above.

### 1. Waveform states (D-01, D-02, D-03)

**Real waveform (loaded).** Unchanged visual treatment from today — vertical bars,
`min-w-px flex-1 rounded-full`, filled portion `bg-brandindigo`, unfilled `bg-lavdim/35`,
container stays `h-9` (`TimedTrackPlayer`) / `h-11` (`VersionComparisonPanel`). Only the data
source and bar count change: ~200 real peak values (0–100 scaled ints) replace the 48-value
`WAVE_BARS` constant.

**Rest state (no peaks yet — D-03's one-time backfill window).** Must be **structurally
distinguishable from any real waveform**, not just visually calmer:
- Fixed, uniform bar height (recommend 15% — well below any real take's typical minimum, so it
  can never coincidentally read as data), rendered in `bg-lavdim/20` (dimmer than the real
  waveform's unfilled `bg-lavdim/35` — this state should read as quieter than "no comment yet,"
  not as "loaded, just quiet music")
- **No indigo progress fill at all** — there is no real shape to sweep across, so showing a fill
  would falsely imply data exists
- A gentle `animate-pulse` (existing Tailwind utility, zero new dependency) communicates
  "loading," not "this is the shape"
- No error copy on first load — this is expected and self-healing (D-03). Only surface an error
  caption if the backfill decode itself throws (see Copywriting Contract)
- HARD CONSTRAINT reminder: this state must never be, or resemble, the deleted `WAVE_BARS`
  array — flat and uniform, never random-looking bar heights

**Level-matched variant (`VersionComparisonPanel` only, D-02).** Identical bar markup/classes to
the real waveform — the only difference is the peak values fed in (level-matched vs raw). No new
visual language; extend the panel's existing caption
("Listening aid only—approximately balances playback without changing either file.") so it also
covers the waveform, e.g. append "and the picture on-screen matches it." No separate color or
badge — per D-02's own stated principle, "the picture matches what you are actually hearing," a
badge would suggest the two states differ more than they should feel.

### 2. "Mark span" mode (D-04)

**Entry.** A new toggle button in the existing transport-link row (same row as
"Record over" / "Pull lyrics" / "Download" / "Name" / "Archive").
- Idle: `text-[10px] font-semibold text-brandfuchsia hover:text-white` — visually paired with
  "Record over" (also fuchsia), signaling "this starts an authoring mode."
- Active: becomes a filled pill, not a text link —
  `rounded-full bg-brandfuchsia px-2 py-1 text-[9px] font-bold text-ink`, label changes to
  **"Marking span — Esc to exit"** on desktop / **"Marking span"** on mobile (no Esc key exists
  on a phone; mobile relies on the explicit Cancel button below, not keyboard copy).
- The whole waveform block additionally gets `ring-2 ring-brandfuchsia/50` while active — the
  mode must be legible from the block's outline alone, not only the button label, satisfying
  "a writer must never wonder whether they are in it."

**Seek disabled.** The existing invisible `<input type="range">` seek overlay
(`absolute inset-x-0 top-0 h-9 w-full cursor-pointer opacity-0`) is disabled while the mode is
active; a new pointer-capture layer takes over the same footprint with `cursor-crosshair`.

**In-progress drag.** A live-updating shaded rectangle from drag-start x to current pointer x:
`bg-brandfuchsia/20 border-x border-brandfuchsia/60`, drawn above the bars, below any marker
layer. Minimum committable width: **100ms** of audio (Claude's Discretion, guards against
accidental sub-100ms spans per CONTEXT.md) — a drag narrower than that snaps back with no
confirm affordance shown.

**Confirm.** Releasing a ≥100ms drag reveals **"Confirm span"** (gradient button, the phase's one
gradient spend — see Color) beside **"Cancel"** (plain text, `text-lavdim hover:text-white`).
Confirming opens the comment composer pre-bound to `{ startMs, endMs }`; the shaded rect persists
at slightly higher opacity (`bg-brandfuchsia/25`) while composing, so the writer can see exactly
what they are about to comment on.

**Exit.** Esc (desktop, suppressed only per D-16's focus rule — Esc itself must still fire even
with the composer textarea focused, since D-04 explicitly requires "Esc exits") and an always-
visible **"Cancel"** text button (desktop) / real button (mobile, ≥44px) both discard the draft
and return the seek overlay to normal. There is no silent, keyboard-only exit path on mobile.

**Mobile parity.** Identical interaction shape — press "Mark span" (≥44×44px tap target, an
explicit exception to this row's usual text-link density — see Spacing), drag with touch to
paint, tap "Confirm span" or "Cancel" (both real ≥44px buttons on mobile, not text links). No
long-press, no modifier-drag — one interaction model, as D-04 requires.

### 3. Range comments (D-04, D-07, D-09)

**Committed span marker.** A shaded band at the span's true bounds,
`bg-brandindigo/15 border-x border-brandindigo/40`, rendered underneath the bars (indigo, not
fuchsia — indigo means "saved," fuchsia means "currently marking," see Color). One marker pill
(existing style, unchanged: `rounded-full border border-brandindigo/70 bg-card px-1 text-[9px]
font-bold`) sits at the span's **start** only — no separate end-marker, avoiding a second pill
that would double the existing marker-clustering problem the 2027 doc already flags.
`aria-label` extends the existing pattern:
`"Range comment, 0:45 to 0:52, {n} {comment|comments}"`.

**Carried comment ("carried from v1," D-09).** Reuse the chip that **already exists** in
`TimedTrackPlayer.tsx` (`shrink-0 rounded-full border border-hair px-2 py-1 text-[8px]
text-lavdim`) — no new component needed. Only the copy needs alignment to D-09's exact phrasing:
change `From {version}` to **`Carried from {version}`** (lowercase "carried," matching D-09
verbatim) so it never reads as a citation of the *current* take.

**Flagged carried span (D-07 — in-point no longer fits the new take).** New visual, none
existing today: recolor the marker pill to `border-amber-400/70 text-amber-400` (see Color) and
append a caption chip **"Needs a new position in this take"** with a **"Reposition"** action that
re-enters Mark-span mode, pre-seeded near the clamped edge so the writer isn't hunting for where
it landed. Never silently drop or collapse to a point — the flagged pill is the visible proof it
is "still offered."

### 4. Private pins (D-10, D-11, D-12, D-13)

**Pin mark.** Deliberately **neither** accent color — a plain lavender dot,
`absolute bottom-1 h-1.5 w-1.5 rounded-full bg-lav/60`, sitting on the waveform baseline (not at
`top-7` where comment pills live) so it never occupies the same visual row as a shared marker.
No pill shape, no border, no count badge — a pin is a bookmark, not a thread.

**Drop affordance.** Because tapping the waveform must only ever seek (hard constraint, shared
with comments), pin creation is an **explicit button**, mirroring how comments are already
created today (seek sets the position; an explicit action commits something at that position).
Add a small **"Pin"** text link to the transport row (`text-[10px] text-lavdim
hover:text-brandindigo`, deliberately quieter than "Mark span" — a pin is low-ceremony). Pressing
it drops a wordless pin immediately at the current playhead position; no composer, no confirm
step. First use only: a one-time dismissible coachmark near the button —
**"Pins are private — only you can see them."** — stored via the existing
`lib/catalogue/local-drafts.ts`-style per-user local persistence pattern so it never reappears.

**Promote affordance.** Tapping a pin dot opens a small inline popover (not a full thread — pins
have no thread): `bg-card2 border border-hairstrong rounded-[8px] p-2 text-[9px]`, two actions —
**"Turn into a comment"** (opens the normal composer pre-seeded at the pin's timestamp; on
successful post, the pin row is deleted — D-12's "consumes the pin," not a soft flag) and
**"Remove pin"** (deletes with no confirmation dialog — a pin is free to redrop, per D-13, so a
confirm step would be friction the decision explicitly rejects).

**Never on the presence channel.** No pin action may call `broadcast(...)` /
`channel.send(...)` on `writers-room:{workId}:presence` — this is a code-level constraint (see
39-VALIDATION.md's grep gate), not a visual one, but it has a visual consequence: **a pin must
never appear to any other viewer's client, under any circumstance, including a second browser tab
of the same room.** There is no "loading other people's pins" empty state to design, because the
server never returns other people's rows — RLS does the hiding, not the UI.

### 5. Transport controls (D-05, D-06, D-14–D-18)

**Playback speed (D-17, D-18).** A 4-step segmented control in the transport row:
`flex items-center gap-1 rounded-full border border-hairstrong bg-card2 p-0.5 text-[9px]`.
Steps: `0.5× · 0.75× · 1× · 1.5×`. Active step: `bg-brandindigo text-ink font-bold`; inactive:
`text-lavdim hover:text-white`. **Visual default on every take load is `1×` highlighted** — the
control must never retain a highlighted 0.5×/0.75×/1.5× state from a previously viewed take
(D-17's reset-per-take).

**Loop toggle (D-05).** Appears **only** when a range/thread is open — placed in the existing
thread-header row (beside the Prev/Next pair). Text toggle: **"Loop ⟲"**, active
`text-brandindigo font-semibold`, inactive `text-lavdim hover:text-white`. Opening a range
comment always plays its span once and stops by default; the loop toggle is the only way to
repeat it — nothing loops on its own.

**Pre-roll (D-06).** No dedicated visual — 2 seconds before a comment/span's start, clamped at
0:00. The shaded span still renders at its true bounds (see §3); only the playhead's audible
start differs from where the shading begins. No UI needs to explain this; it should simply feel
like natural run-in.

**Keyboard discoverability (D-14, D-15).** No help panel is in scope. Add one persistent, quiet
legend line under the waveform, desktop only (`hidden sm:block`, since a phone has no physical
keyboard to discover):
`text-[9px] text-lavdim` — **"Space play/pause · ← → seek 5s · ⇧← ⇧→ nudge 1s · [ ] comments"**.

**Suppression (D-16).** Not a visual spec — but any new focusable control this phase adds
(Mark-span button, speed steps, loop toggle, pin popover buttons) must be excluded from the
global keydown listener's target check the same way the existing composer/rename/lyrics fields
already are, so pressing Space inside a newly-added text control never toggles playback.

## Accessibility Contract

- Every marker (point, range, flagged, carried) is a real `<button>`, keyboard-reachable via Tab,
  with an `aria-label` stating **timestamp, count, and open/resolved state** — extending the
  existing pattern already present on point markers.
- `[` / `]` step focus/selection between comment threads (D-15) — must work with focus anywhere
  outside an input/textarea/contenteditable (D-16).
- The Mark-span mode's active state must be announced, not just colored — the pill's text content
  change ("Marking span — Esc to exit") already satisfies this for screen readers, since it is
  real text, not an icon-only state.
- Pin dots need **no** `aria-label` referencing other users — there are none to reference; the
  author's own pins should still get a label (`"Your pin at {t}"`) for the author's own assistive
  tech use.
- Speed control and loop toggle are real buttons with `aria-pressed` reflecting active state.
