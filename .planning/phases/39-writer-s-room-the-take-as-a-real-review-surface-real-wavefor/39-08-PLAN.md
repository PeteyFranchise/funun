<objective>
Give a span somewhere to live on screen. `work_version_comments.timestamp_ms` was a single
integer, so "lower the guitars through this section" had nowhere to point; plan 39-04 gave the
data path an end, and this plan gives a writer a way to draw one, see one, hear one, and fix one
that no longer fits.

The interaction has to be an explicit mode rather than a plain drag, because an invisible
`<input type="range">` already covers the whole waveform for seeking and a plain drag is therefore
already taken — and because clicking a waveform must never accidentally create a comment.

Output: Mark-span mode, the committed span band, span playback with pre-roll and an opt-in loop,
and the amber reposition prompt for a carried span that outgrew its take.
</objective>

  <action>
Add state for the mode and the drag: whether span mode is active, the drag anchor in milliseconds,
the current pointer position in milliseconds, and a confirmed-but-not-yet-posted pending span.

Entry. Add a toggle to the existing transport link row. Idle it is a fuchsia text link, visually
paired with Record over because both start an authoring mode. Active it becomes a filled fuchsia
pill whose label states that marking is live and, on the `sm` breakpoint and above only, that Esc
exits — a phone has no Esc key, so that half of the label is hidden below `sm` and the explicit
Cancel button is the mobile exit. Use the UI contract's exact classes for both states.

While the mode is active, add `ring-2 ring-brandfuchsia/50` to the whole waveform block, so the
mode is legible from the block's outline alone and a writer never has to read a button to know
whether they are in it.

Seek handover. While the mode is active, set `disabled` on the existing invisible seek range and
render a sibling capture layer over the same footprint with `cursor-crosshair`. Handle
`onPointerDown`, `onPointerMove` and `onPointerUp` on that layer, calling `setPointerCapture` on
down and releasing on up so a drag that leaves the element still tracks. Convert a pointer's
`clientX` to milliseconds against the layer's own `getBoundingClientRect()` and the player's
`effectiveDurationMs`. The same handlers serve touch and mouse — pointer events are one code path,
which is what makes D-04's single interaction model real rather than aspirational.

In-progress band. While dragging, render a live band from the anchor to the current pointer using
`spanGeometry`, with the UI contract's in-progress fuchsia classes, drawn above the bars and below
the marker layer.

Confirm and cancel. On pointer-up, run `normalizeSpanDrag`. A null result means the drag was
shorter than `MIN_SPAN_MS`: discard it silently and show no confirm affordance at all — do not
post it, do not round it up, do not surface an error. A non-null result becomes the pending span
and reveals two controls: Confirm span, the gradient button that is this phase's single gradient
spend, and Cancel. Confirming binds the composer to the pending span and opens the comment panel;
the band persists at the contract's slightly higher opacity while composing so the writer can see
exactly what they are about to comment on. Cancel discards the pending span and leaves the mode.

On mobile both Confirm and Cancel render as real buttons at or above 44 by 44 pixels, not text
links. There is no keyboard-only exit path on a phone.

Exit. Escape exits the mode and discards the pending span. Attach this with a document keydown
listener that is registered only while the mode is active, and deliberately do not apply the
general typing-surface suppression to it: D-04 requires Esc to exit, and the composer textarea
will often hold focus at exactly the moment a writer wants out. Escape is the one key exempt from
that rule, and only while this mode is live. Always release the listener when the mode ends or the
component unmounts.

In `components/catalogue/TimedTrackPlayer.test.tsx`, add static-markup assertions: the Mark span
control renders in the transport row; with no span mode active the markup contains no
`cursor-crosshair` and no `ring-brandfuchsia`; the seek input is not disabled by default. Drag
behaviour itself is not assertable in this environment — that is exactly why
`normalizeSpanDrag` and `spanGeometry` are unit-tested in `lib/catalogue/take-spans.test.ts`, and
this task adds no duplicate arithmetic in the component.

  <action>
Committed band. For every root comment that has an `endTimestampMs`, render a shaded band at its
true bounds using `spanGeometry` and the UI contract's indigo classes, drawn underneath the bars.
Indigo means saved; fuchsia means currently marking. Keep exactly one marker pill per span, at its
start — a second pill at the end would double the marker-clustering problem the design source
already flags. Extend the marker's `aria-label` so a range states both ends and its comment count,
matching the existing point-marker label pattern.

Review seeking with pre-roll. Introduce a single review-seek helper used by `selectComment`, by
the Previous and Next buttons, and later by the keyboard bindings in plan 39-10. It sets the audio
element's `currentTime` to `preRollStartMs(target)` while setting the displayed playhead to the
true target. That split is deliberate: the shaded band and the marker stay where they actually
are, and only the audible start is early, so it feels like a natural run-in rather than a rewind.
Once playback starts, the existing `onTimeUpdate` handler takes the playhead over as usual.

Play once and stop. Hold the currently open comment's stop point in a ref. In `onTimeUpdate`, when
a stop point is set and the current position has passed it, pause — unless looping is on, in which
case seek back to the pre-roll start instead. Opening a range comment sets the stop point to its
end and starts playback; opening a point comment sets no stop point and does not auto-play.
Clear the stop point whenever the selection changes, the writer seeks manually, or the mode
changes. Nothing loops on its own.

Loop toggle. Render it in the thread header beside Previous and Next, only while a thread is open,
as a text toggle with the contract's active and inactive treatments and an `aria-pressed`
reflecting state. It starts off every time a thread opens.

Posting a span. When the composer holds a pending span from Task 1, `submitComment` sends
`timestampMs` as the span start and `endTimestampMs` as its end; with no pending span it sends the
playhead position and no end, exactly as today. Clear the pending span on a successful post, on
cancel, and on switching to reply mode — a reply is a message in a thread, not a second span.

Add static-markup assertions in the test file: a fixture comment carrying an `endTimestampMs`
renders a band element with `bg-brandindigo/15`, renders exactly one marker pill for that comment,
and produces an `aria-label` naming both timestamps. Assert a point comment renders no band. The
pre-roll arithmetic itself is covered in `lib/catalogue/take-transport.test.ts`; do not recompute
it in the component.
  </action>
