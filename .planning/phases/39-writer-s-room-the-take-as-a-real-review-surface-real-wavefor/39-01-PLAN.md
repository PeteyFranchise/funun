(1) Peaks on `work_versions`. `ALTER TABLE public.work_versions ADD COLUMN peaks SMALLINT[]`
plus a table constraint named `work_versions_peaks_shape` asserting
`peaks IS NULL OR (cardinality(peaks) = 200 AND array_position(peaks, NULL) IS NULL)`. Use a
pure expression — a CHECK constraint may not contain a subquery, so the per-value 0–100 range is
enforced at the route layer (plan 39-03's `PeaksSchema`) and by `SMALLINT` at the column layer;
the DB's job here is the fixed cardinality that bounds the payload. Add a
`COMMENT ON COLUMN public.work_versions.peaks` recording that the array is percent-height bars
(0–100) computed client-side at take creation, and that a NULL means "not extracted yet — the
player backfills it", never "draw a placeholder shape". `work_versions` has no column-level
GRANT list (migration 136 gates it by RLS alone), so issue no GRANT for this column.

(2) Span and reposition flag on `work_version_comments`. One `ALTER TABLE` adding
`end_timestamp_ms INTEGER` and `needs_reposition BOOLEAN NOT NULL DEFAULT false`, plus two named
constraints in 160's paired style: `work_version_comments_end_after_start` asserting
`end_timestamp_ms IS NULL OR end_timestamp_ms > timestamp_ms`, and
`work_version_comments_end_range` asserting
`end_timestamp_ms IS NULL OR end_timestamp_ms BETWEEN 1 AND 86400000`. Then restate the whole
`GRANT SELECT (...) ON public.work_version_comments TO authenticated` column list from migration
160 line 65 with `end_timestamp_ms` and `needs_reposition` appended — a column not in that list
is invisible to the API client. Do not touch the existing
`work_version_comments_select` policy, and do not add a second policy to this table.

(3) `validate_work_version_comment()` — `CREATE OR REPLACE`, same no-argument trigger signature,
copying the whole existing body and adding two guards beside the existing
`comment_timestamp_out_of_range` check: raise `comment_end_timestamp_out_of_range` (ERRCODE
`22023`) when `NEW.end_timestamp_ms` is not null, `v_version.duration_seconds` is not null, and
`NEW.end_timestamp_ms` exceeds `ceil(v_version.duration_seconds * 1000)::INTEGER`; and raise
`reposition_flag_requires_carry` (ERRCODE `P0001`) when `NEW.needs_reposition` is true while
`NEW.carried_from_comment_id` is null. The existing trigger binding is unchanged.

(4) `create_work_version_comment` gains a span parameter. Adding a parameter to a Postgres
function creates an overload rather than replacing it, and PostgREST then cannot resolve a
`.rpc()` call — so first issue
`DROP FUNCTION IF EXISTS public.create_work_version_comment(uuid, uuid, text, integer, uuid, uuid[]);`
and only then `CREATE OR REPLACE FUNCTION public.create_work_version_comment(p_work_id UUID,
p_version_id UUID, p_body TEXT, p_timestamp_ms INTEGER, p_parent_comment_id UUID DEFAULT NULL,
p_mentioned_user_ids UUID[] DEFAULT '{}'::UUID[], p_end_timestamp_ms INTEGER DEFAULT NULL)`.
Copy the existing body verbatim and add one guard in the existing `IS NULL OR ... NOT BETWEEN`
style: raise `invalid_comment_end_timestamp` (ERRCODE `22023`) when `p_end_timestamp_ms` is not
null and either falls outside 1..86400000 or is not strictly greater than `p_timestamp_ms`. Add
`end_timestamp_ms` to the INSERT column list and `p_end_timestamp_ms` to its VALUES list. Close
with a `REVOKE EXECUTE` / `GRANT EXECUTE` pair restating the new seven-argument signature
`(uuid, uuid, text, integer, uuid, uuid[], integer)`.

(5) `review_work_version_comment_carry()` — `CREATE OR REPLACE`, same three-argument signature,
carrying both endpoints together. Declare a `v_bound INTEGER` and set it, after `v_target` is
loaded, to `ceil(v_target.duration_seconds * 1000)::INTEGER` or NULL when the target take has no
duration. Replace the bare `LEAST(...)` expression in the `INSERT ... SELECT` with two
`CROSS JOIN LATERAL` derivations over each `source` row so the pair is computed once and reused:

  - start: `LEAST(source.timestamp_ms, COALESCE(CASE WHEN source.end_timestamp_ms IS NULL THEN
    v_bound ELSE GREATEST(0, v_bound - 1) END, source.timestamp_ms))`. Reserving one millisecond
    of headroom for a range is what stops the clamped start from landing exactly on the bound and
    forcing an end of `bound + 1`, which the new trigger check would reject and which would roll
    back every other comment in the same carry batch.
  - end: NULL when `source.end_timestamp_ms` is NULL, otherwise
    `GREATEST(start + 1, LEAST(source.end_timestamp_ms, COALESCE(v_bound,
    source.end_timestamp_ms)))`. This is the D-07 guarantee: a span is clamped, never collapsed
    to a point and never silently dropped.
  - `needs_reposition`: `v_bound IS NOT NULL AND source.timestamp_ms > v_bound` — true exactly
    when the in-point itself no longer fits the new take.

Add `end_timestamp_ms` and `needs_reposition` to the INSERT column list and the derived values to
the SELECT. Restate the `REVOKE EXECUTE` / `GRANT EXECUTE` pair for
`(uuid, uuid, uuid[])` unchanged.

(6) `work_version_pins`. `CREATE TABLE public.work_version_pins` with `id UUID PRIMARY KEY
DEFAULT gen_random_uuid()`, `work_id UUID NOT NULL REFERENCES public.works(id) ON DELETE
CASCADE`, `version_id UUID NOT NULL REFERENCES public.work_versions(id) ON DELETE CASCADE`,
`author_user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE`, `timestamp_ms INTEGER
NOT NULL CHECK (timestamp_ms BETWEEN 0 AND 86400000)`, `created_at TIMESTAMPTZ NOT NULL DEFAULT
now()`. Index on `(author_user_id, version_id, timestamp_ms)`. `ENABLE ROW LEVEL SECURITY`. One
policy, `work_version_pins_author_only`, `FOR ALL TO authenticated`, whose `USING` and
`WITH CHECK` are each exactly `author_user_id = auth.uid()`. Then `REVOKE ALL ON TABLE
public.work_version_pins FROM PUBLIC, anon, authenticated;` followed by
`GRANT SELECT (id, work_id, version_id, author_user_id, timestamp_ms, created_at)`,
`GRANT INSERT (work_id, version_id, author_user_id, timestamp_ms)` and `GRANT DELETE` to
`authenticated` — no UPDATE grant of any kind. Add a `COMMENT ON TABLE` stating that a pin is a
private, wordless bookmark visible to its author alone, that it generates no notification and
rides no realtime channel, and that room membership is verified by the API route at insert time
rather than by a second policy here.

Finish the file with `NOTIFY pgrst, 'reload schema';`.
