## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous client → POST /api/sync/register | First unauthenticated write path in the buyer domain — no session, no staff gate |
| register route → buyer_orgs/buyer_members insert | Service-role write (migration 080 REVOKEs INSERT from anon/authenticated) |
| register route → lead-routing notification | Best-effort side effect that must never fail the signup |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-10 | Denial of Service | public register endpoint spam / email-bombing | high | mitigate | Rate-limit by IP/email (dm.ts pattern); best-effort email that no-ops when Resend absent |
| T-23-11 | Information Disclosure | account enumeration via duplicate-email response | high | mitigate | Duplicate returns the neutral success-shaped response (forgot-password discipline) |
| T-23-12 | Tampering | mass-assignment / arbitrary org columns | high | mitigate | buildRegisterPayload allowlist + explicit insert object; never spread request body |
| T-23-13 | Spoofing | forged qualifying data (fake company) | medium | accept | Inherent to public self-serve; AE-assisted onboarding (23-06) is the human vetting gate before status→active |
| T-23-14 | Repudiation | signup with no audit trail | low | mitigate | buyer_orgs row + lead_routed notification form the trail; staff actions on it are logged in 23-06 |
</threat_model>
