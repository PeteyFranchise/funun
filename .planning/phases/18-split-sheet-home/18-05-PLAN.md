<objective>
Stand up the identity foundation the redesigned living-draft surface (18-01) depends on: the schema, the pure live-identity resolver, and the one Settings gesture (confirm-and-lock the legal name) without which a first-time user's read-only party-1 row can never be populated and split-sheet creation is blocked for them entirely (deliberation §2, research Assumption A3).

This plan builds the plumbing, not the surface. It adds migration 066 (three additive columns plus the two status-confirmation triggers), the pure `resolvePartyIdentity()` module that 18-01 will call to live-link a claimed party's rights identity up to the mint freeze boundary (deliberation §1), and the Settings-side confirm-and-lock UI on the legal name. It ends at a human-gated database push — an executor agent must never run `supabase db push`, matching every migration checkpoint in this project's history.

Purpose: 18-01 rewrites the builder to auto-include the initiator as party 1 with a read-only legal name and live-linked rights fields, and to fast-add collaborators by email/phone alone. Neither is possible until the legal name can be locked, the live resolver exists, and `collaborators` can carry a legal name and a pending/confirmed status. This plan makes those true.
Output: migration 066 with a string-assertion test, a pure resolver module with tests, the `legal_name_locked_at` type + Settings lock UI + server-owned lock stamp, and a blocking human push checkpoint.

Known cross-phase follow-up (documented, NOT built here — research Assumption A4): the live-link promise holds up to `esign_pending`, but the actual freeze at mint time lives in `app/api/split-sheets/[id]/mint-envelope/route.ts` (Phase 17 territory, not in this replan's file scope). For the live-linked values to be captured into the PDF at signing, mint-envelope needs a small future addition to run this same resolver and write the resolved values into `split_sheet_parties` immediately before rendering. Recorded so the freeze-at-mint gap is a known follow-up, not a silent drop.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| claimed party → live-identity read | Resolving one Funūn user's private artist_profiles rights data for display on another user's sheet. |
| owner session → legal-name lock | A one-time, server-owned stamp on a private profile column that must not be client-valued or unlockable via mass-assignment. |
| unauthenticated token-holder → collaborators status write | A party with no account, acting through a public link, causes a write to the initiator's private roster row. |
| migration 066 → live production data | Additive schema and triggers over mid-approval split-sheet and roster rows. |
