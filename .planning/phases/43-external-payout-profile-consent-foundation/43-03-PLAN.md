# Plan 43-03: Payout Profile APIs and Settings UI

## Objective

Add Member-only management of external payment instructions and tax documents while keeping Stripe
Connect distinct and never round-tripping saved secrets.

## Work

1. Extend Settings > Payouts into Funūn payouts, External payment instructions, Tax documents, and
   Sharing history sections. Hide unavailable sections behind the migration/feature gate.
2. Add allowlisted APIs for create/replace/delete/list-masked. Require current Member auth plus the
   approved recent-auth/step-up proof for secret writes and tax-document operations.
3. Validate fields by approved country/rail. Normalize only where standards allow; never infer account
   ownership from format or account validation.
4. After save, discard raw browser state and return only masks, categories, timestamps, and explicit
   verification/change states. Never provide a “reveal saved number” endpoint.
5. On replacement, create a new version, notify the Member through summary-only channels, mark recently
   changed, and expose review state for Phase 43.1.
6. Add history entries for create/replace/delete/validation events using metadata only.

## Acceptance

- Browser/network inspection after save contains no full stored value.
- Another Member, workspace owner, staff without an approved support procedure, and ordinary service
  paths cannot read the payload.
- Stripe onboarding continues unchanged.
- Accessibility, cancel/clear, timeout, validation, retry, step-up expiry, and safe-error tests pass.
- Real-value enablement waits for the 43-02 human migration and key-service checkpoint.
