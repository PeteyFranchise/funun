## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (leadership) → /api/admin/staff | only a leadership session may create/list/modify staff; AE/BD are 403 |
| request body → account creation | email/display_name/staff_role pass an explicit allowlist + closed-enum validation before any write |
| GoTrue (auth.users) ↔ Postgres (funun_staff) | two systems, no shared transaction — app_metadata authoritative, funun_staff a display copy |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-05 | Elevation of Privilege | staff create/role-change routes | high | mitigate | requireStaff(['leadership']) first statement on every handler; only leadership creates/escalates staff (D-02) |
| T-25-06 | Elevation of Privilege | mass-assignment on staff PATCH | high | mitigate | sanitizeStaffPatch allowlist accepts only staff_role (closed enum) + active flag; a body sneaking is_admin/other fields is ignored |
| T-25-17 | Tampering | app_metadata / funun_staff drift | medium | mitigate | Role change dual-writes both in one handler; app_metadata is authoritative for the gate (Pitfall 1) |
| T-25-07 | Spoofing | weak/guessable invite link | low | mitigate | Reuses generateLink({ type:'magiclink' }) one-time Supabase mechanism already proven for buyer/industry invites |
| T-25-18 | Repudiation | unlogged staff action | high | mitigate | logStaffAction called exactly once per create/role-change; centralized helper (D-04) |
