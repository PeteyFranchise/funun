# Phase 31.1 Plan 03: Days-in-Stage + Coverage/By-AE Aggregation Summary

**Pure, jest-locked days-in-stage math against configurable pipeline stages (D-10) and coverage-strip/By-AE aggregation (D-31.1-04) for the leadership tower, with zero I/O.**

## Accomplishments
- `daysInStage()` computes whole days between `stage_entered_at` and now, returns `null` (never 0 or a fabricated value) when absent, and floors at 0 for a future timestamp (clock skew) — never negative.
- `resolveStage()` resolves a stage id against the leadership-configurable `pipeline_stages` set, returning `null` for an unknown id — no hardcoded stage list.
- `buildCoverageSummary()` produces the tower's coverage strip totals (clients, unassigned, active AEs, open pipeline value, at-risk count) as a pure transform over already-fetched rows.
- `groupByAe()` produces the By-AE coverage view — each assigned AE with their load (row count) and a health mix (count per `HealthState`), excluding unassigned rows from buckets while still counting them in the summary.

## Decisions Made
- `atRiskCount` counts only `at_risk`, not `cold` — matches the mockup's single "At risk" stat; `cold` remains visible via `groupByAe`'s health mix and the book table.
- Named the summary field `openPipelineValue` (not `openPipelineCents`) to match `ClientPartnerRow.openDealValue`'s existing raw-dollar unit convention (`ClientPartnersList.tsx`'s `formatMoney` renders it directly, no cents division).
- Added `assignedAeId` to `columns.ts` per this plan's own Task 2 action text ("add the optional ae id/name fields to ClientPartnerRow... add assignedAeId here") — `assignedAeName` (plan 02) is display-only and unsuitable as a grouping key (two AEs could share a name).
- Rows with a non-`HealthState` health value (`'unknown'`/absent) count toward `load` in `groupByAe` but not toward any `healthMix` bucket, keeping `healthMix`'s keys exactly the 5 `HealthState` values per the acceptance criteria.
