# Phase 31.1 Plan 07: Call Game Plan Summary

**Per-account call Game Plan (R14/D-31.1-06): a game_plans-backed GET/PUT/POST route plus a GamePlanPanel in the person workspace that checks off seeded/custom/Selects-context topics and logs "X of N covered" to the relationship log, own-book scoped throughout.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 2/2 completed
- **Files modified:** 7 (5 created, 2 modified)

## Accomplishments

- `lib/client-partners/game-plan.ts`: `GamePlanTopic` type, `SEEDED_GAME_PLAN_TOPICS` (5 default themes with open-ended questions), `buildDefaultGamePlanTopics()`, `coveredSummary()` ("X of N covered", 0-covered included), `buildGamePlanLogBody()` (summary + per-topic notes), zod `GamePlanTopicsSchema` (`.strict()`, mass-assignment backstop), `normalizeGamePlanTopics()`, and `loadGamePlan()` (the one shared DB read for both the route and the RSC page).
- `app/api/admin/client-partners/[orgId]/game-plan/route.ts`: GET (load-or-seed), PUT (upsert, one row per org), POST (log-conversation — appends a `kind='conversation'` relationship-log entry via the existing `appendRelationshipLog`, then retires the plan row so the next visit reseeds). Every handler runs `requireStaff()` then `canAccessOrgContacts` — an out-of-book AE gets 404, never 403, on all three verbs.
- `components/admin/GamePlanPanel.tsx` (`'use client'`): renders the topic list with questions, checkbox toggle, per-topic notes, remove, an "Add your own topic…" row, and a suggested-topics row (seeded defaults + Selects-context suggestions derived from the org's Selects names, explicitly NOT sourced from The Playbook). Save (PUT) and Log conversation (POST) both build plain-string fetch paths from the `orgId` data prop and refresh via `router.refresh()` — no function props cross the RSC boundary.
- Mounted in `ClientWorkspace.tsx`'s `mode="person"` branch (replacing the plan-06-left placeholder slot), fed `initialGamePlanTopics` from the person-workspace RSC page's new `loadGamePlan()` call and `selectsNames` derived from the existing `initialSelects` prop (no new prop threading needed for that half).

## Decisions Made

- **Retire-on-log:** POST log-conversation deletes the `game_plans` row after the relationship-log write commits (best-effort, non-blocking) so the AE's next visit starts from a fresh seeded set — matches D-31.1-06's "checked off on the call, then logged" one-shot lifecycle rather than a persistent running checklist.
- **No "from The Playbook" source labels:** the UI labels suggestions "Seeded default" or "From Selects" only, and carries an explicit note that dynamic Playbook/Plays sourcing is a later phase — upholds the plan's prohibition against implying live Playbook sourcing in 31.1.
- **`selectsNames` derived, not threaded as a new prop from the page:** `ClientWorkspace` already receives `initialSelects` (Selects[]); `GamePlanPanel` gets just the names (`initialSelects.map(s => s.name)`), avoiding a redundant new prop path from the RSC page for data ClientWorkspace already has.
