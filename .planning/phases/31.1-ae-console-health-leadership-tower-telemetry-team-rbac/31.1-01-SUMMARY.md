# Phase 31.1 Plan 01: Migration 128 — AE Console Health Data Model Summary

**Authored and shipped to prod the gating data-model dependency for the whole 31.1 phase: license_requests.executed_at (D-31.1-09 health clock), D-10 pipeline_stages, a seeded health_rules_config singleton, game_plans, and the D-07 onboarding_tasks queue — all zero-policy + REVOKE staff-only tables.**

## Performance

- **Duration:** ~25 min (including the human-gated `supabase db push` checkpoint)
- **Tasks:** 3 (2 automated + 1 blocking human-verify checkpoint)
- **Files modified:** 2 created

## Accomplishments
- `license_requests.executed_at` added as the single source of truth for the relationship-health color clock (D-31.1-09), deliberately distinct from `stage='closed_won'` and payment, forward-compatible with `lib/esign/provider.ts`'s vendor-agnostic `EsignState` contract
- `pipeline_stages` created and seeded with the five D-10 default stages (`new_lead`, `contacted`, `active`, `negotiating`, `closed_dormant`); `buyer_orgs` gains `pipeline_stage_id` + `stage_entered_at`
- `health_rules_config` created as a seeded singleton (id=1) holding threshold days, keeps-warm toggles, and `prospect_image_url` (D-31.1-03/08)
- `game_plans` created (one row per `buyer_org`, unique index) for the R14 per-account Call Game Plan
- `onboarding_tasks` created (net-new, NOT the jobs worker queue) for the D-07 auto-created handoff task, indexed by `(assignee_id, status)`
- Every new table is `ENABLE ROW LEVEL SECURITY` + zero `CREATE POLICY` + full `REVOKE` from `authenticated, anon`; migration ends with `NOTIFY pgrst, 'reload schema';`
- 15/15 jest assertions in `__tests__/migration-128.test.ts` text-lock the doctrine (table creation, RLS/REVOKE posture, zero policies, no grants on the three new private columns, D-10/singleton seeds, HUMAN-GATED footer, NOTIFY tail)
- Owner applied the migration to prod (project `wgfjakfiyeewzfuxkgyo`) via `supabase db push` and confirmed `supabase migration list` shows LOCAL=REMOTE through 128 with no errors
