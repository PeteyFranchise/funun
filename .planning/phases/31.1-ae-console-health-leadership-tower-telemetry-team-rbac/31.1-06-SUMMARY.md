# Phase 31.1 Plan 06: D-07 AE Assignment Handoff Summary

**The AE-assign route now fires the full D-07 structural handoff (required note, self-assign, auto-created onboarding task, best-effort intro email) behind a richer assign panel showing AE load + health mix.**

## Performance

- **Duration:** ~45 min
- **Tasks:** 2
- **Files modified:** 12 (5 created, 7 modified)

## Accomplishments

- `PATCH /api/admin/buyer-orgs/[id]/ae` is now the complete D-07 handoff: a required, trimmed handoff note when assigning (400 + no write if missing/blank); the target-role check widened to admit `leadership` (self-assign) alongside `ae`/`bd`, while the route itself stays `requireStaff(['leadership'])` so an AE can never self-assign; and, after the `ae_user_id` authority write commits, three independently `.catch()`-wrapped best-effort side effects: a `kind: 'assignment'` relationship-log entry, an auto-created `onboarding_tasks` row (seeded checklist + the handoff note) in the AE's queue, and a notification with a Resend intro-email copy.
- New `lib/client-partners/onboarding.ts`: `SEEDED_ONBOARDING_CHECKLIST` (four default handoff items), `insertOnboardingTask`, `listOpenOnboardingTasks`.
- `appendRelationshipLog` widened to accept `kind: 'assignment'` and an optional `meta` object.
- `AssignAePanel.tsx` — AE search, each AE's load + health-mix chips, and a required handoff-note textarea (Assign disabled until both an AE is chosen and the note is non-empty); PATCHes the route directly and `router.refresh()`s.
- `OnboardingTasksPanel.tsx` — read-only render of the signed-in staff member's open handoff tasks (title, quoted handoff note, checklist) on their My tab.
- Both wired into `ClientPartnersRoom.tsx`: the assign panel opens from the "Needs an AE" queue cards and the book table's row action; the onboarding panel renders on My for every role (not leadership-only).

## Decisions Made

- A handoff note is required only when assigning (`ae_user_id` non-null), not when unassigning — matches D-31.1-05's "every handoff carries context" framing (a handoff happens when a client lands with someone, not when they're taken away).
- The assignable AE roster shown in `AssignAePanel` is built from `funun_staff` (filtered to `ae`/`bd`/`leadership` roles) merged with `groupByAe`'s load/health-mix output, rather than from `groupByAe` alone — `groupByAe` only buckets rows that already have an assigned AE, so a brand-new or currently-unloaded AE would otherwise never appear as a selectable target.
- The intro email's recipient address is resolved from the SAME `service.auth.admin.getUserById(aeUserId)` call already used for the target-role check, avoiding a second Auth Admin API round trip.
