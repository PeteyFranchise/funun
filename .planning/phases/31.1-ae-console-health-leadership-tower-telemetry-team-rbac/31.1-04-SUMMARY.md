# Phase 31.1 Plan 04: Consolidated Client Partners Room Summary

**Consolidated My/All Client Partners room with live compute-on-read health (executed-license clock), server-side leadership gating (hide-not-filter, machine-verified), and a single collapsed nav item.**

## Performance

- **Duration:** ~45 min
- **Tasks:** 3
- **Files modified:** 18 (7 created, 11 modified)

## Accomplishments

- `lib/client-partners/signals.ts` — the I/O layer assembling `ClientPartnerRow[]` for both the My tab (own-book) and the leadership-only All tab (whole-book + coverage), wiring `computeHealth()`/`daysInStage()`/`resolveStage()` to real, batched Supabase reads (deals, briefs, Selects, contacts, relationship log, staff names) — no N+1 queries.
- `lib/deals/executed.ts` + `POST /api/admin/deals/[id]/executed` — the D-31.1-09 explicit executed/signed-license stamping action: idempotent (`WHERE executed_at IS NULL`), race-safe, and structurally distinct from the `closed_won` stage transition.
- `app/api/admin/buyer-orgs/[id]/route.ts` extended to accept `pipeline_stage_id` (D-10), stamping `stage_entered_at` only on an actual stage change.
- One consolidated `/admin/client-partners` room: RSC page (`page.tsx`) computes `allData` only inside the `isLeadership` branch and passes `null` otherwise; `ClientPartnersRoom` (client wrapper) renders the My/All tab toggle (All hidden entirely for non-leadership), the coverage strip, the pinned "Needs an AE" queue, the By-AE grouping, and a scoped create-org panel folded in from the retired buyer-orgs page.
- `ClientPartnersList` gained real health-color rendering (replacing plan 02's Rule-3 placeholder stub), an Assigned-AE column render, and a data/string-only row-action slot (`rowActionLabel`) for plan 06 to wire.
- Nav collapsed from two entries (leadership-only "Client Partners" + all-staff "My Client Partners") to one `notIt`-gated "Client Partners" item, plus a new leadership-only "Health Rules" entry (page ships plan 05).
- D-31.1-01's hide-not-filter contract is machine-verified: `lib/admin/gate.test.ts` proves `loadWholeBookWithCoverage` is never invoked for an `ae`/`bd` caller and `allData` is populated only for `leadership`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Regression: buyer-orgs PATCH added an unconditional org-row read for every caller**

- **Found during:** Task 2/3 full-suite regression run (after Task 1's `pipeline_stage_id` support landed)
- **Issue:** Task 1's initial implementation always fetched the current `buyer_orgs` row (needed for the `pipeline_stage_id` current-value comparison) regardless of role, breaking `__tests__/staff-buyer-orgs-api.test.ts`'s existing invariant that a leadership caller editing `name`/`status`/`use_case` alone makes zero extra reads.
- **Fix:** The read is now conditional — only fetched when the caller is non-leadership (scope check) OR the request body includes `pipeline_stage_id` (needs the current value for the `stage_entered_at` stamp decision).
- **Files modified:** `app/api/admin/buyer-orgs/[id]/route.ts`
- **Verification:** Full repo suite green (241 suites / 2598 tests), `__tests__/staff-buyer-orgs-api.test.ts` passing again.
- **Committed in:** `66d86cb` (Task 2 commit — the fix landed alongside Task 2's other changes since it was discovered while validating Task 2)

**2. [Rule 2 - Missing Critical] Real health-color rendering in ClientPartnersList**

- **Found during:** Task 2 (per the plan's explicit note that plan 02 left a Rule-3 placeholder stub here)
- **Issue:** `HealthChip` rendered a local, hardcoded `HEALTH_TONE` map with placeholder colors for `cold`/`prospect` — never wired to the real 6-state health vocabulary's render-mode semantics (`columns.ts`'s `HEALTH_TONE`), and `'prospect'` was rendered as a color dot rather than the D-31.1-08 image-marker slot.
- **Fix:** Replaced with `HEALTH_COLOR` (4 real bands) + a branch reading `columns.ts`'s `HEALTH_TONE` to route `'prospect'` to a distinct (non-color) marker render, matching D-31.1-02/08's documented contract.
- **Files modified:** `components/admin/ClientPartnersList.tsx`
- **Verification:** `npx tsc --noEmit` clean; full suite green.
- **Committed in:** `66d86cb`

**3. [Rule 2 - Missing Critical] Create Client Partner action folded into the All tab**

- **Found during:** Task 2 (plan explicitly calls for keeping this reachable)
- **Issue:** Retiring `/admin/buyer-orgs` would otherwise remove the only UI path to create a new Client Partner org.
- **Fix:** Added a small, scoped `CreateClientPartnerPanel` inside `ClientPartnersRoom`'s All tab, reusing the existing `POST /api/admin/buyer-orgs` route (not the full `BuyerOrgsAdmin` member-management/reassign UI, which is superseded by `ClientPartnersList`'s Assigned-AE column + the plan 06 assign panel).
- **Files modified:** `components/admin/ClientPartnersRoom.tsx`
- **Verification:** `npx tsc --noEmit` clean.
- **Committed in:** `66d86cb`
