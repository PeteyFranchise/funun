## Decisions (locked this session)

- **D-31.1-01 — One consolidated "Client Partners" room, tabbed.** A single nav item. Inside: **My Client Partners** (your own assigned book — every staff member, incl. leadership) and **All Client Partners** (the whole-book tower). **AEs see ONLY the My tab** — the All tab + tower data are leadership-only and hidden entirely for non-leadership (not merely filtered). Enforced server-side (canManage-style) AND in the UI. Replaces today's separate "Client Partners" (`/admin/buyer-orgs`) + "My Client Partners" items.
- **D-31.1-02 — Health COLOR = last actual LICENSE recency (are they still buying), NOT contact recency.** Five states: 🟢 Good (licensed within ~90d) · 🟡 Warning (~120d) · 🔴 At-risk (~180d — actively slipping) · 🔵 **Cold** (~365d+ — licensed once but long gone quiet; may have drifted or had a bad experience — distinct from red) · 🦁 **Prospect** (never licensed — shown as a **symbol/lion mark, not a color**; off the buying-recency axis until their first deal). **Last contact and days-in-stage are tracked + shown as columns (and power the relationship log) but do NOT set the color. Last contact is ALSO surfaced on the client card / detail (the drill-in workspace) — a clear "last contacted X ago" so the AE always knows when they last reached out.** Computed **live on read** (D-06). Selects *engagement depth* is a 31.2 signal. All thresholds leadership-configurable.
- **D-31.1-03 — Health rules = a leadership-only settings surface** (R4): tunable **Last-license** thresholds (Good/Warning/At-risk/Cold, in days) + "keeps-warm" toggles that hold health up despite no recent license (open brief/Crate request · open deal · recent Selects sent · optional recent contact — so an actively-worked lead never reads at-risk). Last-contact + time-in-stage shown as tracked columns, not color drivers. Live preview of the state split; saves apply immediately (nothing to recompute, per D-06). Mirrors the D-10 "one place to adjust as we grow" config pattern.
- **D-31.1-08 — Prospect mark = a lion** (never-licensed clients). The prospect slot renders an **owner-supplied, leadership-configurable image asset — swappable anytime with NO code change**, uploaded/replaced from inside the **Health Rules** screen (reuse the staff avatar-upload pattern: image → storage → config value; applies live). Owner has elected the Detroit Lions logo for now (owner-provided file, owner's decision + IP risk — flagged; replaceable later). Mockup + built component ship a neutral placeholder in that slot and the owner supplies the asset; Claude does not recreate/embed the trademarked logo.
- **D-31.1-09 — Last-license moment = the EXECUTED / SIGNED license (owner-decided 2026-08-23).** The health-color clock = the date the client's license agreement was **signed / executed** (e-sign completion) — **NOT** deal-stage `closed_won`, **NOT** payment-received. Planner must locate the executed-license timestamp on the buyer / sync side (an executed-document / e-sign completion event tied to `license_requests` or the buyer org) and, if no per-deal `executed_at` / `signed_at` is captured today, **add it as this phase's gating dependency** (stamp it when a license is marked executed / signed). Note the buyer→artist signing model is partly counsel-gated (upload-only e-sign for now) — design the timestamp capture forward-compatible with the Dropbox Sign provider interface. The same executed-license source powers the **"lifetime value"** (sum of executed licenses) and **"open deal"** (in-flight, not-yet-executed) columns.
- **D-31.1-04 — All Client Partners tower:** a coverage strip (clients · unassigned · AEs · open pipeline · at-risk); a pinned **"Needs an AE"** queue (unassigned) + inline highlight; the flat book table (Company · Assigned AE · Health · Stage·days · Open briefs · Active Selects · Open deal · Lifetime · Last touch); a **By-AE coverage** view (grouped by owner, each with load + health mix). Reuses the Slice-1 `ClientPartnersList`.
- **D-31.1-05 — Assignment (R6/R7) via a richer assign panel:** AE search + each AE's load + their book's health mix, and a **REQUIRED handoff note** (Assign is disabled until it's filled — every handoff carries context). Assigning fires the locked **D-07** structural handoff (intro email + auto-created onboarding task in the AE's queue). A leader can assign a client to themselves → it lands in their own My tab. Reassign from the row ⋯.
- **D-31.1-06 — Call Game Plan (R14) = a saved per-account prep doc:** topics (themes) each carrying open-ended questions, checked off on the call, then "Log conversation" writes "X of N covered" + notes to the relationship log. In 31.1, suggested topics are **seeded defaults + custom + Selects context**; dynamic Playbook/Plays sourcing is 31.2.
- **D-31.1-07 — Sidebar layout approved** (SALES: My Client Partners, Crate Requests, Selects, Deals, Sync Library, GTM Metrics · OPS: Verification, Reports, The Playbook, Team). Exact room names may be adjusted later.
