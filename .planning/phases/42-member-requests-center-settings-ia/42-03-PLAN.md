# Plan 42-03: Dashboard, navigation, and notifications

## Objective

Make pending decisions discoverable where Members actually look without copying request state or placing
sensitive contents in global surfaces.

## Tasks

1. Add Requests to the artist navigation with an accessible pending count sourced from 42-01. Define
   mobile/narrow behavior and do not poll independently per card.
2. Extend Dashboard **Your next moves** with request summaries. Preserve the existing principle that
   “waiting on you” is cross-account and independent of ownership.
3. Add best-effort summary notifications when a permission request or rights-information update is
   created; retarget master-claim notification links from Settings to the filtered Requests detail.
4. Use neutral notification copy with actor/workspace context but no proposed values, legal names,
   identifiers, evidence contents, or paths.
5. Test unread/read behavior, deep links, count refresh after a decision, notification failure not
   rolling back the authoritative request, and cross-account isolation.

## Acceptance

- Requests, Dashboard, and notification links converge on one source record.
- A decision removes or updates every count on the next authoritative render.
- Notification creation is best-effort and cannot corrupt request creation.
- Search-based tests prove forbidden fields cannot enter notification payloads.
- Focused tests and strict typecheck pass.
