<objective>
Ship the server write-paths that make layered tagging real WITH the owner's approval workflow: an AI tag-suggest route (staff-triggered, provenance-preserving), a tag-propose route (AE proposals land pending; leadership/A&R proposals auto-confirm), and a tag-approve route (leadership/A&R confirm or reject a pending proposal). Artist confirm already exists via MetadataStudio's descriptor fields; this plan adds the AI + staff-proposal + approval layers.

Purpose: Tagging drives Crate filters, search, and brief-matching. Per the 2026-08-13 owner decision, AEs can help tag but their changes are proposals that a leadership/A&R approver confirms — so catalogue tag quality stays governed while distributing the work.
Output: new `app/api/sync-library/tag-suggest/route.ts`, `app/api/sync-library/tag-propose/route.ts`, `app/api/sync-library/tag-approve/route.ts`.
</objective>

## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| artist text → AI prompt | Untrusted artist lyrics/notes feed the model (prompt injection surface). |
| staff client → descriptors write | Only staff may write AI/proposed/confirmed tags; target must be server-loaded. |
| AE proposer → confirmed tags | An AE must never confirm tags; only leadership/A&R approve. |
