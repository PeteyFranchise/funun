# Phase 38.0.1 Plan 10: Column-Allowlist RPCs Summary

**Migration 193 deletes the workspace RLS branch from `tracks`, `vault_assets`, `vault_documents` and `tool_outputs` outright and replaces it with four SECURITY DEFINER read functions whose declared `RETURNS TABLE` clauses are the security contract — leaving `vault_projects` as the only table in the schema whose policies name a workspace helper, and putting no storage path, signed URL, raw document payload or lyric body within reach of any workspace grant. Authored and text-tested only; held for plan 11's joint push with 191, 192 and 194.**

## Accomplishments

- **Section (a) — eight child-table policies recreated without the workspace disjunct.** Each of `tracks_select_project_owner_or_member`, `tracks_write_project_owner_or_editor`, `vault_assets_select_project_owner_or_member`, `vault_assets_write_project_owner_or_editor`, `vault_documents_select_project_owner_or_member`, `vault_documents_write_project_owner_or_editor`, `tool_outputs_select_project_owner_or_member` and `tool_outputs_write_project_owner_or_editor` differs from migration 186's version by exactly one removed disjunct. Migration 078's `is_project_owner` and `project_member_role` clauses, and the two nullable tables' `project_id IS NULL AND user_id = (SELECT auth.uid())` fallback, are restored byte-for-byte. F3 is closed by removal: a workspace caller now has **no write path of any kind** to these four tables.
- **Section (b) — both `vault_projects` policies preserved verbatim**, keeping their `view_summaries` and `edit_metadata` branches. A comment above the UPDATE policy states that custody immutability under that branch is migration 190's `BEFORE UPDATE` trigger, not this policy, because a `WITH CHECK` clause sees only the proposed row and cannot compare it against the stored one.
- **Section (c) — four column-allowlist read functions**, each `LANGUAGE sql STABLE SECURITY DEFINER` with `SET search_path = ''`, an explicit `RETURNS TABLE` list, a single qualified `SELECT` of exactly those columns from exactly one table, a `WHERE project_id = p_project_id AND public.workspace_project_permission(p_project_id, p_uid, 'view_summaries')` gate, a `REVOKE EXECUTE ... FROM PUBLIC, anon` / `GRANT EXECUTE ... TO authenticated` pair, and a `COMMENT ON FUNCTION` telling the next reader the return list is the contract.
- **`__tests__/migration-193.test.ts` — 60 passing assertions.** Ten-policy inventory matched by name against migration 186's set; per-policy slices for all eight child policies (helper absent) and both `vault_projects` policies (helper present, with its exact occurrence count); original-clause survival per policy including fallback counts; per-function declaration, gate, single-table read, REVOKE/GRANT pair and COMMENT; each return column list sliced and asserted **verbatim** plus scanned against a twelve-name forbidden list; whole-file guards (no `SELECT *`, no CREATE TABLE/ADD COLUMN/INSERT/DELETE/DROP, no legacy account field, no bare `USING (true)`, ends with the PostgREST reload).
- **`__tests__/workspace-structural-exclusions.test.ts` extended** with a `no storage or signing module calls a workspace column-allowlist read function` block: it walks `lib/` and `app/api`, collects every module that calls `createSignedUrl`, imports `@/lib/storage`, `@/lib/catalogue/audio` or `@/lib/watermark/signed-url`, or reaches `.storage.from(`, and asserts none of them names any of the four read functions. ## Decisions Made

See `key-decisions` in the frontmatter. The two most consequential:

1. **The "exactly 6" grep criterion is mis-specified — the correct count is 8, and the code was not contorted to meet it.** The criterion undercounts the `FOR UPDATE` policy's `WITH CHECK` restatement (migration 186 and 078 both write the predicate twice there, and preserving that is the whole point of "differs by exactly one removed disjunct"), and it acknowledges its own incompleteness with "plus any conditional-column occurrences". Composition: **3** in the two `vault_projects` policies + **4** `view_summaries` gates, one per read function + **1** `view_private_rights_identifiers` gate on the track ISRC = **8**. The test asserts the decomposition term by term (`{ total: 8, inPolicies: 3, inFunctions: 5 }`) plus a per-policy slice count, which is strictly stronger evidence than any single total.
2. **The forbidden set was widened beyond the columns the plan named.** The plan named `audio_file_url`, `audio_file_size`, `lyrics`, `url`, `document_data`, `inputs`, `output`. `vault_documents.file_url` (migrations 011/023) is a second storage path on the same table, `esign_completion_claim_token` (migration 172) is a capability rather than a fact, and `tracks.metadata` is a free-form blob that can restate withheld material — all three are excluded and asserted forbidden in the test, alongside every `user_id`.
