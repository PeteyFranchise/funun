### `lib/workspaces/consent.ts` (NEW — pure service module)

**Analog:** `lib/workspaces/evidence.ts` (full file read, 100 lines)

**Module header convention** (lines 1-24 of evidence.ts):
```typescript

// Compute-on-read agreement evidence ladder and authority tier (D-16, D-36,
// D-37, D-39). Pure, zero-I/O module -- no Supabase client, no side
// effects (style precedent: lib/client-partners/health.ts's compute-on-read
// resolver with an injectable clock).
```
Copy this header shape: cite the doctrine decisions being enforced, declare "pure, zero-I/O,"
cite the injectable-clock precedent if `consent.ts` needs `now`.

**Core pattern — fail-closed boolean/tagged-union, no I/O** (evidence.ts lines 39-53, 67-78):
```typescript
function isLiveQualifyingEvidence(row: AgreementEvidenceFacts, now: number): boolean {
  if (!row.declaredScope || row.declaredScope.trim().length === 0) return false
  if (row.expiresAt && new Date(row.expiresAt).getTime() <= now) return false
  if (row.supersededAt && new Date(row.supersededAt).getTime() <= now) return false
  return true
}

export function resolveAuthorityTier(args: {
  relationshipState: RosterRelationshipState
  evidence: readonly AgreementEvidenceFacts[]
  now?: number
}): WorkspaceAuthorityTier {
  if (args.relationshipState !== 'accepted') return 'none'
  const now = args.now ?? Date.now()
  const hasQualifyingEvidence = args.evidence.some((row) => isLiveQualifyingEvidence(row, now))
  return hasQualifyingEvidence ? 'authority' : 'operational'
}
```
`consent.ts`'s equivalent function (per RESEARCH Pattern 1, item 1) takes already-fetched facts
(the requested permission set, D-42 exclusion check, D-16 authority-tier/document-support check)
and returns a tagged union — model this on `grants.ts`'s `GrantIssuanceResult` shape (see below),
NOT a bare boolean, since the caller needs the refusal reason.

**Tagged-union return + never-throw convention** — copy from `lib/workspaces/grants.ts` lines 67-129
(`GrantIssuanceResult`, `assertGrantIsIssuable`): ordered checks (unknown value → structural
exclusion → authority tier → subset), each returning `{ ok: false, reason: string }` with a
specific, named reason. `consent.ts`'s Member-side function skips the "subset of what granter
holds" check entirely (the Member IS the root — RESEARCH explicitly: "does not call
resolveEffectivePermissions at all") but keeps the unknown-value, structural-exclusion, and
authority-tier-requires-document checks verbatim in spirit.

### `lib/workspaces/ownership-transfer.ts` (NEW — two-sided state machine)

**Analog:** `lib/workspaces/custody-transfer.ts` in full (215 lines; header comment + state machine

export const CUSTODY_TRANSFER_STATE_VALUES = ['offered', 'accepted', 'declined', 'withdrawn'] as const
export type CustodyTransferState = (typeof CUSTODY_TRANSFER_STATE_VALUES)[number]

export const TRANSFER_LEGAL_EDGES: Record<CustodyTransferState, ReadonlySet<CustodyTransferState>> = {
  offered: new Set<CustodyTransferState>(['accepted', 'declined', 'withdrawn']),
  accepted: new Set<CustodyTransferState>(),
  declined: new Set<CustodyTransferState>(),
  withdrawn: new Set<CustodyTransferState>(),
}

export function isLegalTransferTransition(from: CustodyTransferState, to: CustodyTransferState): boolean {

  if (from === to) return false
  return TRANSFER_LEGAL_EDGES[from].has(to)
}

### `supabase/migrations/188_vault_projects_user_id_immutable.sql` (NEW)

**Analog:** `supabase/migrations/182_workspaces_foundation.sql`'s `guard_workspace_never_zero_owners`
(full function + trigger captured above, lines 345-381) — closest in-repo BEFORE-trigger-that-
rejects-a-mutation precedent (RESEARCH explicitly names this as the shape to copy).

```sql
CREATE OR REPLACE FUNCTION public.guard_workspace_never_zero_owners()
RETURNS TRIGGER
LANGUAGE plpgsql SECURITY DEFINER
SET search_path = ''
AS $$
DECLARE
  v_remaining_owners INT;
BEGIN
  IF (TG_OP = 'DELETE' AND OLD.role = 'owner' AND OLD.status = 'active')
     OR (TG_OP = 'UPDATE' AND OLD.role = 'owner' AND OLD.status = 'active'
         AND (NEW.role <> 'owner' OR NEW.status <> 'active')) THEN
    ...
    IF v_remaining_owners = 0 THEN
      RAISE EXCEPTION 'A workspace must always have at least one active owner.'
        USING ERRCODE = 'insufficient_privilege';
    END IF;
  END IF;
  RETURN COALESCE(NEW, OLD);
END;
$$;

REVOKE EXECUTE ON FUNCTION public.guard_workspace_never_zero_owners() FROM PUBLIC, anon, authenticated;

DROP TRIGGER IF EXISTS guard_workspace_never_zero_owners ON public.workspace_members;
CREATE TRIGGER guard_workspace_never_zero_owners
  BEFORE DELETE OR UPDATE ON public.workspace_members
  FOR EACH ROW EXECUTE FUNCTION public.guard_workspace_never_zero_owners();
```
Copy verbatim: `SECURITY DEFINER`, `SET search_path = ''`, `RAISE EXCEPTION ... USING ERRCODE`,
`REVOKE EXECUTE ... FROM PUBLIC, anon, authenticated` (trigger-internal-only posture), `DROP
TRIGGER IF EXISTS` + `CREATE TRIGGER ... BEFORE ... FOR EACH ROW`. RESEARCH's own worked example
(`guard_vault_projects_user_id_immutable`, Pattern 5) is the specific body to write — the structural
scaffolding above is what must match 182's convention exactly, including the `current_user IN

role-based `TG_OP`/status branching style.

**Migration header convention to copy:** every migration header in this repo (078, 182, 186, 187 all
confirmed) states HUMAN-GATED status, cites the standing "no agent runs `supabase db push`"
convention by naming the prior migrations that established it, and states migration numbering
provenance explicitly. Copy migration 187's header shape (captured above, lines 1-46) almost

**Verify-before-authoring note (carried from RESEARCH):** confirm `current_user` actually reads

## Shared Patterns

### Pure/I/O module split (`lib/workspaces/*.ts` house convention)
**Source:** every existing pair in `lib/workspaces/` (`grants.ts`/`grant-service.ts`,
`roster.ts`/`roster-service.ts`, `evidence.ts` standalone pure) — confirmed by reading `grants.ts`

`audit-redaction.ts` (pure, paired with existing `audit.ts` for I/O).
```typescript
// Pure module: no SupabaseClient import, ReadonlySet/plain-object args, tagged-union or
// boolean return, exhaustive doc comment ending "Never throws."
// I/O module: imports SupabaseClient, imports the pure module's functions, does the
// fetch/compose/return sequence with "if (error) return EMPTY/false" at every step.
```

### Never-cache / re-derive-on-every-call doctrine
**Source:** `lib/workspaces/grant-service.ts` header comment (2), lines 26-33 (captured above).
**Apply to:** `grant-lineage-service.ts`, the rewritten `catalogue.ts`, and any new resolver this
phase adds. Explicitly forbidden: module-level cache, request-scoped memo. This is a repeated,
load-bearing doctrine statement — copy the comment itself, not just the behavior, so the next
reader sees the same warning.

**Source:** `lib/workspaces/access.ts`'s `requireWorkspaceAccess` (captured above, lines 62-110).

identity/null check, then role/membership check, DB-error → 500 (never a permissive fallthrough).

`186_workspace_rls_extension.sql` lines 1-60 (both captured above).
