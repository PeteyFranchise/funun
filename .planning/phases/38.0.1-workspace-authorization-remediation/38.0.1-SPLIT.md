# Phase 38.0.1 — Split assessment and recommendation

> Requested explicitly by the planning brief: "Assess the split explicitly and say so in your
> return." This document is the durable record; the return message summarises it.

## Recommendation

**Split into two sub-phases.** Plan and execute **38.0.1** now as slices **A + B + E + WSR-27**;
open **38.0.2** for slices **C + D**.

This matches RESEARCH's own recommendation, with two deliberate deviations, both argued below:
WSR-24 is pulled forward into 38.0.1, and WSR-27 stays in 38.0.1 rather than moving to the second
sub-phase.

## Why a split at all

Planning the full A-E scope at the fidelity this phase requires produces **21-23 plans**. Phase 38
itself — a green-field build of D-01..D-56 — needed 13. This phase must both (a) solve two genuinely
novel design problems that did not exist as known quantities when Phase 38 was planned (R-01's
consent bootstrap, R-02/R-04's RLS rework) and (b) retrofit six transactional RPCs, a redaction
layer, a cohort gate and nine smaller fixes on top of the reworked foundation.

The constraint is **context cost**, not difficulty. Nothing in slices C or D is hard; there is
simply more of it than fits at full fidelity beside a security-critical RLS rework that needs to
soak. No feature has been judged too difficult, and none has been thinned.

## The dependency boundary

R-06's transactional RPCs (slice C) call **into** the authorization surface slices A and B produce.
`accept_custody_transfer`, `redeem_invitation` and the roster-transition RPC all revalidate
preconditions against grant and relationship state that migrations 191-192 restructure. Building C
before A/B lands means building its authorization calls twice.

E (migration 190) is independent of everything and ships first, alone, with its own review.

### Deviation 1 — WSR-24 pulled forward (RESEARCH placed it in slice D)

Migration 186's helper joins the roster relationship with
`(a.relationship_id IS NULL OR r.id = a.relationship_id)`. When an attachment's `relationship_id`
is NULL that clause matches **any** accepted relationship in the workspace. Migration 192 then binds
custody with `p.user_id = r.member_user_id` — against whichever relationship happened to join. A
nullable `relationship_id` therefore **defeats WSR-06's custody binding directly**. R-16 is
load-bearing for slice B, not hygiene, so it lands with it.

### Deviation 2 — WSR-27 kept in 38.0.1 (RESEARCH moved it to the second sub-phase)

R-18 is a locked owner decision that the consent surface ships in this phase. Beyond honouring it,
there is a verification argument: **WSR-27 is how WSR-01 gets verified.** VALIDATION.md's map lists
WSR-27's verification as conversational UAT, and there is no other way for the owner to exercise the
Member-root consent model this phase's central fix depends on. Without the surface, 38.0.1 ships an
unverifiable authority model. RESEARCH's objection — that the UI needs the endpoint to be stable,
not mid-rework — is handled by sequencing: the UI plans are waves 5 and 6, after the endpoint,
the migrations and the joint push have all landed.

## The binding condition on the whole deferral argument

**Every one of the thirteen deferrals is safe only while the D-56 kill switch stays OFF in
production.** That is not an assumption bolted on here — it is R-03 (flip it off now) plus R-07 (the
cohort gate is a release requirement before it goes back on), both already locked.

This phase enforces the condition in three places:
- Plan 01, probe P5 verifies the switch is off before any work begins, and says STOP if it is not.
- Plan 11's push checkpoint requires re-confirming it is off before and after the migration push.
- Plan 13's human-check for the consent UI requires the owner to flip it on **in a controlled
  window**, verify, and flip it back off — which also discharges smoke-checklist items 8a/8b, the
  D-56 disable drill that has been outstanding since Phase 38.

**If the switch is turned on before Phase 38.0.2 ships, the deferrals stop being safe.** That
sentence is the single most important line in this document.

## If the owner rejects the split

The alternative is one phase of 21-23 plans across roughly nine waves. It is defensible — a single
adversarial review commissioned all nineteen findings, and splitting costs some narrative coherence
across two verification passes. The planner's recommendation is still the split, because the RLS
rework should soak on its own before six transactional RPCs are built on top of it, which is the
same boundary Phase 38 itself used.
