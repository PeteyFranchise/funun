<objective>
Two things land here: R-10 / WSR-20's set-based paginated reader, and the phase's single joint push.

**The verified defect (F18).** `lib/workspaces/catalogue.ts`'s `loadWorkspaceCatalogue` calls
`resolveEffectivePermissions` once per project inside a `for` loop, and that function itself performs
up to four sequential Supabase queries. For a hundred attached projects that is four hundred round
trips in one HTTP request.

**Why the fix is not a cache.** `grant-service.ts`'s own header states, deliberately, that nothing is
cached — a memoised permission set silently reintroduces exactly the staleness D-49 exists to
prevent. R-10 restates the ban. The fix is to fold the already-correct computation into ONE query
per page, so there is nothing to cache in the first place. The query still runs fresh on every call.

Purpose: performance without staleness, plus the coordinated release that makes migrations 191-192
and their TypeScript take effect together.

Output: migration 194, a rewritten catalogue reader, and a completed adversarial smoke pass.
</objective>
