## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Comment-string semicolons broke the standard comment-extraction regex**
- **Found during:** Task 2 (writing the text-lock suite)
- **Issue:** The initial `workspace_project_permission` `COMMENT ON FUNCTION ... IS '...'` string used semicolons between hop descriptions. The repo-standard `functionBlock`/comment-extraction regex (`[^;]*` after `IS`) — used identically by `migration-186.test.ts` and this suite — stops at the FIRST semicolon, which was inside the string body rather than at the statement's actual terminator, truncating the captured comment and failing three assertions that check for `hop 5`/`hop 6`/etc.
- **Fix:** Replaced the semicolons inside the comment string with commas (and one em-dash separator), matching migration 186's own comment style, which never uses semicolons inside its `COMMENT ON FUNCTION` string bodies for exactly this reason.
- **Files modified:** `supabase/migrations/192_workspace_project_permission_v2.sql`
- **Verification:** `npx jest __tests__/migration-192.test.ts` — 34/34 passing after the fix.
