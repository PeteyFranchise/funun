<objective>
Close R-08 / WSR-14 and WSR-15 at the HTTP layer, and build the shared date-validation module the
rest of the workspace surface will adopt.

**The verified defects (F8).** `app/api/workspaces/[workspaceId]/roster/evidence/route.ts` makes
`documentId` optional, is gated only by `canManageRoster` (owner or admin), and inserts a row that
becomes live authority-tier evidence the instant the resolver next runs — there is no proposal state
anywhere. It also accepts `effectiveFrom` and `expiresAt` as bare `z.string().optional()`, so a
malformed value is stored and then compared with `new Date(x).getTime()`, which yields `NaN` and
silently reads as "no constraint".

Purpose: D-36 says the rights holder declares the scope. The workspace may draft; only the subject
confirms. Plan 04 made the ladder gate on confirmation; this plan builds the surface that produces
the confirmation and hardens the surface that produces the draft.

Output: `lib/workspaces/date-schemas.ts`, a modified workspace-side evidence route, and a new
Member-side evidence confirmation route.
</objective>

    Create `lib/workspaces/date-schemas.ts` as a pure module exporting Zod schemas and one ordering
    helper. Named exports, no semicolons, 2-space indent.

    Header comment: state that this module exists because a bare `z.string()` date field is stored
    and then compared with a date constructor, and a malformed value parses to `NaN`, which compares
    false against every bound and therefore reads as "no constraint" — the exact failure mode R-14 /
    WSR-22 names. State that the calendar-validity check matters as much as the format check: a
    well-formed impossible date would otherwise pass a regex and then normalise silently.

    Export `isoDateSchema` — a Zod string schema that requires the `YYYY-MM-DD` shape AND refines on
    calendar validity by round-tripping through a date constructor and comparing the formatted
    result back to the input, so an impossible day is refused rather than rolled over.

    Export `isoDateTimeSchema` — a Zod string schema for a full ISO-8601 datetime, refined the same
    way, and explicitly rejecting a bare `YYYY-MM-DD`.

    Export `optionalIsoDate` and `optionalIsoDateTime` as the nullable/optional wrappers the routes
    actually use, so a call site never has to compose `.optional().nullable()` by hand and get the
    order wrong.

    Export `assertDateOrdering(args: { start: string | null | undefined; end: string | null |
    undefined; startLabel: string; endLabel: string }): { ok: true } | { ok: false; error: string }`.
    Return ok when either side is absent. Refuse when the parsed end is at or before the parsed
    start, with a message naming both labels. Refuse when either parses to NaN, rather than
    treating an unparseable value as absent.

    Write `lib/workspaces/date-schemas.test.ts` covering every behavior bullet, including the
    impossible-calendar-date case and the NaN case in `assertDateOrdering`.
