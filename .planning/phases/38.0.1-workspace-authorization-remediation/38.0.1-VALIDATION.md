## The gap that defines this phase's risk

**This repo's migration tests are TEXT-LOCK, not live-execution.** They assert the SQL string
matches what was authored. They cannot prove a trigger fires, a policy denies, or a helper avoids
recursion. Phase 38 shipped with 4788 green tests and a critical custody-takeover path.

Three requirements here are **behavioral claims about live Postgres** that no Jest test can settle:

- **WSR-25** — does the `BEFORE UPDATE` trigger actually block a `user_id` change, for owner,
  co-owner/editor AND workspace callers?
- **WSR-06** — does the custody binding actually deny a workspace whose relationship member is no
  longer the custodian?
- **WSR-03/04** — does a workspace caller genuinely receive no `audio_file_url` through the new RPC?

Research found **no live-DB test harness anywhere in this repo**. Planning must decide explicitly:
build one, or specify a written owner-run verification per item. **Do not let text-lock green be
mistaken for proof** — that is precisely the failure this phase exists to remediate.

## Sampling Rate

- **Per task commit:** `npx jest <changed-module>` + `npx tsc --noEmit`
- **Per wave merge:** full `npm test`
- **Phase gate:** full suite green, `tsc` clean, `next lint` clean, **plus** the live-Postgres
  verifications above and a re-run of `38-RLS-SMOKE-CHECKLIST.md` (still unticked from Phase 38)

## Manual-Only Verifications

| Behavior | Req | Why manual | Steps |
|---|---|---|---|
| Trigger blocks `user_id` change for all three caller classes | WSR-25 | text-lock cannot prove a trigger fires | As owner, co-owner/editor, and workspace member: attempt `UPDATE vault_projects SET user_id = <other>`; all three must be rejected |
| Custody binding denies a stale relationship | WSR-06 | needs live rows | Transfer custody, then confirm the old workspace loses access |
| RPC column allowlist withholds storage paths | WSR-03/04 | needs a live query | Query as a workspace caller; assert no `audio_file_url`, `document_data`, or path field returns |
| NULL `relationship_id` pre-flight | WSR-24 | production data | Count NULLs on both tables **before** the constraining migration |
| `service_role` audit privileges | WSR-26 | privilege state, not SQL text | `has_table_privilege('service_role','public.workspace_audit_log','UPDATE')` |
