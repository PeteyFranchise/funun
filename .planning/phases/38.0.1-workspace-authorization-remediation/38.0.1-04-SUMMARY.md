# Phase 38.0.1 Plan 04: Evidence Ladder Confirmation/Document/Effective-From Gate Summary

**Closed finding F8 by making `isLiveQualifyingEvidence` require subject confirmation and an attached document before authority tier, and by making `effectiveFrom` (stored since migration 183, read by nobody until now) actually gate liveness — plus NaN-safe date parsing across all three date fields.**

## Performance

- **Duration:** ~35 min
- **Completed:** 2026-09-07T02:49:00Z
- **Tasks:** 2
- **Files modified:** 4

## Accomplishments

- `isLiveQualifyingEvidence` (`lib/workspaces/evidence.ts`) now refuses unconfirmed evidence (`confirmedBySubjectAt` null), undocumented evidence (`documentId` null), and not-yet-effective evidence (`effectiveFrom` in the future) — closing the two halves of finding F8 (WSR-14, WSR-15).
- All three date comparisons (`effectiveFrom`, `expiresAt`, `supersededAt`) now treat a `NaN` parse result as the fail-closed outcome for that check, rather than as "no constraint."
- `loadRelationshipTier` (`lib/workspaces/roster-service.ts`) now selects `document_id` and `confirmed_by_subject_at` and maps them into `AgreementEvidenceFacts`, the only place in the codebase that constructs that type from the database.
- `resolveAuthorityTier` still never demotes an accepted relationship past `operational` — none of the three new checks reaches `none` (D-39 preserved).
- 25 tests in `evidence.test.ts` (11 new), 18 tests in `roster-service.test.ts` (2 new, 1 replaced) — all pass. `npx tsc --noEmit` is clean.

## Decisions Made

- **`confirmedBySubjectAt`/`documentId` are optional keys, not required keys, on `AgreementEvidenceFacts`.** The plan's action text described them as `string | null` without specifying optionality. Making them required broke `app/api/workspaces/[workspaceId]/roster/evidence/route.ts`'s GET handler (a file outside this plan's four declared files) at the type level, because it constructs a literal for `describeProvenance` without these fields — and `describeProvenance` itself must stay byte-unchanged per this plan's own `<verification>` clause ("describeProvenance is byte-unchanged (reviewer diffs it)"). An optional key satisfies both constraints: `!row.confirmedBySubjectAt` and `!row.documentId` treat a missing key identically to an explicit `null`, so fail-closed behavior is unaffected, and the acceptance-criteria greps for `confirmedBySubjectAt`/`documentId` still pass (4 and 3 occurrences respectively, both ≥ 2). This is documented at the type definition site in `evidence.ts` for the next reader.
- **Replaced rather than patched** the one existing `roster-service.test.ts` case whose fixture assumed declared-scope-alone was sufficient for authority tier — patching it forward with confirmation/document fields added would have obscured that R-08 specifically forbids that premise. The two replacement cases name the gating behavior directly.
