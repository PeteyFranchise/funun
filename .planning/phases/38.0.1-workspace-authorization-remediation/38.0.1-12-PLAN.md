<objective>
The data and API half of WSR-27, the minimal Member-facing consent surface added by R-18.

**Why this exists at all.** R-01 makes the Member the root of grant authority. A Member cannot
exercise authority through an API they cannot reach, and Phase 38.1 — which owns workspace UX — is
blocked on this phase. Without a surface, this remediation would ship a correct security model that
is still unusable and a kill switch that still cannot be flipped back on. It is deliberately
minimal: pending requests, per-permission approve or decline, revoke. Workspace chrome, the
switcher, the Roster room and everything else stay in 38.1.

Purpose: give the client component real, correctly-scoped data, and give the nineteen permissions a
vocabulary a musician actually understands.

Output: a plain-language copy table and a read-only aggregate endpoint.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `/api/settings/permissions` | The only identity that matters is the session's; nothing about scope is accepted from the request. |
| aggregate read -> other Members' relationships | Must be unreachable; a workspace owner querying this endpoint sees only rows naming themselves. |
