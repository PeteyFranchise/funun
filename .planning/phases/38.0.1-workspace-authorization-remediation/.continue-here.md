## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention |
|---|---|---|---|
| Stale-anchor doc edit after a subagent rewrote the file | A subagent (planner, researcher) rewrites a doc; a later orchestrator edit keyed on pre-subagent text silently no-ops, because `str.replace` returns the original on no match. **Happened twice** — Phase 38's roadmap block, then Phase 38.0.1's. | advisory | Re-read any file a subagent may have written BEFORE editing it, assert the anchor exists, and verify with an independent grep — never trust the script's own success message. |
| Multi-pass numeric sweep double-shifts already-corrected values | A renumber done as pattern replacement over prose. Pass 1 shifted 188→190 etc.; pass 2 re-ran an overlapping map and shifted the *already-corrected* 190→192, silently corrupting plans 02/05/09's filenames while 10/11 escaped only because their numbers were not sources in the second map. Took three passes to settle. | advisory | Never renumber by repeated pattern replacement. Derive from a single source of truth (each plan's `migration:` frontmatter) and make the operation idempotent. **Before dispatching any wave, verify frontmatter == filename == test-name for every migration plan** — the mismatch is invisible until an executor writes a file under the wrong number. |
| Text-lock tests mistaken for behavioral proof | This repo's migration tests assert the SQL *string*, not behavior. Phase 38 shipped with 4788 green tests and a live critical custody-takeover path. | blocking | Three requirements here (WSR-06, WSR-25, WSR-03/04) have **named owner-run verification steps** in plan checkpoints. A Jest command must never stand in as sole proof that a trigger fires or a policy denies. |
