## Decisions Made
- Identity check (`consentingUserId === relationshipMemberUserId`) is the FIRST check in `assertMemberMayConsent`, ahead of relationship-state and emptiness checks, so the route layer structurally cannot forget it (T-38.0.1-03-04).
- Self-FK chain walk over a closure table for `grant-lineage.ts`, per RESEARCH's explicit recommendation — D-21 describes exactly two authority tiers, not arbitrarily deep re-delegation.
- Project-scope containment rule: a `null` parent `projectId` is relationship-wide and contains any child scope (narrowing allowed); a non-null parent `projectId` requires the child to name that exact project, so a child with `projectId: null` under a project-scoped parent is refused as widening. This resolves RESEARCH's Open Question 1 in the direction it recommended.
- `MAX_GRANT_CHAIN_DEPTH` set to 8 — generous enough for any two-tier chain plus margin, small enough to bound a pathological or adversarial row set (T-38.0.1-03-06, Denial of Service).
