# Plan 38.2-02 — Beta Usage Metering and Workspace Usage Surface

## Objective

Measure how workspaces use seats, roster capacity, storage, AI, and e-sign tools during beta without
enforcing limits, consuming Member credits, or making pricing claims before Funūn has evidence.

## Scope

1. Add an append-only, idempotent workspace usage-event ledger in candidate migration 222.
2. Add service-only recording and bounded summary functions with an explicit metric allowlist.
3. Calculate current seat and roster gauges separately from cumulative metered events.
4. Add a workspace Usage page showing measured activity and the explicit “tracked, not enforced”
   beta state.
5. Add reusable server instrumentation for future workspace AI, storage, and e-sign call sites.

## Validation

- Migration and metric-vocabulary tests.
- Idempotency, non-negative quantity, bounded date-range, and fail-safe service tests.
- TypeScript, lint, production build, and deferred live-data UAT record.

## Risks and controls

- Usage metadata must not contain prompts, contract contents, file paths, emails, or rights data.
- Recording a metric must never block the underlying creative action during beta.
- Counters are informational and cannot be used as authorization or entitlement inputs.
