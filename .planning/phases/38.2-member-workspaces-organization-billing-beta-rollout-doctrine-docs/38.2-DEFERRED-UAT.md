# Phase 38.2 Deferred Human UAT

These checks are intentionally deferred to the owner-led testing session after migrations 219–223
are applied in order and the application deployment is complete.

## Member workspace

- Open Plan & usage from two different workspaces and confirm each shows its own workspace identity.
- Confirm the personal Member plan and personal catalogue remain unchanged.
- Confirm beta usage is labeled “Tracked, not enforced” on desktop and mobile.
- Create representative storage, AI, e-sign, and audio activity; confirm only aggregate counters are
  shown and no prompt, filename, contract text, email, or rights data appears.
- Put a test workspace into `paused`; confirm reads remain available and every workspace mutation is
  refused without deleting or detaching anything. Restore it with compare-and-swap state handling.

## Leadership rollout console

- Confirm non-Leadership Team Members cannot see the navigation item or reach the page/API directly.
- Add one test Member to the pilot, disable and re-enable the record, and confirm staff audit rows.
- Confirm a non-cohort Member receives 404 while cohort-required mode is active.
- Activate the emergency stop with a reason; confirm workspace-derived access stops while personal
  Member catalogue access and the control console remain available.
- Restore access only after verifying the incident/control state.

## Playbook

- Confirm the three entries render in their intended rooms with headings, lists, and callouts.
- Confirm company-wide entries are readable by intended Team roles and the IT entry remains IT/
  Leadership scoped.
- Confirm source hashes show no immediate repository drift after migration 223.

## Production order

1. Apply and verify Phase 38.1 migrations 219–220.
2. Run `38.2-PRE-APPLY-GATE.sql`; every blocking result must be true.
3. Apply 221, verify billing backfill and write decisions.
4. Apply 222, verify usage grants and bounded summary behavior.
5. Apply 223, verify Playbook publication and immutable revisions.
6. Run `38.2-POST-APPLY-VERIFY.sql`.
7. Deploy the application after 221 and 222 exist. The application intentionally fails workspace
   mutations closed if migration 221 is absent.
