# Plan 38.2-01 — Workspace Billing Entity and Read-Only Lifecycle

## Objective

Give every workspace an independent billing identity without changing or consuming any Member's
personal subscription. During beta every workspace begins on a free active plan. A later billing
lapse makes workspace mutations read-only while all rights, evidence, roster, attachments, audit,
and Member-owned catalogue records remain intact.

## Scope

1. Add an additive `workspace_subscriptions` table and append-only lifecycle-event ledger in
   candidate migration 221.
2. Backfill every existing workspace into the beta-free plan and provision future workspaces with a
   database trigger rather than changing Member signup.
3. Add service-only, compare-and-swap state transition and fail-closed write-eligibility functions.
4. Add a central workspace mutation gate and adopt it across workspace-context mutation routes.
5. Add a workspace Plan page that clearly separates the workspace plan from the signed-in Member's
   personal plan.
6. Do not create Stripe customers, prices, checkout sessions, invoices, or charges during beta.

## Validation

- Migration source invariants and pure billing-state tests.
- Workspace route source audit proving mutations use the central write gate.
- Focused API tests, TypeScript, lint, and production build.
- Candidate migration remains unapplied.

## Risks and controls

- Billing may never delete or detach workspace records; migration 221 is additive and has no delete
  cascade from a billing event into workspace data.
- Missing or unreadable subscription state fails closed for writes while workspace reads remain
  available.
- Personal `subscriptions.user_id UNIQUE NOT NULL` remains untouched.
- State transitions use an expected timestamp so two operators cannot overwrite each other.
