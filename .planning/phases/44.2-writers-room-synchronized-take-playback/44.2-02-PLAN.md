# Plan 44.2-02: Protected per-listener playback and session integration

## Objective

Wire the protocol to the take player and live-session UI while preserving normal audio authorization.

## Tasks

1. Add host **Play for room** selection from takes the host may play. Every listener independently resolves
   an authorized protected URL; a control message containing a take ID never grants storage access.
2. Preload enough of the selected take for a bounded synchronized start, show participant readiness, then
   start at a future epoch. Handle one slow/failed participant without freezing everyone indefinitely.
3. Apply play/pause/seek/rate/host-transfer commands and periodic state snapshots through the authorized
   room channel/provider data path chosen in 44.2-01. On reconnect, re-fetch membership and take access.
4. Show host, selected take, ready/syncing/degraded state, drift recovery, and “listen locally” fallback.
   Calls may be muted during take playback only through an explicit control to avoid feedback.
5. Test revoked/signed-URL expiry, removed Member, take deletion, host loss, multiple tabs, two players,
   network delay, backgrounding, and no-call local playback.

## Acceptance

- Video provider never receives or stores the protected take as a call track.
- Unauthorized listeners fail independently without leaking take existence/path.
- Synchronized playback cannot expose private pins/comments or mutate rights/approval data.
- Human multi-device UAT records actual drift and degraded behavior.
