# Plan 44.2-01: Transport protocol and drift model

## Objective

Specify and test a provider-neutral synchronized-transport state machine before touching audio players.

## Tasks

1. Read current take player/transport, signed audio URL batching, room broadcast authorization, reconnect,
   and active-player keyboard registry in full.
2. Define versioned control messages with work/session/take IDs, monotonic sequence, host ID, command,
   position, playing state, playback rate, issued-at monotonic reference, and protocol version. Ignore
   duplicate/out-of-order/wrong-work/wrong-session commands.
3. Define host election/transfer/end/reconnect snapshots and server-authorized host identity; client data
   cannot grant control authority.
4. Implement pure expected-position, drift bands, correction, latency estimation, and state-reducer logic.
   Bound correction and fall back to explicit seek; never market sample accuracy.
5. Test clock skew, delay, duplicate/reordered/lost messages, pause/seek races, host loss, reconnect, rate
   changes, wrong take/work/session, and removed participant.

## Acceptance

- Protocol carries no URL, token, audio bytes, comment, pin, or rights value.
- Pure tests establish deterministic state under reordering/reconnect.
- Existing local playback remains unchanged when no synchronized session is active.
