# Phase 38.0.3 Plan 05: `no_block` Relocation Summary

**Migration 210 authored (not applied): `no_block` moves to an unexposed `private` schema, both string-literal body callers are retargeted before the drop, all eleven block-enforcing policies are rewritten with their predicates proven unchanged, and the `public` copy is dropped with no modifier so the drop itself is the proof that nothing was missed.**

**No database connection was opened and no migration was applied. The number actually claimed is 210** (`supabase/migrations/210_no_block_relocation.sql`), re-verified free at execution time against `supabase/migrations/`, `git status --porcelain` and `.planning/quick/**`.

`types/supabase.ts` does not exist in this repo, so no generated-type regeneration is required — and `npm run db:types` would need a database connection, which is forbidden. Nobody needs to go looking.

The load-bearing choices:

- **Section 3 precedes section 5.** PostgreSQL records `DEPENDENCY_NORMAL` entries for RLS policy expressions but nothing for a name inside a string-literal `AS $$ … $$` body, and every function in this repo uses that form. The drop would have succeeded with either caller still pointing at `public.no_block`, and that caller would have raised `42883` on its next live call — the migration-198 failure shape.
- **`green_room_can_view_post`'s replacement is copied from applied migration 209**, preserving the Tier-2 caller-identity bind (`p_viewer = (SELECT auth.uid()) OR (SELECT auth.role()) = 'service_role'`). Copying 076 would have reverted Tier 2 silently.
- **The drop takes no modifier.** Restrictive-by-default makes the statement its own verification: a missed policy produces `2BP01` with a `DETAIL:` line naming every remaining dependant. The header tells the owner that a refusal is the safety mechanism working, and to read the DETAIL rather than force it.
- **`REVOKE EXECUTE … FROM PUBLIC, anon, authenticated` before `GRANT … TO authenticated`** in the new schema. PostgreSQL grants EXECUTE to PUBLIC by default on every function in every schema, so the hazard follows the function to `private`; a `GRANT USAGE ON SCHEMA` alone would have re-created the exposure.
- **The eleven policies** reproduce their `FOR` clause, `TO` clause (or its absence) and predicate exactly, with only the helper qualifier changed. `dm_threads` stays unqualified inside `dmm_insert_sender` because that is a policy expression, not a definer body with an empty `search_path`.

## OWNER: pre-apply gate, then apply

### Step 1 — the pre-apply gate (run this FIRST, before pasting migration 210)

Plan 06 will author the full `38.0.3-VERIFY-A2-NO-BLOCK.sql` with its P-, D-, B- and E-blocks. **Plan 06's G-block is the part that gates this plan**, and it is quoted below in runnable form so migration 210 is never applied without it. It is read-only.

The failure it prevents: PostgreSQL records dependencies for RLS policy expressions but **not** for a name inside a string-literal `AS $$ … $$` body. So migration 210's `DROP FUNCTION` will succeed even with a third body caller still pointing at `public.no_block`, and that caller will raise `42883 function does not exist` on its next live call — in production, with no prior warning. This query is the only thing standing between the phase and that outcome.

```sql
-- ============================================================
-- PRE-APPLY GATE for migration 210 (plan 06 Part A2, G-block).
-- READ-ONLY. Run this BEFORE pasting migration 210. If G1 says STOP,
-- DO NOT APPLY 210 — extend its section 3 first.
-- ============================================================
SELECT * FROM (

  SELECT 1 AS ord,
         'G1: SECURITY DEFINER bodies referencing no_block' AS check_name,
         coalesce(string_agg(n.nspname || '.' || p.proname, ', ' ORDER BY n.nspname, p.proname), '(none)') AS detail,
         CASE WHEN count(*) = 2
                   AND count(*) FILTER (WHERE p.proname = 'green_room_can_view_post') = 1
                   AND count(*) FILTER (WHERE p.proname = 'discover_profile_id_by_email') = 1
              THEN 'PASS'
              ELSE 'STOP - DO NOT APPLY 210. A THIRD BODY CALLER MEANS SECTION 3 IS INCOMPLETE AND THE DROP WILL BREAK IT SILENTLY.'
         END AS verdict
  FROM pg_proc p
  JOIN pg_namespace n ON n.oid = p.pronamespace
  WHERE n.nspname NOT IN ('pg_catalog', 'information_schema')
    AND p.prosrc ILIKE '%no_block%'
    AND p.proname <> 'no_block'

  UNION ALL

  SELECT 2,
         'G2: policies whose predicate names no_block',
         coalesce(string_agg(tablename || '.' || policyname || ' roles=' || roles::text, ', ' ORDER BY tablename, policyname), '(none)'),
         CASE WHEN count(*) = 11
              THEN 'PASS'
              ELSE 'REVIEW - migration 210 section 4 rewrites exactly 11. Any policy listed here but absent from section 4 must be added before applying.'
         END
  FROM pg_policies
  WHERE coalesce(qual, '') || coalesce(with_check, '') ILIKE '%no_block%'

  UNION ALL

  SELECT 3,
         'G3: public.no_block(uuid,uuid) pre-state, for the record',
         'exists=' || (to_regprocedure('public.no_block(uuid,uuid)') IS NOT NULL)::text
           || ' execute_grantees=' || coalesce((
                SELECT string_agg(DISTINCT rp.grantee, ',')
                FROM information_schema.routine_privileges rp
                WHERE rp.specific_schema = 'public'
                  AND rp.routine_name = 'no_block'
                  AND rp.privilege_type = 'EXECUTE'
              ), '(none)'),
         'INFO'

  UNION ALL

  SELECT 4,
         'G4: is the private schema already present?',
         'exists=' || (EXISTS (SELECT 1 FROM pg_namespace WHERE nspname = 'private'))::text,
         'INFO - and it must NOT appear under Supabase API settings, Exposed schemas, now or ever'

) g ORDER BY ord;
```

**Expected before apply:** G1 `PASS` naming exactly `public.discover_profile_id_by_email, public.green_room_can_view_post`; G2 `PASS` with 11 policies, ten showing `roles={authenticated}` and `release_comments.rc_select_public` showing `roles={public}`; G3 `exists=true execute_grantees=authenticated`.
