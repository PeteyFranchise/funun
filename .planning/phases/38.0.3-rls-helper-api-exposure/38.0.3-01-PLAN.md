## THE TRAP EXEMPTION — READ THIS BEFORE REVIEWING THIS PLAN

`38.0.3-SCOPE.md` contains a rule stated in capital letters:

> **THE TRAP — do not blanket-revoke.** "Revoking `EXECUTE` from `authenticated` would take large
> parts of the app down… Any plan that opens with 'REVOKE from anon, authenticated' is wrong and
> must be rejected at plan-check."

**That rule is correct, it is not weakened here, and this plan is its one documented exemption.**

The TRAP applies to a helper **if and only if an RLS policy names that helper**. RLS policy
expressions are evaluated with the privileges of the querying role, so revoking a helper a policy
calls breaks every read gated by that policy. That is real and it is why Tier 2 binds rather than
revokes.

The four functions in this plan are named by **zero** policies. Their only callers are other
`SECURITY DEFINER` bodies, and a definer body executes with the privileges of the function's
**owner**, not the caller's — so the caller does not need `EXECUTE` for those calls to succeed.
PostgreSQL, *Privileges*: `EXECUTE` is "the only type of privilege that is applicable to functions";
PostgreSQL, *Row Security Policies*: policy expressions "are run … with the privileges of the user
running the query, although security-definer functions can be used to access data not available to
the calling user."

Per-function evidence, measured over all 200 migrations with line comments stripped and
dollar-quoted regions mapped (`38.0.3-RESEARCH.md` §Q1, reproduced as a permanent test by Task 1):

| Function | Policy call sites | Definer-body callers | Action |
|---|---:|---|---|
| `workspace_access_enabled()` | **0** | 11 | revoke |
| `workspace_grant_lineage_live(uuid)` | **0** | 2 | revoke |
| `green_room_post_matches_custom_audience(uuid,uuid)` | **0** | 1 | revoke |
| `workspace_roster_relationship_is_live(uuid,uuid)` | **0** | **0 — dead code** | drop (restrictive), revoke as fallback |

The restatement of the rule that the plan-checker should apply:

> **No blanket revoke. A revoke is permitted only for a function whose policy call-site count is
> proven zero, and the proof must be a test in the repo, not a claim in a plan.**

Task 1 is that test. It runs on every `npm test` from now on, so the claim cannot rot silently.

| Boundary | Description |

| PostgREST `anon`/`authenticated` → `public` schema functions | Every executable function in an exposed schema is an HTTP RPC endpoint by default. This is the boundary the whole phase is about. |
