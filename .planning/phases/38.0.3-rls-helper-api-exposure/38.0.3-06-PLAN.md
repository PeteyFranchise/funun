<objective>
Author the Tier 3 verification pair: the structural gate that must run BEFORE migration 209 is
applied, and the behavioural probe that proves block enforcement survived the relocation.

Purpose: the `no_block` relocation is the only part of this phase that rewrites policies and drops a
function. `DROP FUNCTION` under PostgreSQL's default restrictive behaviour is self-verifying for
policy references — it refuses and names them — but it is **blind to references inside
string-literal function bodies**, and every function in this repo uses that form. That blind spot is
exactly the migration-198 failure shape: the SQL applies cleanly, and the defect surfaces on the
first live call. Part A2 closes it by reading production before anything is applied.

Output: `38.0.3-VERIFY-A2-NO-BLOCK.sql` and `38.0.3-VERIFY-B2-NO-BLOCK.sql`.
