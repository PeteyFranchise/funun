`grant_pg_graphql_access` looked alarming on all four columns, so its body was
read in full. Two independent reasons it cannot affect this phase:

1. Lines 7-14 are an **early return**: it exits unless the DDL that fired it was
   on the `pg_graphql` extension. A `REVOKE` on a `public` function never
   reaches a grant statement.
2. Lines 38-41 target **`graphql` and `graphql_public` only** — never `public`.

**The `touches_public_schema = true` flag was a false positive in the probe's
own pattern**: `%public.%` matches `graphql_public.`. Recorded because the same
sloppy pattern would mislead the next reader too.

`grant_pg_net_access` is the same Supabase-authored shape scoped to `net`, and
`grant_pg_cron_access` is scoped to `cron` and names neither of our roles.
