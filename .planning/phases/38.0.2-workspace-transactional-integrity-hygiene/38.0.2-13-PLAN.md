<objective>
Wire the D-55 cohort gate into the workspace access gate and the creation route, move workspace
creation onto its atomic RPC, and apply the WSR-29 role floor at the API layer.

**WSR-16 / R-07 — the cohort gate is a release requirement.** Without it, re-enabling the D-56 kill
switch goes from "off" straight to "every Member". `requireWorkspaceAccess` already makes one
service-role round trip per call to read the switch; migration 197's `workspace_access_permitted`
folds the switch and the cohort window into one function so the hot path stays at one round trip
rather than two.

**R-25 — a non-cohort Member gets 404, not 403.** During a bounded pilot, someone outside the cohort
should not learn the feature exists. 403 is more honest but leaks the existence of a capability they
cannot reach; 404 matches how the rest of this repo hides unreachable resources. A **disabled
platform control still returns 503** — the two must never be conflated, which is why
`workspace_access_permitted` returns two booleans rather than one.

**WSR-23 / R-15 — creation is two inserts in two transactions** with a compensating DELETE that does
not run if the process dies between them, leaving an ownerless workspace. That is why migration 182
carries a `created_by = auth.uid()` visibility fallback — and why a creator removed from their own
workspace sees it forever. Migration 197 removed the fallback; this plan removes the reason it
existed.

**WSR-29 / R-20 — the API layer must carry the same role floor as the SQL.** This repo's doctrine is
two independent layers agreeing (078, 136, 187, 190, 196), and WSR-17 exists because those two
layers once disagreed about `expires_at`. **But the floor must not be over-applied**: R-20 says
guests keep workspace membership, chrome, and whatever R-12's rules allow. So the floor is a named
predicate composed at the project-data routes, not a change to `requireWorkspaceAccess` itself.

Output: the gate, the creation route, and the two project-data routes, each with tests.

**Non-negotiable constraints for this plan:**
- Do NOT open a database connection. The RPCs are authored but unapplied; every test mocks the
  client.
- Do NOT flip the D-56 kill switch.
- Do NOT touch anything under `lib/playbook/`, `components/playbook/`, or `app/**/playbook/`.
- Stage by explicit path only. **Never `git add -A`.**
- Use `npx tsc --noEmit`, never `npm run build`. `tsc` does not cover `next build`'s lint step —
  leave no unused import or variable, and never add an eslint-disable naming a
  `@typescript-eslint/*` rule.
- **Jest reads its positional argument as a regex**; escape the brackets in bracketed paths.
</objective>
