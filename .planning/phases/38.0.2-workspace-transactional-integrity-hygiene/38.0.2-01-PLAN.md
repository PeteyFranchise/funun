<objective>
Author the pure state-machine module for two-sided workspace ownership transfer (R-05 / WSR-08),
mirroring `lib/workspaces/custody-transfer.ts` verbatim in shape.

R-05 makes ownership transfer two-sided: the owner nominates, the successor accepts. That is exactly
the D-29 custody shape, and this repo already has a complete, reviewed, in-production implementation
of it. This plan copies the module shape — legal-edge table, `isLegal*Transition`, `assertMayOffer`,
`assertMayRespond`, `describe*Effect` — and changes only the subject.

Purpose: land the pure decision layer FIRST, so migration 197's CHECK constraints (plan 05), the
RPCs (plan 08) and the route (plan 12) all copy their literals from one source instead of three.

Output: `lib/workspaces/ownership-transfer.ts` and its unit suite. No database, no route, no
migration.

  `migration up`, or `db query`.
- Do NOT flip the D-56 kill switch. It stays OFF until the whole phase ships.
- Do NOT touch anything under `lib/playbook/`, `components/playbook/`, or `app/**/playbook/` —
  another workstream is mid-flight there in this same working tree.
- `git status` will show unrelated modified and untracked files. Stage by explicit path only.
  **Never `git add -A`.**
- Use `npx tsc --noEmit`, never `npm run build` (a dev server may be live).

    successor holds no active seat in this workspace (a stranger cannot be nominated); successor is
    already `owner`. Each refusal carries a plain user-facing sentence.

    `assertMayRespond(args: { parties: { fromUserId: string; toUserId: string; offeredBy: string };

    `custody-transfer.ts`'s `assertMayRespond` predicate structure exactly, including its
    self-dealing branch: only `toUserId` may accept or decline; only `fromUserId`/`offeredBy` may

    `describeOwnershipTransferEffect(args: { workspaceName: string; successorName: string }):
    string`. The sentence must name what changes (who administers this workspace: its members,
    invitations, roster proposals and configuration) and what does NOT change: it is not ownership
    of any Member's record, catalogue or rights; it creates no split-sheet party, no credit, no
    royalty entitlement, no version-ownership record and no signature authority; and every Member's

    already uses in `custody-transfer.ts`.
