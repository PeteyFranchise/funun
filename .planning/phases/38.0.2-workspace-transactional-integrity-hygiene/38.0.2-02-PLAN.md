<objective>
Author the D-55 cohort gate module (R-07 / WSR-16), mirroring `lib/song-passport/feature.ts` exactly
in shape.

R-07 makes the cohort gate a release requirement: without it, turning the D-56 kill switch back on
goes from "off" straight to "every Member". This module is the server-only rollout boundary — the
env-var decision plus the cohort-window read, folded into one service-role round trip.

Purpose: land the decision function before anything calls it, so plan 09's SQL and plan 13's gate
wiring both build against a settled contract instead of inventing one.

Output: `lib/workspaces/cohort.ts`, its unit suite, and the two new server-only environment
variables documented in `.env.example`. No route change, no migration.

**Two decisions this plan settles, stated so the owner can override them:**

1. **Two environment variables, not three.** `lib/song-passport/feature.ts` uses three
   (`*_ENABLED`, `*_PILOT_ENABLED`, `*_KILL_SWITCH`). Workspaces already have a kill switch — D-56,
   in the database, in `public.workspace_access_config` — and adding a second, env-based one would
   give the platform two stop buttons that can disagree. So this module uses
   `WORKSPACE_ACCESS_GENERAL_ENABLED` and `WORKSPACE_COHORT_PILOT_ENABLED`, and D-56 stays the
   single kill switch.
2. **The default is CLOSED, which inverts Song Passport's third rung.** Song Passport treats
   "pilot not enabled" as "feature off". Here, "neither variable set" means **cohort membership is
   required** — not "workspaces are off", which D-56 already expresses. That is the reading R-07
   demands: the gate's whole purpose is that flipping D-56 on must not admit everyone. Going
   generally available is then one explicit act (`WORKSPACE_ACCESS_GENERAL_ENABLED=true`), never an
   omission.

**Non-negotiable constraints for this plan (phase-wide):**
- Do NOT open a database connection of any kind. No `supabase db push`, `db reset`,
  `migration up`, or `db query`.
- Do NOT flip the D-56 kill switch.
- Do NOT touch anything under `lib/playbook/`, `components/playbook/`, or `app/**/playbook/`.
- Stage by explicit path only. **Never `git add -A`.**
- Use `npx tsc --noEmit`, never `npm run build`.
- Jest reads its positional argument as a regex — use literal paths.
</objective>

    Promise<WorkspaceAccessDecision>`:

    - make ONE `rpc('workspace_access_permitted', { p_uid: userId, p_require_cohort: requireCohort })`
      call

      `{ accessEnabled: false, cohortEligible: false }` — fail closed on every path
    - otherwise return `{ accessEnabled: row.access_enabled, cohortEligible: row.cohort_ok }`
    - normalise a single-object result and a one-element-array result identically, since PostgREST
      returns a set for a `RETURNS TABLE` function.

    Comment that `public.workspace_access_permitted` (migration 197, plan 09) resolves the D-56
    switch and the cohort window in ONE round trip specifically so `requireWorkspaceAccess` does
    not grow from one service-role round trip to two on every gated request, and that this is the
    same "fold the hops into one function" move migrations 192 and 194 already made.

    Also comment that R-25 decided a non-cohort Member receives **404**, not 403, and that the
