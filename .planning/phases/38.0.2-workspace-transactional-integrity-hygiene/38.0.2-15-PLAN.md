<objective>
Move both roster surfaces onto the transactional RPC, point the workspace-facing read at the
collapsing reader, and correct the audit module's now-false header.

**F16 — roster transitions have no compare-and-set at all.** `app/api/roster/relationships/route.ts`
reads the row, calls `assertCanTransition(row.state, ...)`, then issues
`.update({state}).eq('id', row.id)` — with no `.eq('state', row.state)` anywhere in the file. Two
concurrent PATCHes can both read `proposed` and one can overwrite the other's terminal state.

**And the `block` branch has a second, worse problem.** It upserts `workspace_roster_blocks` in a
separate transaction after the state update. A crash between the two leaves a `blocked` relationship
with no block row — and `assertCanPropose`, which reads the blocks table, would then permit a
re-proposal. That is the "side effects" half of WSR-12.

**R-23 / WSR-18 — the workspace can currently see that it was blocked.** Migration 183 keeps
`workspace_roster_blocks` Member-private *so a workspace must never be able to enumerate who blocked
it (T-38-04-05)* — but the relationship row's own `state = 'blocked'` says the same thing. Migration
197 added `workspace_roster_page`, which collapses it to `refused`. This plan points the workspace
GET at it.

**WSR-13 — and the audit module's header is about to be wrong.** It currently says
`logWorkspaceAction` is *"the ONE write-through call every workspace-context write invokes."* After
this phase that is false for every consequential path. A stale doctrine comment in this codebase is
exactly how migration 139's wrong parenthetical reached production and cost a day of broken custody
transfer. Correct it in the same plan that makes it wrong.

Output: both roster routes rewired with tests, and the audit module's header and scope corrected.

**Non-negotiable constraints for this plan:**

  client.

- Do NOT touch anything under `lib/playbook/`, `components/playbook/`, or `app/**/playbook/`.

- Use `npx tsc --noEmit`, never `npm run build`. `tsc` does not cover `next build`'s lint step —
  leave no unused import, and never add an eslint-disable naming a `@typescript-eslint/*` rule.
- **Jest reads its positional argument as a regex**; escape the brackets in bracketed paths.
</objective>
