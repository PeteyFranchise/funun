<objective>
Move invitation redemption onto its transactional RPC, gate the acceptor on the D-55 cohort, and
take the invited email address out of the audit trail.

**F11 — redemption is four transactions.** Lookup; update the invitation to `accepted` with a CAS on
`status = 'pending'` **whose result is never checked** (the error variable catches an error, not
"zero rows matched"); seat lookup; then seat update **or** seat insert. Two concurrent redemptions
can both pass the seat lookup and both take the insert branch — the partial unique index saves
correctness with a `23505` the route reports as a generic 500. And `targetId: pendingSeat?.id ?? null`
writes a null audit target, which is exactly the shape migration 197's deferred constraint trigger
refuses at COMMIT.

**R-24 — the cohort gate applies to the acceptor.** If it applied only to workspace creation, one
cohort owner could pull in unlimited non-cohort Members and the pilot bound would stop meaning
anything. This route is the **third** kill-switch call site — it calls `isWorkspaceAccessEnabled`
directly rather than going through `requireWorkspaceAccess`, and missing it reproduces the exact
shape of hotfix F7.

**WSR-19 — the invited address is in a broadly readable column.**
`app/api/workspaces/[workspaceId]/invitations/route.ts` writes `changes: { role, email }`, and
migration 186's audit-visibility helper made that readable by every active seat, including guests.
The address already lives on `workspace_invitations.email`, whose SELECT policy is owner/admin-only,
and the audit row's `target_id` already points at that invitation. So `changes` should carry the
role and nothing else. Zero audit rows exist in production, so there is nothing to migrate.

Output: both routes rewired, with test suites.

**Non-negotiable constraints for this plan:**
- Do NOT open a database connection. The RPCs are authored but unapplied; every test mocks the
  client.
- Do NOT flip the D-56 kill switch.
- Do NOT touch anything under `lib/playbook/`, `components/playbook/`, or `app/**/playbook/`.
- Stage by explicit path only. **Never `git add -A`.**
- Use `npx tsc --noEmit`, never `npm run build`. `tsc` does not cover `next build`'s lint step —
  leave no unused import, and never add an eslint-disable naming a `@typescript-eslint/*` rule.
- **Jest reads its positional argument as a regex**; escape the brackets in bracketed paths.
</objective>
