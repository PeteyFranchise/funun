<objective>
Repoint the members route at `workspace_change_member_role_or_status`, and add the workspace
ownership route (WSR-07, WSR-08, WSR-11).

**What gets deleted, and why it is safe to delete.** RESEARCH §11's one-line rule: keep every
predicate, delete every mutation sequence. A predicate that refuses before the RPC is a genuine
second layer — it fails for a different reason and it produces a sentence a `RAISE` cannot phrase.
A write the RPC also performs is not a second layer; it is a second writer, and the stale copy is
where drift lives.

So this plan deletes:
- `refuseIfOwnerFloorBreaks`'s `count` query — the floor is now counted after the lock, in the write
  transaction. That cross-transaction count is F15.
- `isOwnerFloorTriggerError` — three files are currently coupled to one English sentence (migration
  182's RAISE, `WORKSPACE_OWNER_FLOOR_MESSAGE`, and this sniffer). The outcome code `'floor'`
  replaces the sniffing; the constant stays as the sentence shown to a human.
- Both `.update(...).eq('id', target.id)` calls and their paired `logWorkspaceAction` calls, in
  PATCH and DELETE.

And keeps everything on §11's KEEP list, unchanged.

**Why a new route rather than an extension of `/members`.** WSR-08's flow is a two-sided
negotiation with its own diary table and its own state machine, and it needs `requireWorkspaceAccess`
to apply from the path segment (D-31). Note the deliberate asymmetry with custody:
`app/api/vault/custody-transfers/route.ts` lives *outside* `/api/workspaces/**` because custody is a
Member act carrying no workspace authority. Workspace ownership is the opposite — it is entirely a
workspace act — so it belongs inside. Say so in the route header.

Output: the members route rewired with its first test suite, and a new ownership route with its own.

**Non-negotiable constraints for this plan:**
- Do NOT open a database connection of any kind. The RPCs this route calls are authored but
  **unapplied** — these tests mock the Supabase client, they never reach a database.
- Do NOT flip the D-56 kill switch.
- Do NOT touch anything under `lib/playbook/`, `components/playbook/`, or `app/**/playbook/`.
- Stage by explicit path only. **Never `git add -A`.**
- Use `npx tsc --noEmit`, never `npm run build`. Note that `tsc` does **not** cover the lint step
  `next build` runs; keep imports used and exports referenced, and never add an eslint-disable
  naming a `@typescript-eslint/*` rule — this project extends only `next/core-web-vitals` and such a
  directive is itself a lint error.
- **Jest reads its positional argument as a regex, so a bare `[workspaceId]` matches nothing.**
  Escape the brackets, as in the verify commands below.
