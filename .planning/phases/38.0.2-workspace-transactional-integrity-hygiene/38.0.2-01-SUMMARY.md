## Decisions Made

1. **403 vs 409 in `assertMayNominate`.** The plan's signature allowed `403 | 409` without assigning them. Split: **403** for authority refusals (nominator is not `owner`; nominator names themselves), **409** for workspace-state refusals (successor holds no active seat; successor is already owner). This keeps "you are not allowed" distinct from "the workspace is not in a state where this means anything", which is what the route in plan 12 will need to render different copy for.
2. **The self-dealing branch covers `decline` too.** The plan required "the nominator may never accept". `custody-transfer.ts` refuses both accept and decline from the offerer, and copying it verbatim — as the plan instructed — is strictly safer: it means a single actor can never *resolve* a nomination in either direction. Documented in the JSDoc.
3. **Blank-name fallback in `describeOwnershipTransferEffect`.** Names are trimmed and fall back to `this workspace` / `the nominated successor`. A missing display name should degrade the copy, never break the consent gate that stands in front of an irreversible authority change.
4. **Header wording adjusted to keep the purity grep honest.** The header says the module "never reads the process environment" rather than spelling the accessor, so the suite's `process\s*\.\s*env` source assertion tests the code rather than matching the module's own prose about itself. Same reasoning applies to why the purity checks live in the test file and not as a comment claim.
