# Phase 38.0.2 Plan 02: D-55 Cohort Gate Summary

Server-only cohort gate for the workspace pilot that defaults **closed**, so re-enabling
the D-56 kill switch admits a named cohort rather than every Member — resolved in one
service-role round trip and failing closed on every error path.

## What Was Built

`lib/workspaces/cohort.ts` (193 lines), mirroring `lib/song-passport/feature.ts` in shape:
pure decision function, structurally-typed injected client, `process.env` as a default
parameter so the decision is testable without mutating global state.

Exports:

| Export | Purpose |
|---|---|
| `WORKSPACE_ACCESS_GENERAL_ENABLED_VAR` / `WORKSPACE_COHORT_PILOT_ENABLED_VAR` | The two variable names as constants, so the reader, the tests and `.env.example` cannot drift |
| `WorkspaceCohortEnvironment` | `Readonly<Record<string, string \| undefined>>` |
| `isWorkspaceCohortRequired(environment = process.env)` | False **only** when general availability is the exact string `'true'`; otherwise true |
| `WorkspaceAccessDecision` | `{ accessEnabled, cohortEligible }` |
| `WorkspaceCohortClient` | Structural interface exposing only `rpc('workspace_access_permitted', { p_uid, p_require_cohort })` |
| `resolveWorkspaceAccessDecision(client, userId, environment = process.env)` | ONE round trip; fails closed on every path |
| `isWorkspaceAccessPermitted(decision)` | Pure: permitted only when `accessEnabled && cohortEligible` |
| `canAcceptWorkspaceInvitation(client, userId, environment = process.env)` | **R-24** — the acceptor predicate |

No default export, no `create`/`update`/`delete`/`save` name, no import of
`@/lib/supabase/server` — the client is always injected. The file has **zero imports**,
so the "every import path begins `@/`" criterion holds vacuously.

## The Two Locked Decisions, As Implemented

**Two env vars, not three.** Workspaces already have a kill switch — D-56, in
`public.workspace_access_config` (migration 186). A second, env-based one would give the
platform two stop buttons that can disagree, and this repo has already shipped a bug of
exactly that shape: **WSR-17 exists because the RLS helper and the API gate disagreed
about `expires_at`.** So D-56 stays the single kill switch and this module reads only
`WORKSPACE_ACCESS_GENERAL_ENABLED` and `WORKSPACE_COHORT_PILOT_ENABLED`.

**The default is CLOSED**, inverting Song Passport's third rung. `isWorkspaceCohortRequired({})`
returns `true`. Going generally available is one explicit act, never an omission. This is
locked by a test titled to name R-07 so it fails loudly if someone later "fixes" the
default to open.

One judgement call worth surfacing: when the cohort is **not** required, the module returns
`cohortEligible: true` from its own reading rather than echoing the RPC's `cohort_ok`.
`accessEnabled` still comes from the database verbatim, so **D-56 keeps the last word
either way**. This follows the repo's two-independent-layers-agreeing doctrine (migrations
078, 136, 187, 190, 196) rather than deduplicating into a single trusted source. It also
satisfies both plan bullets literally ("reports `cohortEligible: true` without needing a
cohort row" when not required; "mirrors `cohort_ok` exactly" when required).
