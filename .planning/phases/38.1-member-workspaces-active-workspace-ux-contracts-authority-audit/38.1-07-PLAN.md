# Phase 38.1-07 Plan — Master-Ownership Claims and Evidence-Derived Access

## Scope

- Let a Label workspace file a claim against a Writer's Room recording version even when it has no existing project attachment.
- Keep a new claim inert and visible to both the workspace and the recording holder.
- Let only the holder confirm, dispute, or attach their own signed/verified supporting document.
- Derive non-master recording access from `document_supported` state without depending on a roster relationship.

## Security and custody boundaries

- A claim never exposes an audio path, signed URL, lyric body, private identifier, or clean master.
- Claim state is not a shortcut into the existing workspace-grant chain.
- Evidence-derived access is recomputed at use time, requires a live non-guest workspace seat, and explicitly excludes `access_clean_masters`.
- The holder identity is resolved from `work_versions -> works.user_id`; callers cannot nominate it.
- Evidence must be owned by the holder, signed or verified, and attached to the graduated project for the claimed work.
- `document_supported` survives roster termination because the record does not reference a roster relationship.

## Verification

- Pure state/access-presentation tests.
- Migration structural tests for RLS, grants, state transitions, locking, evidence binding, and clean-master exclusion.
- Typecheck plus targeted route/UI lint.
