# Phase 38.1-06 Plan — Rights Proposals and Member Confirmation

## Scope

- Add an append-preserving proposal record for PRO, IPI, publisher, and SoundExchange ID changes.
- Let a workspace with live `edit_rights_information` authority propose one field at a time.
- Give the named Member a personal Settings surface to confirm or decline each proposal.
- Apply a confirmed value and decide its proposal in one database transaction.

## Security and doctrine

- A workspace proposal never changes the canonical profile field and confers no access.
- Only the named Member can decide; workspace routes cannot confirm or decline.
- The server re-derives the workspace permission at proposal time.
- Browser roles receive no direct proposal-table writes; the decision function is service-only.
- No payout, tax, or unrelated profile field can be represented.

## Verification

- Pure schema/presentation tests.
- Migration structural test for field allowlist, RLS, grants, locking, and atomic profile update.
- Route/component typecheck, targeted lint, and production build.
