# Phase 38.1-03 Summary — Member-Visible Workspace Audit Surface

## Delivered

- Expanded the workspace Activity room into a searchable audit surface.
- Added client-side filters for activity category, involved person, date window, and protected-detail
  state across the current bounded server-loaded page.
- Added an accessible selected-event inspection panel showing the approved action, actor, affected
  Member, timestamp, record type, permission relied on, and redaction state.
- Added safe workspace-local linking for roster-relationship targets only. Other targets remain text
  until a separately authorized workspace detail route exists.
- Added bounded Older/Newer pagination while preserving the `/w/[workspaceId]` acting context.
- Added CSV export of current filtered results using only approved display fields, with spreadsheet
  formula-injection neutralization for user-controlled cells.
- Added activity categories and neutral target labels as a pure, client-safe presentation model.

## Security boundaries

- Core audit rows still come exclusively from the authenticated `workspace_audit_page` RPC.
- The raw `changes` JSON object is discarded during server normalization and is absent from the
  Client Component type, filters, inspector, and export.
- Service-role profile enrichment still occurs only after the hardened RPC has returned identifiers
  the caller is authorized to see.
- Target IDs produce links only for the reviewed roster destination, and that destination repeats its
  own server-side workspace authorization.
- The interface explicitly identifies protected detail without implying that empty detail is a
  complete raw audit record.
