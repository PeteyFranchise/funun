# Plan 38.1-01 — Active Workspace Context and Persistent Chrome

## Objective

Create the first navigable Member workspace surface while preserving Phase 38's authorization
invariants. A Member can move between Personal and an eligible workspace without reauthentication;
the URL and server—not client state—determine the active workspace.

## Scope

1. Add pure active-context display/path helpers and focused tests.
2. Add a server loader that lists active, non-expired workspace seats through the Member session and
   resolves a requested workspace only after `requireWorkspaceAccess` succeeds.
3. Add an accessible workspace switcher to Personal and workspace navigation. Switching uses links
   and never signs out or writes browser storage.
4. Add `/w/[workspaceId]` layout and landing page with persistent name, type, and role identity.
5. Add `/w` to the middleware authentication boundary.
6. Preserve the existing Personal/Funūn Team Member account switch unchanged.

## Validation

- Focused unit tests for path construction, status/expiry filtering, labels, and malformed data.
- Existing workspace access/cohort tests.
- TypeScript typecheck.
- Next lint for every changed application/component file.
- Static checks proving the new workspace context never imports session-identity helpers and never
  uses localStorage/sessionStorage.
- Human visual and live-membership UAT recorded as a later TODO, not performed in this code session.

## Risks and controls

- **Wrong workspace:** every workspace layout load calls the existing server authorization gate and
  uses the route parameter as the requested context.
- **Feature discovery outside pilot:** workspace options are returned only when the D-55/D-56
  decision permits access; direct routes fail closed.
- **Identity conflation:** the existing account switch remains separate; the new switcher changes
  only URLs under the same authenticated Member.
- **Resource disclosure:** inaccessible workspace IDs render as not found rather than identifying
  whether the workspace exists.
- **Stale tabs:** independent URLs keep tabs independent; no shared client-side active-workspace key.
