# Plan 38.1-04 — Workspace Contract Locker Shelf

## Objective

Add a workspace-local Contract Locker shelf that presents agreement evidence already visible to the
signed-in Member, groups it by Member and project context, and distinguishes document lifecycle from
evidence provenance without treating stored paperwork as legal review.

## Scope

1. Add a workspace Contract Locker destination to the persistent workspace navigation.
2. Read roster relationships through the authenticated bounded workspace RPC and read agreement
   evidence through its existing RLS policy.
3. Resolve only the narrow document fields already approved by migration 193: identifier, project,
   type, status, and signed timestamp. Never read or return file paths, URLs, document bodies, signer
   data, verification payloads, or storage objects.
4. Use the service client only after RLS has returned visible evidence identifiers, and only to locate
   the possible project id needed to invoke the authenticated, caller-bound document reader.
5. Group shelf records by Member, then project context and document type. Show uploaded-by, uploaded-
   at, Member-confirmation, effective window, expiry, supersession, and Funūn-witnessed signature
   facts as separate observations.
6. Link to a canonical personal Contract Locker or project document page only when the authenticated
   Member can already read the underlying document through personal/project RLS.
7. Use provisional neutral copy pending counsel review. Do not say that Funūn approved, validated,
   cleared, or interpreted an agreement.

- Human visual, keyboard, screen-reader, empty, expired, and role-matrix testing is deferred to Phase
  38.1-08.

## Risks and controls

- **Private document leakage:** evidence RLS is the first boundary; document metadata comes only from
  the Member/project RLS read or migration 193's workspace reader. Unresolved documents remain
  descriptive evidence records with no document metadata.
- **Service-role authorization bypass:** the service client may locate `project_id` for an already-
  visible document id, but that value is not presented unless the authenticated reader independently
  returns the document.
- **False legal assurance:** evidence and document states are separate, observation-shaped labels,
  with an explicit notice that Funūn does not interpret legal effect.
- **Stale authority:** effective, expiry, and supersession states are computed on every read with no
  cached or stored authority state.
- **Unbounded work:** evidence is capped at the existing workspace room ceiling; project document
  reads are de-duplicated by project.
