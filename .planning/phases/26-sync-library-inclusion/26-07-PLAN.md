Wire the artist-facing self-apply surface into the Sound Vault song rows and build the blanket-agreement signing page, so an uninvited artist can complete the whole initial journey (submit → track status → sign) from inside the Vault, without the hub.

Purpose: The Vault song row is the ONLY pre-admission door (locked CONTEXT), and pre-admission status lives ON the song, not in the hub. The signing surface reuses the Phase-17 embedded-signing shell so the visual contract matches the app's existing e-sign moment.

</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| viewer → TrackList sync cluster | A non-owner collaborator must not see or use the submit affordance for someone else's song |
| browser → DocuSeal embed | The embed must expose only a scoped per-signer slug |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-26 | Elevation of Privilege | non-owner submitting someone else's song via UI | high | mitigate | Cluster rendered owner-only; the submit route (26-03) independently re-checks ownership server-side (UI is not the security boundary) |
| T-26-27 | Information Disclosure | DocuSeal API key / cross-signer slug leak in the embed | high | mitigate | Reuse SplitSheetSigningEmbed — browser receives only the scoped per-signer slug from mint-agreement; API key stays server-side |
| T-26-28 | Tampering | trusting client "completed" hint as authoritative | medium | mitigate | onComplete is a client hint only; the webhook (26-04) is the authoritative signed state, mirroring the split-sheet pattern |
</threat_model>
