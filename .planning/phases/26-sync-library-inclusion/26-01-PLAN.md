<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client → sync_listings | Any authenticated artist could attempt a direct PostgREST write to fabricate an `admitted` listing |
| authenticated client → capability_grants | An artist could attempt to self-insert a `sync_library` grant to bypass the invite/apply gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-01 | Elevation of Privilege | sync_listings direct write | high | mitigate | `REVOKE INSERT,UPDATE,DELETE FROM authenticated, anon` — all writes via service-role routes only (Wave 2); RLS `select_own` restricts row visibility to the owning artist |
| T-26-02 | Information Disclosure | sync_listings SELECT by anon | high | mitigate | `REVOKE SELECT ON sync_listings FROM anon`; buyers never read this table directly — the catalogue gate (26-06) is the only cross-artist read path, server-side |
| T-26-03 | Elevation of Privilege | capability_grants self-insert of sync_library | high | mitigate | capability_grants already `REVOKE INSERT,UPDATE,DELETE FROM authenticated, anon` (migration 042, unchanged); the new CHECK values do not relax that lockdown |
| T-26-04 | Tampering | vault_documents.type widening reused by other document flows | low | accept | Additive CHECK widening only; existing six types unchanged, no data migration |
</threat_model>
