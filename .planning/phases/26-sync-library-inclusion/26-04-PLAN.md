<objective>
Build the blanket-agreement e-sign path end-to-end using the LIGHTWEIGHT `vault_documents.document_data.esign` JSONB path (not the split-sheet `esign_envelopes` schema), and extend the shared DocuSeal webhook to dispatch by document kind so a blanket-agreement completion is handled correctly instead of falling into split-sheet fanout.

Purpose: The blanket agreement is the legal gate of the whole pipeline and is sign-once per artist. The single hardest brownfield finding (RESEARCH) is that the DocuSeal webhook is account-wide — a blanket-agreement completion hits the SAME URL as every split sheet and must not be misrouted. This plan owns that contract on both ends.

Output: a versioned template module, a Unicode-safe PDF renderer, the `mint-agreement` route (server-only DocuSeal call), and the webhook dispatch extension — preserving the raw-body→verify→parse ordering and idempotency guard.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| artist session → mint-agreement | Untrusted request could try to mint an agreement for another user or spam mints |
| DocuSeal → webhook endpoint | An attacker could POST a forged completion to fabricate a signed agreement / advance listings |
| DocuSeal API key | Must never reach the browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-11 | Spoofing / Tampering | forged webhook fabricating a signed agreement | high | mitigate | Raw-body HMAC verification via the existing `verifyDocusealSignature` GATE BEFORE any DB write — ordering preserved, not regressed; parse only after verify |
| T-26-12 | Tampering | duplicate/replayed completion advancing listings twice | high | mitigate | Idempotency guard on `vault_documents.status === 'signed'` before any listing advance, mirroring the existing `envelope.status === 'completed'` guard |
| T-26-13 | Information Disclosure | DocuSeal API key exposure | high | mitigate | `docusealProvider.createRequest` runs server-only; the browser receives only the scoped per-signer slug (existing split-sheet pattern) |
| T-26-14 | Tampering / Mass assignment | mint route vault_documents insert injection | high | mitigate | Fixed allowlisted insert column set; user_id from session, request body never spread |
| T-26-15 | Elevation of Privilege | mint-agreement minting for another artist | high | mitigate | user_id/name/email resolved from the authenticated session, never the request body |
| T-26-16 | Tampering (legal-document integrity) | Unicode name mangling in the signed PDF | high | mitigate | `registerFunuunPdfFonts()` imported in blanket-agreement.tsx (P17-08 regression guard) |
</threat_model>
