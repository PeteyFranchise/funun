<objective>
Replace the two duplicated `is_public !== true` inline checks (in `lib/deals/catalog.ts`'s `isRightsReady` AND `lib/deals/request-target.ts`'s `authorizeRequestTarget`) with ONE new admission-status helper, so buyer-catalogue eligibility is driven by real sync-library admission instead of the beta `is_public` placeholder.

Purpose: RESEARCH flags this as a pre-existing drift risk the codebase's own comments call out. Phase 26 must fix it by having both callers delegate to the same helper — not add a third copy. This is the point where the placeholder inclusion gate becomes the real curated-admission gate. (No buyer transaction ships this phase — this is the correctness/wiring fix that unblocks the downstream 22-05 catalogue consumer.)

Output: `isAdmittedToSyncLibrary()` in catalog.ts (pure), `isRightsReady` refactored to use it, `authorizeRequestTarget` refactored to use it, and both I/O callers (`loadCatalogPage`, `authorizeRequestTarget`) populating the admitted-listing signal.
</objective>
