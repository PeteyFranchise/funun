<objective>
Build the DB-independent domain core for the sync library: the status-transition state machine, the eligibility predicate, and the shared types — all pure and fully unit-tested, so the Wave 2 routes import one authority instead of re-deriving transition rules.

Purpose: A curated admission pipeline lives or dies on the correctness of its state machine (illegal transitions must be impossible). These are textbook TDD units — write the transition table as tests first, then the implementation. Running in parallel with the migration (26-01), since nothing here touches the DB.

Output: `lib/sync-library/submission.ts` (transition validators), `lib/sync-library/eligibility.ts` (`hasSyncLibraryCapability`), and the shared `types/index.ts` additions (`SyncListingStatus`, `SyncListing`, `DocumentType` += `blanket_agreement`, with the forced `DOC_LABELS` entry).
</objective>

    NOTE — the flow follows 26-CONTEXT decision #2 (AUTHORITATIVE, overrides UI-SPEC's superseded `applied→under_review→staff-accepts→agreement_pending` progression): there is exactly ONE staff gate — admit/reject at `pending_admit`. There is NO separate staff "accept" step. Self-applied and invited songs differ only by `entry_source` metadata and their initial state, not by an extra gate.
    - Export `SYNC_LISTING_STATUSES` (readonly tuple) matching migration 096 exactly: applied, invited, agreement_pending, pending_admit, admitted, rejected, withdrawn, removed.
    - `isValidTransition(from, to)` returns true only for the locked edges:
      · applied → agreement_pending (artist starts signing), pending_admit (already/just signed), rejected (staff), withdrawn (artist)
      · invited → agreement_pending, pending_admit, rejected (staff), withdrawn (artist)
      · agreement_pending → pending_admit (agreement signed via webhook), rejected (staff), withdrawn (artist)
      · pending_admit → admitted (staff admit), rejected (staff reject), withdrawn (artist)
      · admitted → removed (leadership takedown), withdrawn (artist)
      · Every other pair (incl. any → itself, any transition out of a terminal rejected/withdrawn/removed) returns false.
    - `nextStatusOnAgreementSigned(from)` returns 'pending_admit' when from ∈ {applied, invited, agreement_pending}, else null (this is what the sign-completion webhook applies to the whole cohort).
    - `initialStatusForEntry(source, alreadySigned)` returns: self_applied → alreadySigned ? 'pending_admit' : 'applied'; admin_invited → alreadySigned ? 'pending_admit' : 'invited'.
    - `isTerminal(status)` true for rejected/withdrawn/removed.
    - Bad/unknown status strings never throw — they return false/null.
  </behavior>
