# Plan 44.1-02: Session lifecycle, tokens, authorization, and cost controls

## Objective

Build the server-side session boundary and provider adapter; no UI joins a real room until access and
spend controls are proven.

## Tasks

1. Define provider-neutral create/join/end/webhook/usage interfaces. Provider secret never enters client
   code; tokens are short-lived, work/session scoped, least-privilege, and carry server-derived identity.
2. Revalidate `resolveWorkAccess` plus block/removal state for start, join, reconnect/token refresh, and
   privileged session actions. Do not infer authorization from Phase 44 presence.
3. Enforce one active session/work, six participants, owner-approved duration warning/hard maximum, idle
   end, feature/plan gate, per-user/work rate limits, concurrency ceiling, and global kill switch.
4. Persist only minimal lifecycle/usage metadata if approved. If schema is needed, preflight numbering,
   avoid migration 228, author human-gated SQL/RLS, and never apply it autonomously.
5. Verify signed provider webhooks idempotently; reconcile starts/joins/leaves/ends and billed minutes.
   Summary alerts contain no call content, media token, or unreleased-song metadata.
6. Test cross-account, removed/blocked mid-call, token replay/expiry, duplicate start, abandoned browser,
   webhook spoof/reorder/retry, limiter outage, provider outage, and cost-cap behavior.

## Acceptance

- Page load/presence creates zero video participant minutes.
- A removed Member cannot mint/refresh and is disconnected through the provider path as quickly as the
  provider permits.
- No recording capability/token permission is enabled.
- Migration, if any, stays NOT APPLIED until owner-run application and remote verification.
