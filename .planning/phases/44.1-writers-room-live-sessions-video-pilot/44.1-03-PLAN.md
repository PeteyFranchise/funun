# Plan 44.1-03: Live-session UI and DAW-window screen sharing

## Objective

Integrate a branded, accessible session into the Writer's Room without turning the page into a generic
meeting app or replacing persistent room chat.

## Tasks

1. Add **Start a session** / **Join session** states beside Room members. Show camera badge for session
   participation separately from green room presence.
2. Build prejoin device preview and permissions; join/leave, mute, camera, device switch, participant
   strip, dominant/shared stage, network quality, reconnect, ended/full/expired states, and audio-only use.
3. Implement screen share as a user-triggered provider track. Prefer a selected DAW application/window;
   warn before whole-screen selection and explain that browser/system audio may be unavailable.
4. Optimize the shared DAW stage for readable text/waveforms; cameras become adaptive thumbnails. Do not
   add any “save call audio as take,” record, transcription, or approval action.
5. Keep Phase 44 chat visible in the desktop rail and accessible from mobile without duplicate ephemeral
   provider chat.
6. Add keyboard/screen-reader focus, permission-denied, no-device, mobile-view-only screen share, Safari,
   backgrounding, reconnection, reduced-motion, and narrow-layout tests/UAT.

## Acceptance

- User action is required for every join, media permission, and screen share.
- Call audio/screen tracks cannot enter storage or `work_versions` through this feature.
- Leaving/end reliably stops tracks and provider billing state.
- UI explains reference-quality audio without suggesting master/mix approval.
