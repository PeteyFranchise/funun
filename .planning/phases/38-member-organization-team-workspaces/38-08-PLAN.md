<planner_decisions>
**Grant cardinality (resolves 38-RESEARCH.md Open Question 1): one row per
`(workspace_id, relationship_id, project_id, permission)`.** Normalized rather than a JSONB array,
per the research's own recommendation — it makes D-49's subset check a set-difference query, makes
D-50's per-permission audit natural, and is directly indexable from inside a STABLE SQL helper.
JSONB is retained only for `workspace_permission_bundles.permissions`, which is UI sugar and never a
security-relevant read path.
