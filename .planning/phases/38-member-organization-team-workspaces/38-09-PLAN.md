<objective>
Implement grant issuance and — the harder half — grant re-evaluation at use time, plus the
attributed acting-on-behalf helper.

Purpose: D-49 has two clauses and only one of them is easy. Refusing an over-broad grant at issue
time is a route check. Making a grant stop working when the granter's access is later reduced
requires that no surface ever reads `workspace_grants` directly — every consumer must go through one
resolver that re-derives membership, relationship liveness and authority tier on the spot. This plan
builds that resolver before any surface exists to bypass it.

Output: `lib/workspaces/grant-service.ts`, `lib/workspaces/acting.ts`, their paired tests, and the
grants API route.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| granter's own effective set → issued grant | The privilege ceiling; the classic delegation-escalation surface |
| stored grant row → exercised capability | The gap where a grant outlives the granter's access unless re-derived per use |
| workspace grant → clean-master storage path | Custody D-09's structural boundary; the resolver must be incapable of crossing it |

| T-38-09-02 | Elevation of Privilege | A grant continuing to work after the granter's access or the relationship is reduced (D-49 use-time clause) | critical | mitigate | `resolveEffectivePermissions` re-derives membership, relationship liveness and authority tier on every call and caches nothing; a test asserts two calls with different state return different results |
