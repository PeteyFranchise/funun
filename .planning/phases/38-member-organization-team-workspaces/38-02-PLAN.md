<objective>
Build the second half of the pure logic core: the workspace-membership state machine (including
the never-zero-owners predicate), the roster-relationship state machine, and the compute-on-read
agreement-evidence ladder that resolves a relationship's authority tier.

Purpose: D-05's "inert until accepted", D-13's never-zero-owners, D-18's unilateral revocation and
D-39's automatic authority lapse are all *rules*, not storage. Expressing them as pure predicates
first means migrations 182/183 mirror a tested contract instead of inventing one, and every route
in waves 3–7 calls the same function rather than re-implementing the rule inline.

Output: `lib/workspaces/membership.ts`, `roster.ts`, `evidence.ts` and their paired unit tests.
No database, no route, no component.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workspace-supplied roster proposal → Member's data | The proposal crosses into a stranger's account context; inertness is the control |
| stored agreement evidence → authority-tier grants | An expired or scope-less document must not keep unlocking consequential powers |
| workspace admin → workspace continuity | An owner removing the last owner would orphan the workspace and its rights evidence |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-38-02-01 | Elevation of Privilege | A `proposed` roster relationship treated as live access (D-05) | critical | mitigate | `isWorkspaceAccessLive` returns false for every state other than `accepted`; `isInertState` is asserted; migration 183 and the RLS helper in plan 38-11 both filter on `accepted` |
| T-38-02-02 | Elevation of Privilege | Authority tier surviving document expiry (D-39) | high | mitigate | Compute-on-read `resolveAuthorityTier` with an injected clock — there is no stored tier column to go stale, and no cron job whose failure would leave authority live |
| T-38-02-03 | Elevation of Privilege | Authority derived from an attached file with no declared scope (D-36) | high | mitigate | `declaredScope` must be non-empty for the `authority` result; test asserts a null scope yields `operational` |
| T-38-02-04 | Denial of Service | Last owner removed, orphaning the workspace and its rights evidence (D-13, D-46) | high | mitigate | `assertOwnerFloorHolds` checked before the actor's role in `canRemoveMember`; the same message constant backs migration 182's trigger so UI, API and DB agree |
| T-38-02-05 | Repudiation | A "verified" label implying Funūn validated a document (D-37) | medium | mitigate | `describeProvenance` emits only observation-shaped labels; a comment-stripped source grep enforces it; final wording remains counsel-gated |
| T-38-02-06 | Spoofing | Relationship revived out of a terminal state to restore lapsed access | medium | mitigate | `refused`, `blocked` and `ended` have empty outbound edge sets; a renewed relationship is a new row |
| T-38-02-07 | Tampering | npm/pip/cargo installs | high | accept | No new package; 38-RESEARCH.md Package Legitimacy Audit records none proposed for this phase |
