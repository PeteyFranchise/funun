# 37.3-01 — Song Passport Architecture and Additive Schema Foundation

## Objective

Create the disabled-by-default, additive Song Passport foundation: one Passport per work,
append-only field revisions, a transactional current-head relation, immutable snapshots,
authority grants, actions and tasks, with typed vocabulary and route-level authorization
helpers. No existing artist-facing read or write path changes in this plan.

## Locked doctrine

- `.planning/deliberations/song-passport-doctrine.md`
- `.planning/phases/37.3-song-passport/37.3-ARCHITECTURE.md`
- One Passport per work; one current head per field/target.
- Values, snapshots and authority actions are append-only.
- Contributor, composition, recording-version and release targets remain distinct.
- Writer's Room membership never grants legal, release, delivery or private-data authority.
- Sensitive writes use server-side authorization and service-role persistence; raw browser
  roles do not write Passport capability or evidence tables.
- Private identity and legal data are denied by default and require self-access or an
  explicit, unexpired, unrevoked grant.

## Tasks

### Task 1 — Red migration contract

Create `__tests__/migration-151.test.ts` first. Lock table names, one-per-work uniqueness,
typed target constraints, current-head composite integrity, trust/privacy states, RLS on
every table, no raw browser writes, private/legal read gating, append-only guards, safe
SECURITY DEFINER helpers and the human-gated migration header.

### Task 2 — Additive migration 151

Create the Passport, value ledger, field heads, snapshots, actions, tasks and scoped grants.
Use foreign keys to existing work/version/profile/collaborator/release/track records without
modifying landed migrations. Add RLS and explicit grants/revokes. Add SECURITY DEFINER read
helpers with empty search paths and narrow authenticated execute grants. Add immutable-row
triggers for values, snapshots and actions. Finish with PostgREST schema reload.

### Task 3 — Typed domain vocabulary

Create `lib/song-passport/schema.ts` and red/green tests. Define layers, states, privacy
classes, sources, snapshot purposes, actions and the initial stable field vocabulary.
Delivery-safe status must be explicit per field; private/legal fields can never inherit a
delivery-safe default.

### Task 4 — Authorization and feature boundary

Create pure authorization helpers and tests proving membership is not authority. Sensitive
actions require explicit scoped facts even for an owner. Add a server-side feature check
that defaults false unless `SONG_PASSPORT_ENABLED=true`; do not add a client/public flag or
mount any UI/API route in this plan.

## Rollback

The feature remains disabled and no existing runtime consumes the new tables. Application
rollback is removal of new library imports (none are expected outside tests). Database
rollback is non-destructive: leave the additive schema in place and keep the feature off;
do not delete evidence tables or edit migrations already applied.
