# Phase 37.3 — Song Passport Seven-Slice Implementation Plan

**Execution update (2026-09-02):** all seven slices are code-complete and migrations
150–156 are applied. Deployment, rollout flags and pilot UAT remain human-gated; this is not
yet a general-release claim. See `37.3-01-SUMMARY.md` through `37.3-07-SUMMARY.md`.

## Sequence rule

Execute slices in order. A later slice may research in parallel but may not write against an
unverified authority, snapshot or migration boundary from an earlier slice. Every database
migration is human-gated.

## Slice 1 — Architecture and additive schema foundation

**Goal:** establish one Passport per work, append-only field revisions, immutable snapshots,
actions and least-authority RLS without changing the current UI.

**Outputs:** tables/helpers/RLS, typed domain models, source registry, field vocabulary,
privacy classes, feature flags, route authorization helpers and migration text-lock tests.

**Gate:** unauthorized cross-work access fails; one work cannot receive two canonical
Passports; snapshots cannot be updated/deleted; no current product read path changes.

**Rollback:** feature remains off; retain additive tables and revert application references.

## Slice 2 — Legacy discovery, backfill and reconciliation

**Goal:** populate conservative inherited/draft values from works, profiles, collaborators,
split sheets, contracts, versions, projects and track metadata without fabricating approval.

**Outputs:** dry-run report, idempotent backfill job, duplicate/conflict queue, shadow-read
comparison and owner review tooling.

**Gate:** repeat runs create no duplicates; ambiguous records are reported, not merged;
confirmed/locked states appear only when existing evidence supports them.

**Rollback:** stop job, disable cohort, keep ledger evidence and legacy sources authoritative.

## Slice 3 — Passport UI inside Sound Vault

**Goal:** show the four layers, provenance, trust/privacy states, missing/conflicting facts,
tasks and source links beside the existing Writer's Room.

**Outputs:** Passport overview, layer views, provenance drawer, scoped edit/propose controls,
task panel and readiness explanations. Current layout remains recognizable.

**Gate:** users can distinguish composition from recording/release facts and understand why a
field is missing, inherited, confirmed, locked, outdated or disputed.

**Rollback:** hide Passport routes/tabs; Writer's Room and Release Report remain unchanged.

## Slice 4 — Confirmation, approval, permissions and conflict workflows

**Goal:** turn drafts into trusted facts through authority-scoped actions, never silent merge.

**Outputs:** own-identity confirmation, contributor proposals, approval snapshots, conflict/
outdated review, notification/task routing, server authorization and audit events.

**Gate:** the authorization matrix passes; concurrent edits preserve revisions; material
post-approval changes require successor approval; tasks alone never change readiness.

**Rollback:** disable action endpoints and return to read-only Passport projection.

## Slice 5 — Recording versions, master selection and Release Report graduation

**Goal:** carry composition truth across versions, keep recording facts distinct and graduate
an exact approved master into a release without re-entry.

**Outputs:** version lineage, version metadata, explicit master designation, successor-master
workflow, work/version/release links and Release Report mapping/review screen.

**Gate:** three-version acceptance story passes, including a final mix uploaded outside the
Writer's Room; prior masters and release snapshots remain historical and immutable.

**Rollback:** disable graduation/master replacement and retain existing manual release flow.

## Slice 6 — Snapshots, delivery artifacts, portability and custody history

**Goal:** create safe outputs and preserve the exact truth used for export, transfer or sale.

**Outputs:** tagged MP3 and sidecar generation from Passport snapshots, provider-neutral JSON
manifest, export receipt links, portable custody package, chain-of-title/custody events and
retention/deletion workflow.

**Gate:** private-field filters and source-hash invariants pass; export snapshots are stable;
ownership/custody changes preserve before/after controllers and historical receipts.

**Rollback:** stop generation/transfer actions, preserve artifacts and receipts, revert to
existing delivery-safe release-track routes where applicable.

## Slice 7 — Pilot rollout, observability, support and claims review

**Goal:** prove the full Phase 37.3 workflow with a small real cohort before general release.

**Pilot:** at least three works spanning a solo artist, a multi-writer song and a work with an
existing release/legacy metadata. Include two contributors, three versions, one conflict,
one profile update after confirmation, one graduation, one export and one custody correction.

**Outputs:** cohort flags, audit dashboards, failure alerts, support SOP, user feedback,
Playbook revision, production verification and evidence-scoped claim ladder.

**Gate:** zero authorization/privacy/source-mutation incidents; no silent overwrite; no
manual re-entry of approved facts at graduation; every artifact resolves to an immutable
snapshot; pilot users can explain current versus planned direct-delivery status.

**Rollback:** stop cohort expansion immediately; disable Passport writes/exports while
retaining read-only history and legacy workflows.

## Phase handoff

After Slice 7 passes, Phase 37.3 may be called shipped within its documented boundary.
Standards exports do not inherit that claim: Phase 37.4 still proves CWR/RIN/ERN validation,
and Phase 37.5 still proves partner delivery and acknowledgment.
