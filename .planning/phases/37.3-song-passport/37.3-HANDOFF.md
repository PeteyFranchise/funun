# Phase 37.3 — Song Passport Engineering Handoff

## Outcome

All seven approved Song Passport slices are implemented in the repository and migrations 150–156 are applied. The feature is intentionally dark: deployment, pilot enablement and real-user UAT remain explicit human gates.

## What was built and why

### 1. Trusted data foundation

One Passport belongs to one Writer's Room work. Contributor, composition, recording-version and release facts stay in separate layers. Values are revisions with provenance and trust state, not mutable fields whose history disappears. This makes inherited data reviewable without pretending it was confirmed.

### 2. Conservative legacy discovery

The owner can preview or apply deterministic discovery from works, profiles, collaborators, lyrics, versions, split sheets and a linked Release Report. Repeating discovery does not duplicate facts. Contradictions become reconciliation issues instead of Funūn guessing which source wins.

### 3. Sound Vault interface

A collapsed Song Passport panel sits inside the existing Writer's Room, preserving the current creative layout. People, Song, Recordings and Release views explain what Funūn knows, where each fact came from, its trust state, missing information, conflicts and review work.

### 4. Authority and approvals

Contributors can propose facts and confirm only their own identity. Concurrent changes use expected-head checks and soft conflict behavior, preserving both revisions. Composition and release approvals freeze immutable, hashed snapshots. Explicit grants separately govern legal visibility, approvals, master selection, exports, clean-master copies and custody.

### 5. Master and Release Report continuity

An authorized person can select an exact recording version as the master only against an approval snapshot. Successor masters preserve the prior designation. Approved facts can graduate into a linked Release Report without retyping, and a final mix uploaded in the Release Report can be linked back without duplicating the audio bytes or inventing Writer's Room history.

### 6. Delivery-safe artifacts and custody

Funūn can generate snapshot-bound Passport JSON, a human-readable sidecar, an ID3-tagged MP3 copy when the selected master is MP3, and a scoped custody package. WAV, FLAC and other formats remain unchanged and use sidecars. Evidence records the exact source hash, artifact hash, snapshot, purpose, audience and generation receipt. Custody transfers preserve before/after controllers and trigger an access review.

### 7. Pilot operations

Global, cohort and emergency-stop controls are server-owned and fail closed. Value-free operating events support an internal Playbook dashboard without exposing Passport content. The repo includes pilot UAT, support escalation rules, rollback doctrine and an evidence-scoped claim ladder.

## User impact

A writer can keep song information together from the first idea through versions and release preparation, understand what is trusted versus merely inherited, collaborate without silently overwriting another person's evidence, identify the exact final master and carry approved information into a Release Report. They can create accountable handoff files while Funūn remains honest that a prepared file is not proof a distributor or recipient accepted it.

## Non-claims

This build does not claim DDEX certification, automatic DDEX identity embedded in audio, universal zero-entry distributor delivery, certified direct Secretly/DSP/society delivery, rights adjudication, legal advice or proof that a custody event by itself establishes legal title. DDEX validation remains Phase 37.4; named-partner transmission and acknowledgment remain Phase 37.5.
