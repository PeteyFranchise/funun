# Phase 37.3 Slice 2 — Legacy Discovery and Reconciliation

## Objective

Discover existing Song Passport facts from legacy Funūn records without guessing, silently
merging people, or upgrading inherited data to confirmed truth.

## Scope

- Add an idempotent source fingerprint and a server-owned reconciliation queue.
- Build deterministic discovery for works, collaborators, split sheets, profiles, versions,
  releases and track metadata.
- Provide owner/admin dry-run and explicit apply endpoints.
- Record ambiguous or contradictory source data as review issues.
- Preserve every legacy source as authoritative until a user explicitly resolves a difference.

## Verification

- Repeat discovery/apply produces no duplicate ledger values or issues.
- Dry-run performs no writes.
- No discovered value is marked confirmed or locked.
- Cross-work access and contributor-only apply are rejected.
- Migration text locks server-only write boundaries and idempotency constraints.
