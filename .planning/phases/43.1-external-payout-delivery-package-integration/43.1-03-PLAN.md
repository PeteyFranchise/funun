# Plan 43.1-03: Secure recipient delivery

## Objective

Deliver an approved disclosure to the named finance recipient with explicit identity, expiry, audit, and
revocation semantics.

## Work

1. Implement the approved recipient verification path (authenticated Member or verified guest). Do not
   treat possession of an emailed URL as sufficient for tax or bank access.
2. Exchange the one-time URL token for a short, scoped server session after recipient verification and
   step-up. Prevent referrer leakage, caching, indexing, screenshots in automated previews, and secrets
   in client persistence.
3. Render masked context before access and only the approved categories after authorization. Keep tax
   document access separately acknowledged and audited.
4. Record view/download/failed-attempt/expiry/revoke events as metadata. Notify the contributor after
   first view/download without including secret values.
5. Add payer-side readiness/status tracking that never reveals the data itself to unauthorized workspace
   members.
6. Test token theft/replay, email change, recipient reassignment, brute force, expiry boundaries, revoked
   sessions, cache headers, browser history, link scanners, and concurrent views.

## Acceptance

- A workspace role alone cannot consume the disclosure.
- URLs, logs, analytics, and notification payloads remain secret-free.
- Recipient and contributor can see accurate access history.
- Revocation and expiry block both fresh token exchange and existing sessions per the approved policy.
