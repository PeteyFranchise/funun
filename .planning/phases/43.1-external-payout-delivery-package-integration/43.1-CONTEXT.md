# Phase 43.1: External Payout Delivery & Package Integration — Context

**Captured:** 2026-09-23
**Status:** Blocked on Phase 43 verification
**Migration:** Unassigned; human-gated; migration 228 is unavailable

## Phase boundary

Let an authorized payer request selected payment/tax categories, let the contributor consent to an
immutable snapshot, deliver it to a named recipient through expiring access, and add readiness—not
secrets—to asset delivery packages.

## Locked decisions

- **S-01:** Disclosure is a purpose-bound consent record, never a workspace permission.
- **S-02:** A request names payer entity, finance recipient, contributor, work/deal/invoice context,
  rail/currency, requested categories, purpose, deadline, and expiry.
- **S-03:** The contributor decides their own request; workspace owners cannot approve for them.
- **S-04:** Approval freezes a versioned disclosure snapshot. Later profile changes never mutate it.
- **S-05:** Recipient access is scoped, expiring, step-up protected, and audited; token material is
  hashed and never logged.
- **S-06:** Revocation stops future access but cannot claw back a view/download; the UI states this.
- **S-07:** Default upload packages contain readiness state and a secure link only.
- **S-08:** Tax documents are not implied by approval of bank instructions.
- **S-09:** Static encrypted export is an exception behind a separate human checkpoint, not the MVP.
- **S-10:** Notifications and audit are summary-only; no raw record or storage path.
- **S-11:** Bank changes trigger warnings/holds and out-of-band verification guidance.

## Dependencies

- Phase 42 Requests center is shipped so contributor decisions have an operational home.
- Phase 43 encryption/profile boundary, step-up auth, audit, retention, and key operations are verified.
- Legal/privacy approval covers supported recipient types, countries, rails, tax documents, and retention.

## Launch boundary

Do not enable production disclosure merely because UI and schema exist. Require two-account authorization
tests, token replay/expiry/revocation tests, package-content inspection, key-rotation/restore exercises,
and named finance-user UAT.
