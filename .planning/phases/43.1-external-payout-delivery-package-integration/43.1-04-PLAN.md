# Plan 43.1-04: Package manifest, security verification, and launch

## Objective

Integrate payout readiness with delivery packages without embedding restricted data, then perform the
end-to-end launch gate.

## Work

1. Locate every asset/upload-package generator and add a versioned payout-readiness manifest containing
   only contributor display reference, ready/requested/waiting/declined/expired states, secure recipient
   link when approved, and link expiry. Never include raw account/tax values or an unrestricted object URL.
2. Require each contributor's own approved disclosure; one contributor's approval cannot cover another.
   Package creation may report blockers but cannot weaken consent to meet a deadline.
3. Scan generated archives, PDFs, JSON/CSV metadata, filenames, URLs, ID3 metadata, emails, logs,
   notifications, and audit payloads with seeded canary secrets.
4. Run end-to-end role/IDOR, stale-state, bank-change, expiry, revoke, replay, rate-limit, KMS outage,
   notification-failure, and concurrent package-generation tests.
5. Conduct contributor and named label/distributor finance UAT using synthetic values. Verify mobile and
   assistive-technology flows.

## Separate optional checkpoint

Do not implement a static financial export unless the owner/security/legal explicitly approve it after
the secure-link workflow is proven insufficient. If approved, create a new plan for a separately encrypted,
watermarked, recipient/purpose-bound artifact with an out-of-band secret and irreversible-download warning.
It must never be placed in the ordinary asset ZIP.

## Launch gate

Owner confirms migration application/remote verification, security and legal sign-off, runbook ownership,
synthetic UAT, and package-content scan. Record rollout/rollback and feature-flag states. Otherwise leave
the feature disabled and mark the phase incomplete.
